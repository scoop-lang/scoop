## 2. 更新与帧工作的目标边界

节点至少区分以下三类失效；布局失效包含场景失效，单纯场景失效不反向要求布局。

| 类别 | 典型来源 | 必须执行的工作 |
| --- | --- | --- |
| 逻辑更新 | render 读取的 State、父级输入或 children 变化 | 更新当前 Props、必要的 render／reconcile／update |
| 布局失效 | 内容尺寸、字体、方向、约束、布局动画、子项布局结果变化 | 重新取得该路径所需布局结果，更新依赖它的祖先布局 |
| 场景失效 | 颜色、透明度、caret、滚动变换、绘图资源、输入呈现变化 | 重建受影响场景或合成状态，复用有效布局 |

`Element.update` 要能报告本次输入对布局和场景的影响；不具备精确分类的实现保守要求布局。已知只有事件处理器替换时，更新处理器引用即可；会影响输入资格或焦点行为的配置仍执行相应输入／场景工作。

新增明确的布局请求入口，绘制请求只表示场景需要更新。动画在实际读取它的阶段登记用途：布局阶段使用的动画值使布局失效，场景阶段使用的值仅使场景失效；同时用于两者时按布局处理。复用既有 Surface 时间轴和帧参与机制，不通过 State 每帧重建组件，也不建立第二个动画调度器。

这些变化需要更新公开 Element／LazyElement 协议及现有控件，不能宣称为完全不影响组件的内部优化。

## 3. 重复测量：完整结果与帧内复用

### 3.1 先解决结果保存，再增加缓存

当前测量不仅返回 LayoutMetrics，还修改节点 placements 和元素自己的绘制／排版状态。例如 ActionInk 保存 `drawing`，ParagraphCache 替换 TextLayout。按约束 A、B、A 测量时，只恢复 A 的尺寸和 placements，会让 scene 继续使用 B 的内部状态。

目标协议将每次成功测量表示为可独立使用的布局结果。一个结果至少包含：

1. 本节点的 LayoutMetrics。
2. 本节点的类型化布局数据，如内容区域、基线、裁剪所需几何、段落布局引用。
3. 本次选中的直接子布局结果及其放置；跳过或未放置也有明确表示。
4. 该结果所持有资源的释放责任。

Element 通过普通泛型表达布局数据，例如概念上的 `Element<L>`、`LayoutResult<L>` 和 `scene(context, layout: L)`。正式签名在 UI 规范中统一确定；描述与节点内部的类型封装沿用现有泛型包装方式，不通过反射访问字段，不引入关联类型或未检查的 Any 还原。

布局结果、子放置及 scene 使用的布局数据发布后不可修改；不能让 A、B 两份结果引用同一个随后被覆盖的可变几何对象。使用普通不可变值和明确快照落实这一协议，不增加运行期深度不可变性审计。

测量可以维护输入相关的内部缓存，但 scene 所需的布局状态必须从选中的结果取得，不能依赖一个会被后续试测覆盖的“最近一次 drawing”字段。颜色、透明度和仅影响像素的动画在 scene 中采样；影响尺寸或位置的动画进入布局输入。

布局结果引用子结果形成共享结构。缓存命中只选择结果引用，不深拷贝整棵 placements 树，也不立即遍历所有后代恢复成员字段。原有 `finishMeasurement` 改为沿最终选中的结果完成必要工作，试测结果不能单独发布输入、焦点、锚点或帧参与状态。

### 3.2 缓存范围与失效条件

帧内缓存属于根的一次布局轮次，按节点保存，并能跨不同 MeasureContext 回调复用。只在单个 MeasureContext 内增加 Map 不能消除祖先重复测量带来的重新计算。

缓存识别的输入为：节点、有效布局输入版本、Constraints、布局方向及本轮相关环境／动画采样。子树布局失效必须反映到依赖它的祖先结果；可变资源的 revision 或变更通知也必须参与失效。同一轮内完全相同的有效请求最多计算一次。

Constraints 使用现有值比较。初期节点内查询种类少，可采用小型结果表；不要求浮点数或任意对象自动获得 Hash，也不能使用移动对象的裸地址作为 key。结果表只覆盖真实请求，不用任意请求配额决定布局是否合法。

帧内保留成功结果，失败结果不进入缓存。下一轮只保留跨帧仍可能复用的当前布局，其他历史约束结果释放，避免长期保存每次窗口缩放产生的尺寸。缓存不保存完整子树副本。

共享子结果的资源只由该结果负责释放，不能由多个父结果各自关闭一次。结果存储保留最终选择仍可达的结果，释放未被保留的结果；已接受编辑帧等独立持有者继续遵守各自的资源持有合同。

### 3.3 文本、资源和惰性子项

- ParagraphHost 的结果显式持有对应 TextLayout。优先复用现有 RetainedParagraphLayout 的持有语义，确保替换段落缓存不会关闭仍被选中布局或已接受编辑帧使用的对象；无需扩展为通用资源租约框架。
- 新结果构造失败时，只释放本次取得的资源；旧的有效结果按其既有持有关系继续存在。输入几何仍只在 Accepted 后发布，Discarded 不把试测结果变成可交互位置。
- LazyElement 的每次试测记录自己的已测项和放置选择；保留范围、帧资格与卸载决策只根据最终结果执行。不能为命中布局缓存而枚举全部 ItemSource，或因切换试测约束而重复挂卸同一个 key。
- `skipChild` 保留逻辑挂载和状态更新，本轮没有布局／呈现。恢复呈现时必须按当前输入和约束选择有效结果，不能带回失效的旧命中区域。

### 3.4 Flex／Grid 与 intrinsic 的处理

先让现有布局算法使用完整结果复用，再根据计数删除没有必要的重复请求。Flex 已有的无界内容复用继续保留；Grid 的内容、轨道和最终单元格测量可以复用相同请求。

本批不以新增一整套 minIntrinsic／maxIntrinsic 为前置。若真实基准仍表明只查询尺寸的成本突出，再为实际消费者增加最小尺寸查询协议；该协议必须明确不替换最终布局、不改变场景状态。不能默认回退到带上述副作用的 measure 并称其为纯查询。

基线中可构造 d 层单单元格、行列为 Auto、对齐为 Stretch 的 Grid，叶子自然尺寸固定，产生约 `3^d` 次叶子测量。六层的 729 次是当前调用路径推导，尚非本方案的实测记录。整改后，同一节点相同请求只生成一次结果；该固定构造每个叶子只需少量不同约束结果，总结果数随深度线性增长。普通 Frame 链另作单次测量对照，不能把所有容器深度都当作指数倍率。

## 4. 跨帧布局与场景复用

### 4.1 布局复用

完成第 3 节后，未失效且有效约束、方向及布局依赖未变化的节点，直接复用上一轮选中的布局结果。祖先仅改变位置或绘制变换时，不重新调用尺寸未变子树的 measure。

初期布局失效沿实际布局依赖保守传播到根；传播路径上的有效兄弟结果可以直接复用。只有在测得明显收益后再增加更细的 relayout boundary，不为所有容器预先设计复杂的边界分类。

字体集合、图像固有尺寸等外部资源必须有有效失效来源。优先消费已有变更通知；仅有 revision 的共享资源可在已请求的帧入口检查一次，并使实际依赖它的节点失效。不能在每个节点重新扫描全部资源，也不能为检查 revision 产生持续帧。

迁移 ActionInk、Frame、文本宿主等把布局和绘制混在 measure 中的实现。Progress／Spinner／caret／颜色过渡作为仅绘制变化的代表；Disclosure 高度、Sidebar 宽度、Resizable 面板尺寸作为确实需要布局的对照。

### 4.2 场景几何与静态绘制

布局复用先落地，之后再减少 scene 回调。场景缓存必须同时考虑变换、clip、呈现顺序、输入资格、焦点、锚点和 Portal 出口；布局尺寸相同不代表这些信息相同。

局部几何可以复用，向 Surface 组装本帧候选场景时应用当前变换、clip 和顺序。Accepted 后才替换已提交输入／焦点／编辑几何；窗口缩放、滚动、重排、禁用、隐藏、Portal 变化和卸载都应正确更新或移除记录。

静态绘制子树通过明确的缓存边界复用已记录内容。边界沿同一 Element 协议实现，不增加 ViewBody 分支。可复用条件必须覆盖实际绘制依赖；读取时间／动画、需要每帧参与判断或登记 onFrameComplete 的节点继续执行相应场景工作。

不能缓存一次性帧完成回调并在后续帧反复执行，也不能因跳过 scene 而漏掉当前帧的必要通知。像素缓存命中、场景回调跳过和输入几何复用分别计数，不把三者当成同一项优化。

### 4.3 draw 与 drawLayer

保留两者的区别：draw 直接绘制；drawLayer 是有限、独立记录并按约定合成的绘图层。不能在关闭 Tiles 缓存时改成不同的坐标或混合语义，也不能用 withState 替代合成隔离。

逐个检查实际调用：无需隔离和像素缓存的内容使用 draw；需要隔离的内容保留 drawLayer。先测量记录、回放、光栅化与合成成本，再优化重复记录。仅看到 saveLayer 调用不能推出每次 GPU 分配的实际成本。

公共文本／绘图宿主集中维护自己的版本。revision 必须覆盖真实内容、资源和动态采样，不能仅从 Props 引用或主题身份派生一个被宣称为普遍正确的版本。无法声明完整依赖的自绘继续正常执行。

## 5. 逻辑更新、输入比较与订阅

### 5.1 保留 State 的通知语义

现有“写入即通知，包括同引用写回”的语义继续保留。它支持普通业务对象原地修改后的显式发布，不能因为类型实现 Equals 就自动改变行为。

确有调用需求时可以增加显式的等值抑制选项；等值判定只作用于选择该语义的状态，不成为 Props 跳过或订阅正确性的基础。本轮优先消除已经确认的重复工作，不把 State 等值选项设为前置。

### 5.2 受约束的输入跳过

为 Component／Element 描述提供显式输入比较入口。只有具备清晰不可变输入、可观察模型或明确变化版本的组件才启用相应比较；未声明比较的任意用户输入保守更新。这是同一更新协议的选择，不保留另一套旧实现。

跳过必须满足以下条件：

- 节点自身没有待处理的 State 失效，方向及有效显示依赖没有变化。
- 输入比较覆盖 render／update 真正消费的值；引用内部可变内容不能仅凭引用相同视为不变。
- Element 的 children 独立参与协调；相同的 Unit 输入不能掩盖子项增删或重排。
- 当前 Props 始终替换。父节点跳过不能取消后代已经排队的独立更新。
- 回调与 Binding 仍然指向当前输入。比较器若忽略动作变化，实际调用路径必须通过稳定的转发入口读取当前 Props；仍向子项复制旧闭包的实现不得忽略回调变化。
- 比较器或缓存规则本身变化时重新求值，不沿用先前规则作出的跳过结论。

新建的 LabelProps／ButtonProps 引用通常不同，仅增加 `===` 判断收益有限。内置控件按实际显示输入设计比较和已有内容缓存，避免用任意深比较或反射遍历对象。

验收分别覆盖局部 State 变化与父级无关状态变化。前者不重建兄弟本来就是已有行为；后者才能证明新增跳过有效。Link Button 的 hover 下划线、Sidebar 菜单的交互前景色等真实变化仍必须更新。

### 5.3 订阅关系复用

每次成功 render 仅移除不再读取的依赖、添加新依赖，保留交集关系。render 失败不发布半套订阅关系，关闭流程仍能解除原有关系。

每条订阅保存可常数时间解除的内部登记，不在 StateSignal 的所有观察者中再次搜索。依赖收集和对比可以使用 StateSignal 自身的局部类型化序号作为索引；该序号只服务库内登记，不是任意对象的地址哈希、持久身份或新增 runtime ABI。

State 变化仍须访问实际观察者，这个 O(M) 通知成本合理。目标是消除 M 个观察者重复扫描同一订阅表造成的 O(M²)，以及未变化关系的反复拆建。解除关系后清除引用，保持卸载节点可回收。

## 6. 构造作用域、生命周期与实例归属

### 6.1 首次 render 前取得资源

组件／元素工厂改为接收当前 Props 与 ComponentScope。作用域已知道根、逻辑父级、方向及资源归属；工厂在该作用域内创建实例，首次 render 可以使用已取得的输入区域、交互控制器和显示资源。

推荐把公开 Component／Element／LazyElement 协议调整为持有本次作用域的抽象基类。应用继承的是公开组合／自绘协议，不是 MountedNode 或内部渲染节点；只共享这三个实际类型所需的归属实现。工厂签名和所有内置／第三方示例同时迁移。

资源创建和路由登记可在构造阶段完成；启动业务任务、发起聚焦或播放动画等需要挂载语义的动作仍在 onMount 或帧接受后执行。onMount 保留为挂载通知，不再负责让必需资源第一次变得可见。

创建顺序为：准备局部挂载归属和 scope → 工厂创建实例及资源 → 验证实例属于本次挂载并接入树 → 首次 render／子项构造 → 挂载通知。初始化中的挂载记录只存在于内部组装过程，不对外发布半初始化节点。

### 6.2 失败清理与状态

工厂取得的资源立即登记到本次 scope。工厂、首次 render 或 onMount 失败时，清理本次已创建的子项和资源，保留原始错误并按现有规则合并清理错误；构造未完成的实例不调用假定已成功挂载的业务通知。

卸载先停止该挂载继续产生工作，再清理后代和本地资源；通知和释放顺序在 UI 规范中写全，并与 scope 退休和异步任务取消保持一致。

移除 Button、选择控件、Command／Combobox 行和 Sidebar 等仅为“onMount 后发布 scope／control”而存在的 State。正常业务 onMount 修改状态后产生的后续 render 仍然合法。

布局前尚无布局结果、按需创建的资源和业务可选值仍可以用 Option。验收关注消除不必要的首轮补渲染，不要求所有控件没有 Option 或 `!!`；AGENTS 的 IR 输出完备要求不扩展成 UI 字段禁令。

### 6.3 用实例自身的归属替代全局扫描

公开基类在实际实例上保存私有挂载归属。一个实例服务一次挂载；把已有实例返回给另一次工厂调用时，在实例自身的归属处拒绝，卸载后也不把它重新包装成另一份新实例。可重复使用的是 View 描述和外部模型。

据此删除 ActiveInstances 的全局线性表。检查位置必须是实际 Component／Element／LazyElement 实例；仅在新建 MountedNode 上增加 registered 位无法发现两个节点共享同一实例。

该检查和解除为常数时间，不要求给 Any 增加 Hash，不为 UI 修改对象头、GC 移动合同或全局对象身份。修改接口是为表达真实的单次挂载生命周期，不以历史接口兼容性保留全局表。

## 7. 显示默认值与 DSL 整改

### 7.1 根默认字体

UI 根提供默认 FontCollection；未显式覆盖的控件使用该集合。未提供外部集合时，每个根创建并拥有一份系统 fallback 集合，在后代资源退休后关闭。外部集合由调用方持有，根和控件只借用；共享给多个窗口时，关闭一个窗口不能关闭它。

根默认字体通过 ComponentScope 的明确类型化入口取得，叶子元素在构造／更新时解析“显式字体优先，否则根默认字体”。组合组件不再仅为向所有后代传字体而复制配置；已有单个控件内标题／说明的局部覆盖继续有明确优先级。

默认集合更换或其 revision 变化，使实际使用它的布局失效，保持挂载身份。所有文字消费者一并迁移，包括 Label、Typography、Button 内容、可选择文字、Input／Textarea／OTP、菜单及自绘示例，不能让部分控件仍悄悄创建另一份默认集合。

本次先解决已经大量出现的根默认字体与显式覆盖。ThemeSource 的响应式变化、局部主题参数、Direction 的现有传播继续使用；不把任意 AmbientKey／Provider、自动 Context 换绑或移除 Direction 设为前置。业务状态、动作和模型继续显式传入。

### 7.2 保留 receiver 边界

保留语言规范 8.1.2 的 D0a 规则：receiver function 内不隐式访问外层 receiver，内嵌普通回调也不恢复这种查找。显式 `this@…`、对象引用和普通词法捕获继续可用。

不通过 DSL marker、额外 context receiver 或 builder 注入整个 owner 来隐藏访问目标。显式外层访问仍可用于确有需要的局部代码；整改目标是让常规界面组合减少对外层组件的依赖，不以字符串数量为验收条件。

### 7.3 普通 View 函数与动作参数

按表单、工具栏、列表行等真实组合提取普通 View 函数。函数接收显示值、稳定模型／Binding 和动作；builder 只配置当前对象与收集子项。小型 render 可以在进入 DSL 前准备局部 val 和动作，无需给每个叶子增加函数、组件或 ViewModel 层。

以下是根默认字体落地后的目标写法；普通参数和 View 函数组合当前已支持：

```kotlin
private fun counterView(
    value: Int,
    enabled: Boolean,
    onIncrement: () -> Unit
): View = row {
    spacing = 12.0
    label("Live controls")
    button(f"Count: ${value}", onIncrement) {
        this.enabled = enabled
    }
}

// In the persistent component, count is a delegated State property.
public override fun render(): View =
    counterView(count, model.enabled.value, { count += 1 })
```

普通函数不增加挂载身份，State 读取仍归调用者本轮 render。显示值是本轮快照；事件执行时通过 State／Binding／模型操作读取当前值，涉及可替换输入的动作读取当前 Props。不能把显示快照捕获成后续更新的依据，也不能修改已经发布完毕的 builder 来冒充状态更新。

必需模型、内容和动作继续放在普通前置参数；配置使用 `Builder.() -> Unit`，业务事件使用普通函数类型。槽位由组件提供所需的具名信息，优先沿用已有 `(ActionContentStyle) -> View`、`(SidebarPresentation) -> View` 等合同，避免调用方绕回外层对象重新查询这些信息。

### 7.4 配置与示例整理

优先使用已存在的 `style { ... }`、`focus { ... }` 等嵌套配置入口，删除示例中多余的 `Some(builder { ... })` 外层包装。普通字段仍保留单一存储，不为每个属性机械增加多套 setter。

继承、清除和显式赋值按对应字段的领域语义表达，不能为省略 Some 合并不同含义。容器布局配置建议放在子项声明之前，子配置只修改当前对象；这是示例组织约定，不新增语言求值顺序或语法限制。

先迁移 themes 的 Showcase 和 shadcn 中仍大量依赖外层字段的示例；对照已有普通参数形式的 progressExamples。保留 key、子项顺序、实例复用、当前事件处理器和编辑模型，不通过增加挂载层来掩盖 DSL 噪音。

## 8. View、Portal 与多窗口错误

### 8.1 保留有必要的节点职责

当前 Empty／Component／Element／Portal／Lazy／Direction 六种形状各有现有职责。增加大量普通控件没有要求继续增加 ViewBody；本次不以回到三种形状为指标，也不为减少 match 分支把 Portal／Lazy 强塞进普通 Element 并增加私有旁路。

新增普通控件继续组合公开 Component／Element／LazyElement。共享实现可以按实际重复提取；不创建第二套挂载或身份机制。

### 8.2 Portal 模式与状态保留

Portal.mode 从匹配身份移到可更新配置。同一逻辑父级、相同 key 的 Portal 改变 NonModal／FocusContained／Modal 时，保留内容实例、本地状态和编辑模型；模式配置不再造成内容卸载。

模式更新先验证选项组合，再在安全边界更新屏障、输入资格和焦点约束。需要新几何的聚焦等待 Accepted；解除模态约束不自动执行一次关闭／重开，onCloseRequest 和 onClosed 仍只表示实际关闭。

原焦点目标与恢复资格按真实聚焦和关闭过程维护，不能每次模式切换都覆盖为面板内部当前焦点。嵌套弹层、连续切换、未接受帧与关闭交错需有组合测试。

跨父级或跨窗口移动内容仍遵守普通挂载身份规则。Sidebar 在桌面导航和移动 Drawer 之间切换的状态归属需要按实际树结构处理，不能承诺仅移除 mode 身份就解决跨宿主迁移；可长期保留的业务模型继续由外层持有。

### 8.3 窗口级错误通路

窗口的构造、render、measure、scene、输入和帧完成回调失败，先停止该根后续工作、退休其输入与资源并关闭该 Surface，再向应用交付一次根错误。其他根的队列、业务观察者和有效帧继续运行。

UiHost 显式接收根错误处理器，参数包含 WindowId 和 Throwable。处理器正常返回表示允许其他根继续；应用可以主动退出。处理器自身失败、共享渲染宿主故障和宿主消息投递故障仍进入宿主级关闭通路，不吞掉错误。

attach 的初次挂载失败也归相应窗口：清理并报告后返回空结果，成功返回 UiWindow，避免异常再次穿过宿主总捕获而关闭其他窗口。单窗口快捷入口明确采用报告失败并退出的策略。正式签名、关闭时序及 LastWindowPolicy 行为同步写入 UI／Surface 规范。

UiHost 和 SurfaceHost 必须一起改造，在 SurfaceWindow／根回调入口处理窗口失败；只修改 UiHost.catch 不足以隔离下层已执行的整体 close。保留原始错误及清理错误，不自动重试、重新挂载或回滚任意业务 State；错误发生前对共享模型的写入仍然存在。

## 9. 实施批次与依赖

各批先修规范，再完成实现、调用方和定向测试。表中的顺序优先处理重复测量与无效布局；范围独立的文档／DSL 组合整理可以提前开展。已交付的组件库是迁移和验证对象，不重新设置“shadcn 第一批之前全部完成”的门槛。

| 批次 | 交付范围 | 依赖与出口 |
| --- | --- | --- |
| P0：基线与合同 | 确认当前 sysroot／工具链；补代表性计数；写完整布局结果和失效合同 | 得到可重复基线，明确哪些数值是实测；不扩大为通用 profiler |
| P1：测量结果复用 | 类型化完整布局结果、节点级帧内缓存、文本结果持有、Lazy 最终选择；调整 Flex／Grid | 重复请求只计算一次，A→B→A 的几何／文本正确，嵌套 Grid 消除重复展开 |
| P2：跨帧布局 | 布局／场景失效、动画用途、资源 revision、有效结果跨帧复用 | 稳定尺寸的纯绘制动画不调用 measure；真实布局动画仍正确 |
| P3：逻辑更新 | 输入跳过、当前 Props／children／回调合同、订阅关系差量更新 | 父级无关变化不级联可跳过后代；订阅操作随实际关系数增长 |
| P4：挂载与默认字体 | 构造作用域、公开实例归属、删除全局实例表、根默认字体、相关控件迁移 | 消除资源发布型补渲染；实例挂卸无全表扫描；共享字体生命周期正确 |
| P5：场景与图层 | 局部几何复用、静态场景边界、drawLayer 调用与版本整理 | 静态子树减少 scene，输入／焦点／帧完成及混合语义不变 |
| P6：窗口与 API 收尾 | Portal 动态模式、窗口级错误、DSL 示例和全部文档同步 | 模式切换保留内容；窗口失败相互隔离；当前接口与示例一致 |

P3 的订阅复用可以独立实施；P4 的公开基类与 P1 的 Element 布局泛型应在最初协议设计时一并列明，迁移到同一目标接口，不维护临时旧协议桥接。P5 依赖 P1／P2 的完整结果与失效；P6 的 DSL 数据／动作整理不依赖场景缓存。

每批只提交完成的能力与对应文档，不保留 TODO／未实现分支作为公开合同。只因下一批仍有优化空间，不重复运行已通过的无关全量验收。

## 10. 验收设计

### 10.1 计数与正确性矩阵

| 场景 | 必要断言 |
| --- | --- |
| 深度 1／3／6／10 的固定 Auto Grid 链 | 记录 measure、不同请求数和缓存命中；同节点同有效请求计算一次，总结果数随该构造深度线性增长 |
| Flex 的 Content／Fixed、Start／Stretch、有界／无界与 Frame 对照 | 尺寸、基线、放置正确；按实际不同约束计数，不要求任意布局算法全局线性 |
| A→B→A 约束切换 | 最后选择 A 时尺寸、子项放置、ActionInk 几何、文字换行和命中一致；没有提前关闭 TextLayout |
| Progress／Spinner／caret／纯颜色动画 | 完成初始布局后、约束与布局输入稳定期间 measure 为 0；实际像素仍变化并按可见性停帧 |
| Disclosure／Sidebar／Resizable 布局动画 | 实际尺寸变化仍触发布局；稳定兄弟子树复用，输入与新布局一致 |
| 局部状态与父级无关更新 | 分别断言 render／update 范围；保持真实 Link 下划线、交互文字颜色等变化 |
| 相同引用的可变业务输入 | 同引用 State 写回仍通知；未声明安全比较的子项仍取得变化 |
| 仅更换回调、Binding 或 children | 点击调用新处理器、绑定新模型、正确增删／重排；不残留旧闭包 |
| 共享 State 的大量观察者 | 通知为一次线性访问；稳定依赖不反复拆建；切换依赖和卸载后解除正确 |
| 批量实例创建／卸载与重复实例 | 登记／解除次数随实例数线性增长；同实例重复工厂返回被实例自身归属拒绝 |
| 构造、首次 render、onMount、清理失败 | 已取得资源恰好释放；错误保留；无资源发布型额外 render，无失效节点继续接收工作 |
| 默认字体、显式字体和多个窗口 | 默认集合共享、显式值优先、字体变化重排；根关闭只释放拥有的资源 |
| Tabs／Collapsible 隐藏、懒列表滚动与恢复 | 隐藏子树不测量、不呈现、不独自持续请求帧；状态保留，恢复无旧几何 |
| 真实 Command／Combobox／Sidebar 组合 | 分开统计筛选、构造、已实现项、布局和场景；不枚举全部列表项作为缓存代价 |
| 场景复用下的变换／clip／顺序／禁用 | 像素、输入、焦点、锚点和编辑几何一致，未接受帧不发布候选结果 |
| drawLayer 的缓存开关与 Clear／Src 等混合 | 保持独立合成语义，像素结果一致；分别测记录、重放与光栅化 |
| Portal 模式切换及嵌套关闭 | 内容实例／编辑模型保留；屏障、Tab 范围、焦点恢复与关闭回调正确 |
| 两窗口中的一个回调失败 | 只失败根关闭，另一根继续更新；根错误处理器失败走宿主级出口 |

计数由定向测试元素、已有测试模型或显式开发测量入口取得，不给每次生产操作增加长期计费或预算检查。性能基准记录目标、release 配置、真实挂载数量及帧时间；不把源码推导、缓存命中数或进度文档中的旧验收当成本轮性能实测。

### 10.2 测试位置与执行范围

- 普通状态、配置、模型、布局与资源行为放在所属 Cone 的 scoop.test 测试中，优先扩展现有 composition、layout、flex、text_cache、lazy、paint_cache、dsl_builders 和对应控件测试。
- 帧接受／丢弃、真实输入／焦点、窗口失败等使用已有实窗测试组织；只有确实需要外部进程控制时使用 fixture。D0a 的编译失败规则复用已有编译器覆盖，不为每个控件复制 negative fixture。
- 每批源码修改先格式化与静态检查，再运行相应 release 测试；调整共有协议后检查所有受影响库、示例和第三方 Element／LazyElement 的代表消费者。
- 先显式准备与源码一致的开发 sysroot，只重建实际变化的依赖。复核时 UiCompositionTest 曾因预编译 scoop.surface 缺少 FocusOrigin／FocusVisibility 导入而停在编译阶段；这不是已通过的基线，开始 P0 时须先解决依赖对齐。
- 共有帧／焦点／窗口合同改动列明 macOS、Windows、Linux 的验证范围；未执行的平台据实记录，不以单平台通过替代全部结论。
- 原始日志、逐帧数据和 profiler 文件保存在仓库外；实施记录只保留范围、结果概要、失败闭合及实际限制。
