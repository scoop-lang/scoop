# 真实读屏器与触屏验收

使用同一批构建好的 accessibility 和 touch-input 示例。每个平台先完成适用的整组操作，再汇总异常；修完本轮所有缺陷后，只复查受影响项。已确认的 macOS 捏合／旋转和文本拖放不重复。

本轮人工环境为 macOS VoiceOver、Windows Narrator、Linux Orca 与 Linux 触屏。Windows 程序由用户直接启动；Linux 使用用户能操作的 `wayland-0`。程序按正常用户操作取得输入，不循环请求系统激活。软件键盘、笔及其他尚无设备的组合保持待验，不能据接口或合成事件补记通过。

## A：读屏器

先打开 accessibility 示例，使用当前读屏器的导航与控件操作命令；不要求三种读屏器采用完全相同的按键或措辞。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| A1 | 找到 Display name，读取 Alex，改成 `Scoop😀中`，选择后读取选区 | 可读标签、编辑角色、当前文字及实际选区；编辑结果只出现一次 |
| A2 | 找到 Receive updates，关闭后重新打开 | 读出复选角色和当前勾选状态；操作与界面状态同步 |
| A3 | 找到 Volume，增减数值 | 可读当前值与范围，按 5 为步长改变；读屏器数值与界面一致 |
| A4 | 展开、折叠 More information | 展开状态准确；内容只在展开时进入阅读范围 |
| A5 | 导航 Delivery options 表格 | 能分辨两列表头 Channel／Frequency，并读取 Email／Weekly、In app／Daily 的对应单元格 |
| A6 | 操作 Announce status 两次 | 可听到相应的 Status update 公告，当前操作位置不被公告移走；允许读屏器合并尚未播出的 polite 公告 |
| A7 | Save 打开 Saved 对话框，导航内容，再用关闭入口或 Escape 关闭 | 能读标题和正文；模态期间不能操作背景字段；关闭后回到可用的原窗口 |

再打开 touch-input 双窗口示例，用读屏器找到一个虚拟列表项目，使用 Move up／Move down 改变位置，滚动后重新定位该项目；检查名称与顺序一致，旧位置没有重复项目。Zoom／Rotate／Reset 按钮应可完成与手势对应的操作。Password 字段只暴露受保护状态，不读出测试正文。Open modal 打开的弹窗应提供名为 Close 的默认关闭按钮，读屏器可直接找到并操作。

## T：Linux 触屏

在 `wayland-0` 上打开 touch-input 双窗口示例。各项完成后统一反馈；不需要同时操作 Orca。

| 编号 | 操作 | 预期 |
| --- | --- | --- |
| T1 | 轻点按钮、复选框和输入框；在长文及虚拟列表中直接滑动 | 轻点只执行一次；拖动滚动不误触按钮，滚动内容与触点一致 |
| T2 | 快速滑动后松手，再触碰正在滑动的内容；拖到滚动边界 | 松手后的惯性与当前设置一致；再次触碰能接管；回弹恢复到合法范围，命中位置随画面移动 |
| T3 | 在图形区域双指捏合、旋转，再松开一个或全部触点 | 图形与数值同步，接触结束后停止；剩余触点不会跳变成一次无关点击 |
| T4 | 长按文字选择，拖动两端把手，跨越长文可见边缘；松手后从选区内部直接拖出，再分别长按选区和鼠标右键 | 选择与把手同步；越界时可继续选取；从已有选区直接拖动可开始拖放，长按选区与右键保留选区并打开编辑菜单，动作及关闭后编辑正常 |
| T5 | 长按可提示／可弹菜单的控件，选择菜单项目，再点外部关闭 | 显示相应提示或菜单；动作只执行一次，关闭后后续触摸正常 |
| T6 | 在列表中拖动项目，使用另一窗口接收文本；取消一次拖放 | 成功操作只有一份目标结果；Move 来源只删除一次；取消保留来源 |
| T7 | 在 133% 下把窗口分别移到屏幕左上与右下，触点相同控件；运行中切换显示缩放后再次触点及滑动 | 触屏命中与鼠标一致，不随桌面位置偏移；改缩放后无需重启即可继续输入与绘制 |

若会话提供软件键盘，分别进入 Email address、Telephone number 和 Notes，核对布局／输入用途、遮挡后的可见编辑位置，以及关闭键盘后的恢复。未出现软件键盘时记录环境实际行为，不把请求返回成功当作设备通过。

## D：跨程序拖放与 Linux PRIMARY

使用 touch-input 示例与一个临时外部文本编辑文档。各平台完成同框移动、两窗口移动，以及双向跨程序复制／移动；核对文字完整、复制保留来源、移动只删除一次，取消不改变两边。macOS 已通过的文字、URL 双向和多文件复制拖放结果直接复用。

URL 与文件列表分别验收；接收区显示最后收到的内容，每种格式都先重新拖入，再立即拖出：

1. 把浏览器中的 URL 拖入接收区，再拖到支持链接的外部目标，核对完整地址，包括查询参数与片段。拖到文件管理器时，平台可能生成 URL 快捷方式。
2. 同时把两个含中文／emoji 名称的临时文件拖入接收区，确认显示两个文件名，随后从接收区复制拖到空目录。核对两个文件的名称、正文及源文件保留；中间不再拖入 URL，以免替换接收区内容。

Linux 在原生 PRIMARY 可用且有中键时，另用 Notes 与临时外部文档双向执行“选中文字 → 在另一处中键粘贴”。先在普通剪贴板复制一段不同的文字，检查选取及中键粘贴后，普通粘贴仍得到原先复制的内容。没有中键或会话不提供 PRIMARY 时记录实际条件。
