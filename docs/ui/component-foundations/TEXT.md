# 编辑策略、显示投影与文本选择

本文属于 [控件基础设计](DESIGN.md)，规定 T1／T2 的目标合同，尚未实施。继续使用 `scoop.ui.text` 中的 TextEditorState／TextEditHost、window 的 TextInputState 事务和 graphics.text 的 Unicode／布局查询；`scoop.ui.text` 仍是 UI Cone 内的公共 package。

## 1. 保留一份编辑模型

TextEditorState 继续保存真实正文、方向选区、端点 affinity、marked range、revision 和历史；同一模型同一时刻只有一个活动编辑宿主。TextEditHost 负责焦点、输入、滚动、排版和已提交几何。OTP 分槽或遮罩不建立第二份文档，也不为每个格子创建独立 IME 连接。

本轮不实现富文档编辑、语法高亮、Code Block、系统密码控件、原生自动填充或 accessibility 文本接口。普通输入过滤和视觉遮罩不声称提供 OS secure-input 能力。

## 2. 输入策略接在发布之前

把现有单行换行归一化演进为公共 `TextEditPolicy`，随 TextEditHost 的不可变 options 更新。它用于真实输入、粘贴及编辑命令产生的修改；输入来源明确区分 NativeInput、Paste、EditCommand 和显式 Programmatic 请求，便于选择适用变换。

TextEditorState 的普通 `replace` 仍表示调用者明确编辑模型，`replaceAll` 仍表示替换文档并重置历史；它们不偷偷查询当前宿主选项。需要程序编辑也遵循输入策略时，使用显式传入 policy 的同一事务入口。应用的持久数据校验与 UI 输入限制各有明确调用边界。

策略收到完整准备后的编辑候选，返回接受、拒绝或一组变换。变换以候选文本上的非重叠 UTF-8 区间替换描述，框架据此生成位置映射；不能只返回一个无映射的新字符串，再猜测光标应该移动多少字符。

配置包含当前确实需要的组合：

- 单行换行处理；复用原有 CRLF、Unicode 换行和选区映射规则。
- 粘贴文本变换，例如移除 OTP 分隔符；只对 Paste 来源启用时不影响正常逐字输入。
- 明确的字符／文本接受规则；不把 ASCII 数字、Unicode 数字或其他字符类别混为一个隐式选项。
- `maxLength` 按 Unicode grapheme 计数。截取只发生在 grapheme 边界，并计算本次替换的选区释放出的长度；不能把组合字符、emoji ZWJ 或 UTF-8 字节切断。
- 自定义纯变换与拒绝。配置顺序有明确含义：换行处理、来源特定变换、字符约束、长度约束。built-in 与自定义变换在同一事务内生成最终映射。

已经由程序放入的超长正文不会在首次普通输入时被无提示地截掉尾部。长度限制约束新增内容；删除或减少长度的修改仍能进行。需要规范化整份既有文档时，调用显式程序编辑。

策略回调在同步准备阶段执行，不能写 State、重入同一 editor 或启动任务。使用现有 UI 求值／修改规则，不增加编译期纯度系统。回调异常和非法变换在发布前失败，不改变正文、历史、composition 或原生快照。

## 3. 原生 batch、composition 与变换顺序

原生 batch 内每个操作的范围基于该批之前的操作结果；不能一边接收原生 operation，一边过滤文本，却继续使用原生旧偏移。统一流程如下：

1. 检查活动连接、来源和 baseRevision。在临时值中按原始顺序应用整批操作，保留已完成编辑和末尾仍在进行的 composition 基线；不发布中间值。
2. 得到已提交候选文档、可能存在的 preedit 覆盖及方向选区。已完成部分交给策略；尚未提交的 preedit 保留原生文本和有效范围，不按 OTP 字符集或 maxLength 截断。
3. 对候选的实际区间替换生成位置映射。把选区、affinity、composition 基线和待显示 preedit 的挂接位置一并重定位，保留 preedit 本体；不能只映射最终 cursor。
4. 若一个 batch 先 Commit 再 Preedit，前面的已提交部分仍经过策略，后面的组合接到变换后的正确位置；不能因为末尾有 marked range 就跳过前面已完成的编辑。
5. 合成一个完整结果，复用已经验证的范围与映射，一次提交正文、选区、composition、revision 和历史，再发布 native 文档快照。不要为了证明前一阶段完成而重新完整验证同一份结果。

位置映射以合法 UTF-8 标量边界表示。保留片段保持相对位置；被替换片段中的端点依据 affinity 落到替换前／后边界。grapheme 限制在实际用户编辑边界应用，native 标量范围仍按 window 合同接收，不错误拒绝合法 IME 更新。

拒绝普通编辑时保持先前文档和历史。拒绝最终 composition commit 时恢复该次组合的已提交基线、结束 marked 状态，并把恢复后的快照反馈给原生连接。即使拒绝后正文没变，也必须确认已消费的 native origin，使原生不会继续基于被拒绝文本发出旧范围；不能仅因 `onEdited` 不触发而跳过确认。

取消 composition 沿用既有基线恢复，不把临时 preedit 放入 undo 历史。策略在组合中途更新时不改写活动 preedit，最终提交使用当前有效策略。只读／禁用、换绑或失焦的处理仍由宿主和连接生命周期统一决定。

## 4. 撤销、重做和剪贴板

一个被接受的原生 batch 或一次粘贴包含的全部变换作为同一编辑事务。历史记录保存用户可见的最终修改，不能先存原文，再用一次 `replaceAll` 纠正。连续键入只有在既有合并条件成立时才合并；显式变换、选择变化和 composition 边界应结束不适当的键入合并。

Undo／Redo 回放已经接受的历史，不再次执行用户策略回调。策略变化不能使 redo 变成一次新的、内容不同的输入。回退时 selection 和 affinity 同样恢复。

Cut 先准备可接受的删除事务，再成功写出原选择文本，最后发布删除；剪贴板写入失败不修改文档或历史。Copy／Paste 使用 [共同剪贴板合同](PLATFORM.md#3-剪贴板的共同文本合同)，不在 editor 内再加一份 OS 行尾处理。变换只修改本次粘贴的编辑结果，不改写系统剪贴板内容。

`onEdited` 在成功发布后通知最终结果，是业务观察入口，不是做过滤、撤销修复或光标补丁的入口。单纯确认被拒绝的 native origin 不伪造一次正文编辑通知。

## 5. 文档与显示文字的投影

增加独立的显示投影，输入为真实编辑快照，结果包含用于排版的文字与单调的位置映射。默认恒等投影；内置遮罩按原文 grapheme 生成显示单元，并保留必要换行。投影不修改 TextEditorState，也不向历史追加编辑。

| 操作 | 使用的数据 |
| --- | --- |
| 过滤、undo／redo、程序读取 | 原始文档及其选区 |
| Native surrounding text、selection、marked range | 原始文档；不把遮罩文字作为真实输入法文档 |
| 排版和光标显示 | 投影后的文字，原文端点通过映射定位 |
| 鼠标命中、拖选、视觉移动 | 使用已提交显示布局，结果逆映射回原文，保留 affinity |
| 选择背景与 preedit 装饰 | 把原文范围映射到显示布局，不按字节数估算矩形 |
| 复制／剪切 | 由明确的复制策略决定，允许时使用原文，不复制意外的遮罩符号 |

映射支持保留片段、替换显示单元及不占原文的分隔显示；不允许任意重排原文索引。RTL 的视觉顺序交给 TextLayout，位置映射处理逻辑偏移。边界由区间和 affinity 表示，不建立按每个 UTF-8 字节膨胀的全表。

投影结果与布局归同一快照所有，旧 Accepted 场景仍使用旧布局和旧映射。新的测量／绘制失败时不能把新映射套到旧画面上。改变字体、宽度、遮罩或投影规则后，按现有资源替换与成功帧协议更新。

内置遮罩模式默认禁止 Copy／Cut，调用方可以明确调整策略；Paste 和正常编辑仍可用。临时显示原文只改变显示投影，不把它当成一次输入，也不重新创建 editor。是否自动暂显最后字符属于后续 Input 控件策略。

OTP 后续使用一个编辑模型和一个真实焦点，按显示单元绘制格子、活动格和选择状态。公共宿主提供原文范围对应的 caret／selection 几何，控件不按 `String` 字节或 UTF-16 长度拆格。短信自动填充、平台专用密码输入行为不属于这项能力。

## 6. 可选择的 StyledText

现有 ParagraphHost 已提供 StyledText、行内对象和命中／选择几何；Label 目前没有完整选择行为。增加只读的文本选择宿主，复用同一 ParagraphHost、Unicode 导航和公共输入行为，不把带样式内容转换为一个丢失样式的 Textarea。

宿主保存方向选区、锚点和已提交布局，提供拖选、按词／行选择、Shift 扩展、SelectAll 和 Copy。它只处理选择相关的语义命令，不打开用于插入文本的 IME 连接，不维护多余的编辑／撤销文档。

选区始终用原始 StyledText 的逻辑 UTF-8 范围表示；复制沿现有文本／行内对象替代文字规则输出纯文本。换行、软换行、截断、双向文本和行内对象均通过公共排版查询处理，不能用屏幕 x 坐标比较来判断逻辑范围。

对链接或 Marker 这类文本范围交互，使用稳定 key、范围和显式动作／装饰描述。范围的已提交矩形可组成一个 InputArea 形状，共用 Press；文本拖选达到阈值后按 [序列归属](INTERACTION.md#2-按下序列归属与拖动) 取消链接的点击候选。焦点与激活仍走公共协议，宿主不自行调用浏览器或 OS URL API。

本轮只保证同一文本宿主内部的选择和范围交互，不实现跨任意组件树的全局文档选区、Markdown 解析或可编辑富文档。Message／Typography／Marker 等控件以后在这个能力上组合外观与动作。

## 7. 验收重点

- 过滤前后包含组合字符、emoji ZWJ、非 BMP、CRLF 和 Unicode 换行；长度按 grapheme，原生范围按 UTF-8 标量，两者不混淆。
- 单次替换、替换选择、删除、超长已有文本、OTP 分隔符粘贴、非法策略结果和回调异常；失败前后正文、选区、composition 和 undo／redo 保持一致。
- 原生多 operation batch，尤其是 Commit 后 Preedit、preedit 多次替换、取消后继续编辑、拒绝最终 commit、换绑后的迟到 origin；中文输入法不得因实时过滤打断组词。
- 一次粘贴／过滤只撤销一次；undo／redo 不重跑策略；剪切遇到剪贴板失败或策略拒绝不丢原文。
- 遮罩、显示分隔符、零宽原文映射、双向文本和切换显隐；鼠标命中、方向移动、选择背景和 native caret 使用正确快照。
- StyledText 拖选跨样式和行内对象、链接点击转拖选、截断恢复、文字变化及失败帧；资源替换后无旧布局借用、无重复 IME 连接。
- 原有 TextEditorState、TextEditHost、ParagraphHost、Input／Textarea 的定向测试继续通过，静止输入框没有多余帧或计时任务。
