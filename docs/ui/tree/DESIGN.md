# Tree 与父节点吸顶设计

设计日期：2026-11-21；多列补充：2026-11-22。状态：实施中，实际交付见[实施记录](PROGRESS.md)。目标是在 `scoop.ui.component` 增加通用 Tree 和目录树入口，对齐 Ant Design Tree／DirectoryTree 的功能，提供同一组件的单列／多列模式，并支持 VS Code 树视图的 Sticky Scroll（滚动时保留当前分支的祖先行）。

本文中的新类型和方法在对应批次交付前均为拟议接口。实施各批次前，先把相应合同纳入 [组件规范](../../specs/SCOOP-UI-COMPONENT-SPEC.md)、[UI 规范](../../specs/SCOOP-UI-SPEC.md)和无障碍规范，再修改实现、调用方与编程材料。当前行为仍以现行 spec 为准。本次按用户要求只在本地 macOS 验证；公共接口保持平台无关，不将跨平台运行验收作为本次完成条件。

## 3. 数据、状态与公开入口

### 3.1 数据快照

建议先提供具体的 `TreeData<T>` 与 `TreeNode<T>`，用不可变节点数组构成多根树。一个节点包含：

- 显式、全树唯一的 `ViewKey`，以及类型化业务值 `T`。
- 用于默认标题、Typeahead 和无障碍名称的文字；自定义 View 不被反向解析为文字。
- `enabled`、`selectable`、`checkable`、`checkboxEnabled` 和拖动资格等实际能力。
- `TreeChildren<T>`：`Leaf`、`Known(Array<TreeNode<T>>)` 或 `Deferred`。`Known([])` 是已经加载的空分支；`Deferred` 表示尚未读取，不能用空数组冒充。

图标和标题 View 在行渲染器中按需构造；节点数据本身不预建整棵 View。业务结构通过普通类型化代码映射到这些节点，对应 Ant 的 `fieldNames` 能力，不引入字段名反射或 `Any` 数据表。

`TreeData` 在接入新快照时建立 key、父引用、深度和同级位置索引，检查重复 key、结构环及同一节点重复挂入多个父项。相同文字合法，`ViewKey.Position` 不可作为节点身份。未变快照不在滚动或每帧重复检查。

这一入口会为当前已加载的 N 个节点建立 O(N) 元数据。虚拟化限制的是 View／布局／绘制数量，不宣称免除数据索引成本；未加载子树不进入 N。先满足 Ant 的实际数据规模，不预建另一套远程游标或百万层级数据协议。

### 3.2 状态归属

`TreeState<T>` 是应用可持有的普通模型，关联数据快照、展开、选择、勾选、查询和加载结果；配置多列时同时持有列定义、显隐、宽度覆盖与排序。提供 `replaceData`、`setExpanded`、`setSelected`、勾选、重试、`pathTo(key)` 及列状态的明确动作；构造／更新检查输入，render／measure／scene 只读取结果。

可交互状态分别使用本地 State 或外部 Binding：展开与选择绑定 key 数组；级联勾选绑定 checked keys，独立勾选绑定包含 checked／halfChecked 的完整值。两种勾选配置用不同 enum 分支携带对应输入，避免让调用方给级联模式提供任意半选结果。

本地模式从 initial 值初始化一次；绑定模式直接读写 Binding，不复制一个看起来已接受的内部值。写入后读取实际采纳结果，再发送变化通知。被拒绝的展开不触发加载，被拒绝的勾选／选择不改变呈现；单纯重复激活仍可发送独立的 `onActivate`。

展开、选择、勾选与键盘焦点四者独立。展开父项不自动选择它，点 Checkbox 不顺便选行；焦点取真实 FocusTarget。模型只保存范围选择的锚 key 等必要策略状态，不保存另一份系统焦点。

未知 key 可以来自待加载数据或受控恢复值，暂不参与呈现；不在 render 中擅自清空外部 Binding。删除节点立即退休挂载、输入和该节点的在途请求；选择值是否保留由应用的显式更新决定。替换整个数据集可同时显式重置状态，不以标题推断身份延续。

### 3.3 入口示意

以下为拟议调用形状，不是当前可编译示例；精确签名随实施批次进入 spec。

```kotlin
val state = TreeState(
    data,
    selection = TreeSelectionMode.Multiple,
    checking = TreeChecking.Cascade()
)

tree(state) {
    this.height = Some(480.0)
    this.itemExtent = ItemExtent.Fixed(28.0)
    this.showLines = true
    this.expandAction = TreeExpandAction.DoubleClick
    this.sticky {
        this.enabled = true
        this.maxRows = 7L
        this.maxHeightRatio = 0.4
    }
}
```

`TreeHandle` 绑定一个挂载，提供按 key 显露、聚焦和读取最近 Accepted 的阅读位置；多列时另可按 `(nodeKey, columnId)` 显露或聚焦单元格。模型的 `pathTo` 不依赖挂载。显露允许明确指定 `expandAncestors`，受控展开拒绝时不伪造成功；已知路径上的折叠祖先可依次展开，尚未加载、不可确定路径的任意远程 key 不通过扫描或递归网络请求猜测。隐藏／不存在的列不被显露请求自动打开，不能显露的请求沿普通失败结果结束。

普通 Tree 默认只由箭头展开；DirectoryTree 默认单击标题展开，也可选双击或仅箭头。DirectoryTree 默认整行命中和 Sticky Scroll，普通 Tree 的 Sticky Scroll 默认关闭、可显式打开。普通目录／文件图标可由主题和应用覆盖。

### 3.4 事件

变化通知提供触发 key、类型化节点值、输入来源及实际采纳后的结果；选择／勾选不依靠重建 View 收集节点。展开、选择、勾选、加载分别有 `onExpand`、`onSelect`、`onCheck`、`onLoad`；后者只在成功发布子项后通知。加载失败有独立错误通知和状态。

`onActivate` 与 `onDoubleClick` 表示动作，右键沿现有 ContextMenu 接入并可通知 `onContextMenu`；拖动提供开始、进入、经过、离开、结束与 Drop 的对应事件。事件使用已有指针／键盘信息及原生菜单锚点，不复制 DOM Event。源替换或内部投影重算不冒充用户输入事件，变化通知也不承担受控 Binding 的第二条写入路径。

列显隐、宽度和排序采用相同的采纳后通知规则。列的外观更新不发送节点选择／展开通知，列调宽结束也不冒充业务单元格编辑提交。

### 3.5 多列定义与状态

不提供列配置时使用现有单列入口。显式的 `TreeColumns<T>(columns, treeColumn)` 保存非空列数组和必需的树列 ID；每个 `TreeColumn<T>` 包含：

| 字段 | 职责 |
| --- | --- |
| `id: String` | 当前列定义内唯一的稳定身份，独立于标题与显示位置 |
| `header` | 表头文字或自定义 View；另有明确的无障碍名称 |
| `cell: (TreeNode<T>) -> View` | 按需构造该节点的单元格，访问类型化业务值及必要节点信息 |
| `semanticText` | 可选的纯文字描述函数，读取节点数据，不构造 View |
| `size: TableColumnSize`／`alignment` | 复用现有列宽类型、最小／最大值、文字样本及逻辑对齐 |
| `resizable`／`hideable` | 列调宽与显隐资格；树列始终可见 |
| `compare: ((T, T) -> Int)?` | 可选的业务值比较函数，供同级稳定排序使用 |

`treeColumn` 必须对应一个实际列，不要求物理上位于第一列。只有树列增加层级缩进、连接线、展开器、Checkbox 和节点图标；其他列直接显示各自的单元格。节点用于 Typeahead 和默认名称的文字仍来自 TreeNode，不从任意单元格 View 提取。

列与节点身份分别保存；单元格地址使用节点 key 与列 ID 的组合，不拼接标题或行列序号。同 key 的节点重排、整行吸顶与按相同 ID 更新列定义保持存活单元格的身份。显隐导致实际单元格退出挂载时，按现有生命周期结束其输入会话；需要保留的业务字段仍由应用模型持有。

列配置是不可变快照，显隐、宽度覆盖和排序属于独立状态，通过 `replaceColumns`、`setColumnVisible`、`resizeColumn`、`setSort` 等动作更新；需要外部控制时使用普通 Binding。`replaceColumns` 保留同 ID 的有效宽度／显隐状态，新限制收敛原宽度，删除列时清理对应列状态。未知列、重复 ID 或缺失树列在接入时报告；试图隐藏树列保持原状态。删除当前排序列或移除其比较能力时，在该次明确更新中结束对应排序。

配置多列的拟议调用形状如下，`columns` 为应用已经构造的类型化列数组；仍使用同一个组件入口：

```kotlin
val state = TreeState(
    data,
    columns = TreeColumns(columns, treeColumn = "name"),
    selection = TreeSelectionMode.Multiple
)

tree(state) {
    this.height = Some(480.0)
    this.sticky { this.enabled = true }
}
```

显式列模式即使只剩树列可见，也保留表头、列配置与树形表格语义，不随可见列数在两套模式间切换。表头默认显示，可显式隐藏；隐藏表头不丢失列名称和程序列操作能力。

## 4. 展开、选择与查询

`initialExpandAll` 只作用于初始化时已知节点，`initialExpandParent` 默认打开初始指定节点的祖先。后续异步返回不重放初始值，也不自动递归加载整棵远程树。`setExpanded(keys, expandAncestors=true)` 在该次明确更新时补齐祖先，对应 Ant 的自动展开祖先能力；默认更新不反复补齐。应用若希望每次受控更新都强制显示路径，应每次明确采用该策略；普通手动折叠不因仍保留后代展开 key 而立即重开。

基础 Tree 的多选支持逐项切换；DirectoryTree 使用桌面目录规则：普通点击替换选择，Primary 点击切换单项，Shift 选择锚点到目标之间的当前展开行范围。目录预设中再次点击已选单项保持选择。Primary 由底层平台快捷键抽象解析，不在控件判断操作系统。

范围选择遍历逻辑展开行，不只取当前挂载项；跳过不可选择项，折叠子孙不参与新范围。连续 Shift 操作使用开始时的选择基线和锚点，反向缩短区间不会不断累加旧范围。已有隐藏选择保留，是否清除由本次替换／增量操作决定。锚点已删除或退出当前投影时，从当前可见焦点或目标建立新锚点。

查找分两种明确模式：

- Highlight：与 Ant `filterTreeNode` 一致，只标记命中，不删行；可显式展开命中路径并跳转结果。
- Filter：显示命中项和使它可达的祖先路径。只搜索已加载数据；不为查询自动拉取未知子树。退出查询恢复用户原来的展开状态，搜索展开作为临时投影保存。

过滤只改变投影，不裁掉基础树数据或按隐藏结果重算业务勾选；级联操作仍作用于基础树中已知、可传播的节点。匹配高亮与选择分别着色，不能用 selected 冒充命中。

默认匹配文字来自节点的搜索文字，允许类型化匹配函数。元数据匹配不构造标题 View；查询或数据改变时才重算结果。

### 4.1 同级排序

多列提供显式单列排序，复用 `TableSort` 的稳定列 ID 和方向值；没有排序时保持来源顺序。有 `compare` 的列才提供表头排序动作，点击按未排序 → 升序 → 降序 → 未排序循环。应用可由 `setSort` 或对应 Binding 控制，受控拒绝不先切换排序标记。

排序分别作用于每组直接子节点，根节点视为同一组；比较相等时保持来源顺序。先得到同级有序结果，再按展开与过滤规则投影，不能把展开后的所有行全局排序而打散父子关系。数值、时间等按业务值比较，不按格式化后的单元格文字排序。

比较只读取当前已加载数据，不触发加载或构造单元格 View；新加载的一组子项按当前排序接入。排序、数据或比较函数改变时重算必要的同级结果，列宽／显隐、选择或滚动不重跑排序。隐藏排序列保留已生效排序；应用可通过模型清除，列显隐菜单标明当前排序。

排序不改变 key、选择、勾选、展开或基础数据中的父子关系；阅读锚点按 key 保持，Shift 范围选择改用排序后的当前展开行序列。来源顺序由应用维护，需要服务端排序时由应用发布相应有序快照，本地不再配置重复的比较动作。

## 5. 勾选规则

`TreeChecking.Off` 不创建 Checkbox；Cascade 与 Independent 是两种完整策略。

Cascade 下，勾选父项向可传播子孙传递，子项变化向祖先汇总。全部可参与子项勾选时父项勾选，部分勾选时为 Mixed，全部未选时为 Off。checked 和 halfChecked 不重叠；取消某个子项时同步撤销祖先的“全选”结果，避免下一次投影又从旧父 key 把它勾回去。

`enabled=false`、`checkboxEnabled=false` 或 `checkable=false` 都是勾选传播边界：传播不越过该节点向下或向上穿透，父项汇总排除该分支。禁用节点自身的受控值可以显示；其后代由独立用户操作改变时，也不反向穿透边界。若没有任何可参与子项，不因空集而凭空自动勾选父项。

例如 P 下有 A、B 和禁用的 C：选择 P 只更新 A、B；A、B 都选中即可使 P 全选，C 的值保持原样。C 下可交互的后代仍可独立操作，但不影响 P。

Independent 下只更新当前 key，允许应用给出独立 Mixed 状态。用户点击 Mixed 变为 On；设置完整外部值时照实际值显示。两种模式共享 Checkbox 的既有三态外观，不另造复选框。

父节点已勾选而子项未加载时，不为了计算勾选发起加载。该 key 表达对分支的勾选意图；后续实际接入的可传播子项继承当前意图，再汇总半选。若期间取消父项，迟到子项按最新勾选状态接入。全选状态只描述当前 UI 模型及其分支意图，不等同于已经枚举所有远程业务实体。

整体 `enabled=false` 沿现有 UI 输入范围停用树；节点 `enabled=false` 停用该节点的用户动作，不隐式禁用所有后代。需要“可展开但不能选择／勾选／拖动”的节点时，分别关闭这些能力。这是与 Ant 节点 disabled 仍可触发展开细节的明确适配，保持 Scoop 的统一禁用与无障碍合同。

## 6. 异步加载与数据更新

使用一个类型化 `TreeLoader<T>` 描述必要的应用 CoroutineScope 和加载函数；加载函数为 suspend 调用，返回该节点的子节点数组。它复用现有 Job 和 owner 投递，不在 UI 库引入调度器、HTTP 客户端或重试服务。

叶／已知／未知由 `TreeChildren` 表达；加载中的 Job 与失败信息由模型按 key 保存。对 Deferred 节点，状态为未请求、加载中或失败；成功后将该分支替换为 Known，已加载 key 集合由数据派生，避免与 children 不一致的第二份 loadedKeys 真相。应用也可通过替换数据快照发布 Known 或使分支重新成为 Deferred。

1. 用户展开被采纳后，对 Deferred 分支启动一次加载。显式初始／受控展开遇到 Deferred 时，在正常更新后的动作边界启动；不在 render、测量或语义查询中启动。存在 Deferred 的可交互树必须有 loader，缺少必要输入在配置接入时报错。
2. 同一 key 的当前请求去重。加载时显示原父行上的进度，保留原位置；用户可以折叠，不显示伪造的业务子节点。
3. 折叠默认保留正在进行的请求；成功缓存子项，保持用户当前折叠状态，不自动重新展开。
4. 成功为空数组时成为已加载的空分支，可按目录外观保留文件夹图标，但没有可展开子行。失败不等于已加载；显示错误及显式重试入口，不在每帧或重绘时自动重试。
5. 删除节点、替换数据集／loader 或模型关闭时取消相应 Job。完成时核对当前数据集、节点和该次任务仍对应，旧结果不能覆盖新请求；使用普通任务身份即可。
6. 取消恢复为可再次请求状态，不显示网络失败。业务作用域拥有任务寿命；观察同一外部模型的某个 View 卸载，只解绑观察，应用结束模型时才关闭其任务。

完成后的同级排序、展开投影、勾选汇总和阅读位置在同一次模型更新中使用新数据。加载状态改变而数据未变时，复用原节点索引。

## 7. 展开投影与虚拟化

基础树与展开后的行序列分开。内部 `TreeProjection` 保存每个当前展开行的 key、节点引用、父行索引、深度、同级位置、可见子树的排除末端索引，以及连接线所需的祖先信息。加载、同级排序、过滤和展开共同生成一份投影，布局、导航、吸顶与语义读取同一份结果。

第一版在数据／展开／过滤／排序改变时，从当前同级顺序 O(V) 构造 V 个展开行的索引和 key 映射；同级排序本身另有比较成本。选中、hover、焦点、列宽／显隐或单纯滚动不重新展平。勾选重算只涉及实际受影响的子树和祖先，外部整批变化允许一次 O(N) 重算。用真实性能结果决定是否需要更细的结构增量更新，不先建立复杂的动态顺序树。

布局按 offset、viewport 和 overscan 找到所需范围，再加入吸顶祖先和既有 `pinnedItems`。仅这些行构建 View 并测量；挂载量与视口行数、吸顶行数和活动交互项有关，与整棵树的 N 无关。相同 key 在普通位置与吸顶位置之间保留一个挂载实例。

默认使用主题给出的单行高度；固定高度是主要快速路径，可变高度复用 `ItemExtentIndex` 的估计与按需测量。行高、字体或宽度变化使必要尺寸失效；未测量行使用估计，不为首屏或最长标题扫描并布局所有节点。

默认虚拟模式要求有界视口，正文按可用宽度截断或换行。单列需要横向滚动时使用明确的 `contentWidth`；多列的内容宽度由列宽总和决定，不能再叠加另一份互相冲突的 contentWidth。两者使用共享的外层水平视口，不靠当前可见行的最大宽度让滚动条来回跳。小型有限树可关闭虚拟化并自然测量所有展开行；所有模式共用数据和交互，有界滚动模式共用吸顶算法。自然高度、没有自身纵向滚动视口的 Tree 不产生吸顶，也不自动接管外层 ScrollArea。

展开、折叠、前方插入和实际行高变化沿 KeepVisible 保持正文的稳定 key。折叠包含真实焦点的分支时，先请求焦点回到该存活祖先；删除焦点节点则选最近存活祖先或邻近行。模型／数据替换与 Discarded 帧沿现有更新和提交规则处理。

### 7.1 共享列布局、表头与滚动

多列沿用 `TableTracks` 分配宽度：Fixed 使用声明宽度，Fraction 从最小值分配剩余空间，Auto 只测明确的表头／文字样本；自定义 View 表头没有可提取文字时使用样本或最小值。树列的自然宽度另计展开器、Checkbox 和图标的固定槽位，深层缩进在分配后的列宽内消耗；应用可用最小宽度明确预留路径空间，不为寻找最深／最长节点扫描整棵树。总最小宽度超出可用宽度时横向滚动，内容不得侵入相邻列。

表头、普通行和吸顶行消费同一次完整布局中的不可变列宽结果与列顺序。树列在自己的分配宽度内扣除缩进和控件槽位，剩余空间才交给标题；可用空间不足时沿该列裁剪。RTL 按逻辑 Start／End 放置列、缩进和调宽边缘，文字／图标本身不镜像。

纵向视口位于固定表头下方，表头高度先从组件可用高度中扣除；表头不是节点，不占节点行的 ItemSource 或高度索引。横向复用 DataTable 的共享滚动方式，由外层一份水平 ScrollState／ScrollViewport 驱动表头和树行内容；纵向沿原 Tree 视口。每个轴只有一份状态，场景按真实内外路径登记，不为每个区域另建同步滚动状态。纵向滚动条按实际可见视口的逻辑 End 放在前景，不随整列横移到屏幕外；横向条位于组件底部，两轴在角部互相让出空间。

表头的真实焦点目标只参与外层水平显露，不推动纵向位置；正文／吸顶行及其单元格沿实际内外视口路径处理所需轴。行的纵向定位和阅读锚点复用内层 Tree 视口，水平滚动不改变吸顶祖先链。

列调宽复用 `tableColumnResize` 的指针、键盘、范围与取消规则，写入同一列宽状态后重新分配一次共享轨道。纯调宽／显隐不重建节点索引或排序结果；可变行高所依赖的列宽改变时，重新测量所需行并更新尺寸索引。列隐藏／删除使原焦点目标退出时，在正常动作或更新收尾中请求焦点回到同一节点的树行主目标；删除该节点时沿原祖先／邻近行回退，不在 render 或布局中改变焦点。

固定行高约束同一行全部单元格，内容遵循各列截断／裁剪策略；可变行高取该行所有可见列实测高度的最大值，再加统一的行留白。吸顶采用这个完整行高，不能只用树列文字高度。列显隐或宽度改变后，正文与吸顶同时使用新行高并保持阅读锚点。

第一版按行虚拟化，某行被选入视口／overscan／吸顶／活动项范围时才构造其可见列；隐藏列不构造。若有 W 个普通所需行、S 个吸顶祖先、P 个额外活动项和 C 个可见列，单元格数量按 O((W + S + P) × C) 增长。横向裁剪不宣称列虚拟化；同一个单元格随整行吸顶保留原实例。

## 8. 父节点保持可见（Sticky Scroll）

### 8.1 用户可见行为

当父行的自然位置滚出自己的顶部槽位，而其展开子树仍处于正文阅读位置时，该父行停留在视口上方。更深父行依次停在它下面，组成当前分支的祖先链；不是固定根节点，也不是选择节点的路径。

```text
滚动前                         已滚入 compiler/parser 深处
┌──────────────────────┐      ┌──────────────────────┐
│ ▾ scoop              │      │ ▾ scoop              │ ← 吸顶祖先
│   ▾ compiler         │      │   ▾ compiler         │
│     ▾ parser         │      │     ▾ parser         │
│       ast.scoop      │      ├──────────────────────┤
│       lexer.scoop    │      │       tokens.scoop   │ ← 正文继续滚动
│       ...            │      │       syntax.scoop   │
└──────────────────────┘      └──────────────────────┘
```

进入兄弟分支时，相应的内层父项被子树末端推离并替换；离开整棵根树时根吸顶也退出。回滚到父行自然位置时，它恢复普通放置，不出现两行相同内容。

配置为 `enabled`、`maxRows=7`、`maxHeightRatio=0.4`。同时服从行数和高度限制，按外层到内层保留能容纳的完整祖先行；不足一行时不吸顶。多列有表头时，比例基数使用扣除表头后的纵向视口高度，表头不计入 maxRows。极深路径暂不合并标题为另一个路径控件。可变高行按实际高度计算，不硬套固定 itemHeight。

多列固定整条祖先行，包含全部当前可见列，且与表头和正文严格对齐：

```text
名称                         类型       大小
─────────────────────────────────────────────
▾ workspace                  目录       —       ← 固定表头下的祖先行
  ▾ compiler                 目录       —
    ▾ parser                 目录       —
─────────────────────────────────────────────
        tokens.scoop         源文件     8 KB    ← 滚动正文
        syntax.scoop         源文件     21 KB
```

点击吸顶标题按当前树的选择规则处理，并显露该节点在树中的自然位置；箭头只展开／折叠，Checkbox 只勾选，行内按钮、右键菜单和拖放仍针对原节点。多列非交互单元格遵循同一整行选择／激活规则；其中的独立按钮或编辑器优先处理自己的输入。吸顶区接收滚轮与触摸时，纵向驱动原 Tree 视口，水平沿共享外层视口处理。

### 8.2 布局算法

1. 从当前 offset 对应的首个逻辑行开始，沿父引用取得外到内的候选路径。
2. 每加入一条吸顶祖先，就以新的吸顶区底边重新定位被它下面覆盖的首行，再决定下一层；不能只把最初首行的全部祖先机械复制过来。
3. 只有自然行顶已越过对应槽位、仍有展开后代占据该分支时才吸顶。末端位置由投影的 subtreeEnd 与尺寸前缀取得，不扫描后代 View。
4. 一条行的放置位置受“自然位置、吸顶槽位、所属子树末端减去行高”共同约束。抵达子树末端时向上推离；内层绘制不能盖住仍有效的外层祖先。
5. 应用行数／高度限制，选择正文范围、祖先及活动项的并集，每个条目每轮按现有规则测量和放置一次。可变行高的新测量可请求后续收敛帧，未变几何不能在两条路径间反复跳动。

所有位置、尺寸、吸顶顺序、正文裁剪区和滚动快照一起进入不可变 `TreeLayout`。scene 不读取另一轮试测修改的尺寸表；Accepted 后才更新可观察阅读位置、命中和语义几何。

### 8.3 一个行实例、共享滚动视口

吸顶行仍是原 ItemSource 中相同 key 的那个行实例，只改变这一次布局的放置与场景层次。自然行已进入吸顶位置时，不在原位置再画一份；自定义标题及各列单元格里的 State、编辑器、菜单锚点、焦点和 Checkbox 因此都保持同一归属。

正文先绘制，吸顶背景及外层祖先随后覆盖，滚动条沿既有前景顺序呈现。背景使用不透明主题表面，不能让后方文字穿透；阴影／分隔线只表示区域边界。正文的绘制与命中同时裁掉遮挡区，不能只在视觉上覆盖而仍点击后面的行。

现有 `children()`／`children(order)` 只提供一次完整呈现，不能让两组行分别进入正文和吸顶的裁剪／显露路径。为该实际消费者补拟议的 `SceneContext.item(key)`：仅用于 LazyElement 当前最终布局中已放置的条目，按显式 key 找到原布局结果，在调用处沿当前 clip、场景顺序及滚动路径呈现。它不构建、测量、重新放置条目，也不发起滚动。

逐项模式与原完整呈现模式互斥；同一布局中的已放置项须各呈现一次，重复或缺失按本轮场景正确性报告。`withState`／`withScrollReveal` 共用这一份呈现记录，Discarded 不发布候选几何。Tree 据此先呈现正文项，再呈现吸顶项；不需要把同一 key 挂到第二棵树。

Sticky 的高度不加入数据内容高度、不改变滚动条范围，也不动态写入 `ScrollPadding.top`。现有 ScrollPadding 会移动正文并扩大范围，拿它代替遮挡区会产生跳动。

正文沿 `withScrollReveal(viewport, bodyRect, ...)` 扣除顶部吸顶区；多列表头已经位于该纵向视口之外，不再次从 bodyRect 扣除。吸顶项使用它的实际呈现区域和所需滚动轴。按 key 定位、PageUp／PageDown、焦点及无障碍显露都使用未遮挡正文区域，防止导航目标藏在祖先下方。水平滚动时表头、正文与祖先沿外层视口共享同一 x 偏移。

KeepVisible 保存吸顶区下方第一个实际阅读行及项内偏移，几何变化时把新祖先高度与该 key 的阅读位置一起求解。用户的新滚动／定位意图优先，吸顶变化本身不生成额外的程序滚动意图。

## 9. 键盘、拖放与无障碍

### 9.1 键盘

| 输入 | 默认动作 |
| --- | --- |
| Up／Down | 移到前／后一个可聚焦展开行，不改变展开或勾选 |
| Right | 折叠父项展开；已展开父项进入第一个可聚焦子项 |
| Left | 展开父项折叠；叶或折叠项返回最近可聚焦父项 |
| Home／End | 当前展开投影的首／末个可聚焦行 |
| PageUp／PageDown | 按扣除吸顶区后的正文高度移动，并显露目标 |
| Space | 有可用 Checkbox 时切换勾选，否则按选择策略切换选择 |
| Enter | 执行默认激活；目录父项按展开策略处理，叶项通知应用 |
| Primary／Shift 组合 | 按目录预设或多选策略切换单项、扩展连续范围 |
| 文字输入 | 用现有 Typeahead 查找已展开、可聚焦的下一匹配行 |

左右键按逻辑展开方向适配 RTL；Up／Down 不反转。树导航只处理行主目标尚未消费的键，不抢标题内部编辑器的光标、IME、Space 或快捷键。默认树只有一个 Tab 停靠点；需要行内交互时，F2 进入该行已有子目标，Escape 返回行主目标，具体焦点仍由原 FocusHandle／LazyFocus 完成。

多列缺省仍按节点整行选择，行主目标的左右键保留展开／折叠语义，不因为多列就切换为单元格选择。F2 进入当前行的首个可用单元格交互目标；行内 Tab／Shift+Tab 按可见列和真实子目标顺序移动，越过行边界退出行内交互并继续外层 Tab 顺序。Escape 在内部控件未消费时返回树行主目标。静态单元格通过无障碍表格导航和按地址显露提供访问，不给每个纯文字格子再造键盘输入目标。

表头排序按钮和调宽手柄保留自身的正常键盘及无障碍入口，其 Tab 顺序独立于正文唯一的树行入口；排序或调宽不改变节点选择。按 `(nodeKey, columnId)` 聚焦只接受该真实单元格内的可用目标，纯展示单元格可显露但不伪造聚焦成功。

### 9.2 拖放

本次默认拖动一节点及其整个子树，不因多选而隐式批量搬移。使用稳定 source key、target key 与 `TreeDropPosition.Before／Inside／After`；反馈区结合实际行高和缩进计算，After 指目标整棵子树之后的同级位置，不落进已展开后代中。

`allowDrop` 是纯落点判断。自己、自己的后代、已删除节点、明确禁用位置和无实际变化的同位移动不成为可提交落点。Inside 默认只用于分支，表示追加到该父项；Before／After 解析为目标父 key 与相邻同级 key，不将展开行号作为插入位置。未加载分支上的 Inside 可以交给业务按“追加”处理，不伪造未知子项的数值索引。应用负责更新数据或执行文件操作，控件不能先改一份内部数据再等业务拒绝。

同级排序生效时，Before／After 手动重排落点停用；合法 Inside 仍可改变父子归属，更新后的子项按当前排序排列。需要手动顺序时先由应用明确清除排序。列调宽手柄、排序表头和单元格独立控件不启动节点拖动；多列整行的落点仍以树列缩进和目标节点关系解释，不把其他列的 x 坐标当作层级意图。

原生拖放沿现有 `localData` 传递类型化的树内 payload，并使用节点文字作为默认 Text 表示；业务可明确提供实际文件／URL 表示。默认 Tree 只接受同一模型当前仍有效的树节点请求，不把外部文本猜成节点 key。这里的模型关联只用于解释移动对象和防止结构环，不引入来源授权或新原生数据格式。

悬停可展开父项后用现有 deadline 请求展开，离开／取消时撤销；仅启动对应分支的正常加载。边缘自动滚动复用原视口和活动拖放更新，吸顶区不冒充正文上边缘热区。每次更新沿最近 Accepted 几何重新解析位置；源替换、折叠或加载改变了落点时重新判断，不能提交旧索引。

吸顶行与普通行使用同一 key、回调和业务提交，Before／After 仍依据原节点的逻辑位置。自定义标题子控件先按正常输入规则处理，点 Checkbox 或展开箭头不启动整行拖动。跨树／跨窗口接入使用现有数据拖放合同，由应用明确提供数据和提交逻辑。

### 9.3 无障碍

需要为现有 Window 语义增加 Tree／TreeItem，并使 UI 的惰性集合允许 Tree 角色。数据描述提供 parent key、零基 hierarchyLevel、同级 index／count、expanded、selected、checked／mixed、busy 和真实可执行动作；同级数量不能使用展开后全列表的 count 冒充。

显式列模式发布树形表格语义，复用现有 `SemanticGrid`、行、单元格、列头及按行列 key 的 Realize／Reveal／Focus，并补齐树层级能力。逻辑展开关系和整行选择归属于节点行，单元格通过列 ID 关联表头，树列提供层级展示与原节点动作；不会每增加一列就增加一个可选择树节点。当前可见列决定显示列位置／数量，隐藏列退出阅读树，列 ID 保持其稳定身份。原生 provider 按平台的层级表格能力投影，不以数个独立 List 代替。

表头名称、排序方向和单元格文字有明确的数据级描述，查询不得调用 cell 工厂；有名称而缺少单元格文字描述时保留未知状态。折叠、过滤和排序后的逻辑行位置与当前投影一致，同级位置仍按对应父项的呈现子项计算。纯数据查询不构建整行的所有单元格，更不创建全表 View。

离屏逻辑节点的查询只读数据；选择、展开、勾选通过原模型动作，Realize／Reveal／Focus 复用原惰性挂载与 Accepted 路径。未知远程子项不公布虚假的总数，不因辅助技术枚举而加载网络数据。叶节点没有 expanded 动作。

吸顶不产生额外 TreeItem、第二组行／单元格、第二个 Checkbox 或额外 Tab 目标；逻辑父子及阅读顺序保持，更新的只是同一个节点及其单元格的实际几何。可变行高、部分推离和正文遮挡均反映到 native 可见区域。公共语义沿原平台 provider 投影；本次验证本地 macOS 的单列／多列角色、层级与表头映射，不以已有 List 语义通过代替 Tree 验收。

## 10. 外观与动效

默认外观消费现有 Theme、字体、密度、对比度与减少动画偏好。Tree 只增加实际需要的缩进、行内槽位、连接线、选择／命中高亮和吸顶分隔样式；应用可覆盖标题、图标、展开器与加载器，不复制一套 Ant 主题。

连接线来自同一树投影，处理末尾兄弟、叶节点、过滤后的路径和 RTL。固定行高标题默认单行省略；可变行高支持多行或自定义内容，吸顶保留原行的实际高度。

展开收起、箭头、选择及 hover 使用已有动画／Presence。结构过渡只作用于实际可见部分，不为了动效创建整棵子树；逻辑上已经关闭的内容退出键盘和语义操作，退出画面不保留可点击副本。减少动画立即收束到最终布局。吸顶跟随真实滚动位置，不另做追赶动画造成命中滞后。

## 11. 实施顺序与验收

| 批次 | 交付内容 | 必要验收 |
| --- | --- | --- |
| T1 | 数据／状态、展开投影、基础行与虚拟视口、多列定义／共享列宽／表头、单选／键盘、语义基本链路 | 多根、节点／列身份错误、受控拒绝、真实焦点、固定／可变行高、按节点／单元格显露、列对齐 |
| T2 | 按条目场景呈现、父节点整行吸顶、正文显露、阅读锚点、同实例行放置 | 单项一次呈现及失败帧、多层／兄弟／根切换、推离、表头下的 7 行／40% 限制、多列可变行高、RTL／共享水平滚动、交互实例不重复 |
| T3 | 级联／独立勾选、多选／目录预设、查找／过滤、列调宽／显隐与同级排序 | 禁用传播边界、Mixed、Shift 反向范围、过滤与隐藏选择、同级稳定排序、调宽取消、隐藏列焦点回退 |
| T4 | 异步加载、默认／受控展开组合、拖放 | 去重、失败重试、折叠中返回、删除／换数据集的旧结果、新子项按当前排序接入、排序与落点规则、悬停展开、吸顶行拖放 |
| T5 | 自定义行／单元格与外观、动效、本地无障碍、示例与编程材料 | 单列／多列完整交互组合、原生层级表格与行内输入、静止停帧、实际发布消费者 |

重点组合用例：

1. 勾选父项 → 折叠 → 异步返回子项 → 重新展开，核对继承、禁用边界和没有额外加载。
2. 深层分支吸顶 → 吸顶父项折叠 → 焦点回到存活父项，正文锚点和滚动范围不乱跳。
3. 搜索命中离屏后代 → 临时展开路径 → 显露到吸顶区下方 → 清空查询恢复用户展开状态。
4. 目录多选 → Shift 反向缩短 → 折叠／过滤／重新排序，范围依据当前投影和稳定 key。
5. 自定义标题持有输入框／菜单 → 行在普通与吸顶位置转换，构造、挂载、焦点和事件计数都只有一份。
6. 拖动到吸顶父项 → 悬停展开并加载 → 滚动／插入改变落点 → Drop 按最新合法位置提交一次。
7. 10 万个已加载节点，分别折叠大部及全部展开，记录索引成本；固定列配置下，滚动时挂载和 build 数仅随视口、吸顶和活动项变化，单元格数量按可见列数增长。
8. 可变行高、零视口、很小的视口、高 DPI、极深路径、数据替换及 Discarded 帧，不出现永久振荡、旧命中或重复语义项。
9. 多列表头 → 深层祖先整行吸顶 → 水平滚动／调宽／切换 RTL，三处列边界始终对齐，纵向滚动条保持在真实视口边缘；表头不计入吸顶行数，高度比例按实际纵向视口计算。
10. 焦点位于非树列的输入框 → 隐藏该列／替换列定义 → 回到同节点的树行主目标，展开、勾选、选择和相同 ID 的有效列状态保持。
11. 按大小排序 → 同值兄弟保持来源顺序 → 异步加载新子项 → Shift 范围选择和 Inside 拖放，父子关系不被全局排序打散，Before／After 重排落点不在排序中生效。
12. 非树列多行内容决定行高 → 该行吸顶 → 调宽或隐藏此列，整行采用同一最大高度，阅读锚点保持，自定义单元格不重复构造或收到两次事件。
13. 辅助技术查询离屏行／单元格、表头、同级位置与排序方向，再执行显露／勾选／展开；查询不触发 View 构建或远程加载，动作只命中原节点，单列和多列均按本地实际 provider 验证。

纯模型、错误路径和公开消费者行为使用所属 Cone 的 `scoop.test`；必要的真实窗口、输入与 native accessibility 使用现有 UI 测试方式。仅编译诊断、链接或必须外部进程控制的合同进入 fixture。普通验证使用 release 和共享缓存，不复制 sysroot，也不以 GC stress 代替 UI 行为验收。
