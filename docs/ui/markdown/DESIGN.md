# Markdown 编辑器设计

日期：2026-11-15。状态：按核心功能与扩展框架的范围继续实施，进度见[文档库实施记录](../../markdown/PROGRESS.md)。独立文档模型、解析、结构化处理与生成见 [`scoop.markdown` 设计](../../markdown/DESIGN.md)。本文定义 `scoop.ui.markdown`；已交付接口以[规范](../../specs/SCOOP-UI-MARKDOWN-SPEC.md)和库声明为准，后续设计随相应批次落实。

## 1. 目标与已确认取舍

提供一个可嵌入 Scoop 应用的 Markdown 编辑组件，重点是 Typora 自带的 Markdown 编辑与展示能力，支持源码、所见即所得和 side-by-side 三种模式。目标是核心编辑体验，不要求完整复刻 Typora 或逐个内置其额外语法。大文档能力以本仓库真实 Markdown 为基线，并验证更大的组合文档。

分层与扩展接入遵循以下要求：

- 文档本身属于独立 `scoop.markdown` Cone；无 UI 程序也能解析、处理和生成 Markdown。
- 扩展通过 Inline／Block 接入。Mermaid 是“扩展图像块”的参考用法：源码可编辑，外部工具生成图片，编辑器嵌入展示；具体 renderer 的增加与完善不构成本轮前置。

普通 Markdown 使用 Scoop 原生自绘和文本排版。扩展按 Inline／Block 两种形态接入；文档层统一识别片段，编辑器在光标进入时原位展开源码、离开后恢复展示。公式、自定义指令等扩展保存原始源码，不要求提供图形化语义编辑，也不将任意 UI 组件嵌入作为本设计的交付要求。

编辑组件提供文档变化、保存请求、资源解析和打开链接等接入点，宿主应用组合文件面板、持久化和工作区。Typora 的应用级文件管理、云同步、PDF 排版等不成为本组件的交付前置。

### 1.1 本轮交付边界

本轮范围限定为核心 Markdown 能力和可实际接入的扩展框架。下表是实施与验收依据，后文的具体扩展示例用于说明抽象，不自动成为新增功能清单。

| 范围 | 本轮交付 |
| --- | --- |
| 独立文档核心 | CommonMark 与常用 GFM 结构、无损源码保存、结构查询与修改、Markdown 生成、快照与差量；无 UI 程序可以独立使用 |
| 编辑与展示核心 | 源码／所见即所得／双栏；段落与文字格式、列表与任务项、链接与图片、代码、表格；选区、IME、剪贴板、撤销／重做、查找与导航，以及大文档布局和输入 |
| 扩展框架 | 标准节点匹配与新增语法接入、统一扩展片段与索引、来源映射和可选内容处理、Inline／Block 展示、光标触发的源码编辑、异步结果与资源生命周期；缺少或失败的适配可回退到源码 |

框架以标准图片／代码和少量已有行内、指令适配验证两种识别入口、两种展示形态及源码编辑闭环，不以支持多少种 Typora 扩展衡量完成度。具体语法、渲染器和第三方兼容可以后续独立增加；本轮不追加完整公式能力、Mermaid 图种、mdBook 命令集、上下标、高亮、emoji 简码或 HTML 展示。打字机／专注模式等非必要辅助功能也不阻塞本轮。

已完成的公式、Mermaid、mdBook、脚注／目录、front matter 和 HTML 导入能力保留，作为现有能力或接入参考。框架调整需要时做必要适配与回归，不继续扩张各自兼容范围。HTML 导入不再增加新格式或转换功能；保存原始 HTML 与未知语法的源码仍属于文档无损保留能力。

## 2. 三种模式的精确行为

| 模式 | 编辑面 | 展示和交互 |
| --- | --- | --- |
| `Source` | Markdown 原始源码 | 语法高亮、行号、缩进、围栏／括号辅助、查找替换、折叠和行定位 |
| `Wysiwyg` | 普通 Markdown 的语义内容 | 标题、文字样式、列表、任务项、链接、表格等直接编辑；必要标记在当前位置按需显露 |
| `SideBySide` | 左侧源码，右侧富文本 | 两侧均可编辑，右侧也可配置为只读预览；共享文档与撤销历史，焦点决定当前输入面 |

这里的 Wysiwyg 必须支持普通 Markdown 的直接编辑，不能只做“点哪里都弹出整个源码框”的阅读器。扩展、复杂原始 HTML 和暂时无法确定结构的片段使用明确的局部源码编辑面。

三种模式都绑定同一个 `MarkdownEditorState` 和 `MarkdownDocument`。模式切换不是文件转换，不经 HTML 往返，不生成新文档、不重置历史，也不重排 Markdown。当前选区以源码位置保存，各视图保存自己的滚动位置、折叠状态和视觉期望列。

源码标记与代码颜色从后台原语法派生，行号只排版可见物理行。源码辅助独立配置缩进、括号配对和已识别围栏的补全；一次辅助与原输入共用同一事务，保留原生组合、显式替换和粘贴的字面含义。无 UI 的源码输入片段仍提供原样输入，具体入口及边界见[编辑器规范 §5.2](../../specs/SCOOP-UI-MARKDOWN-SPEC.md#52-源码标记行号与输入辅助)。

双栏采用一个活动逻辑选区，另一栏可以显示对应范围；焦点转移后继续从对应源码位置编辑。两栏宽度不同，布局缓存各自持有；源文本、解析和外部渲染结果按实际输入共享。

## 3. 对标能力与语法范围

使用明确的 Markdown profile 固定行为。本轮核心以 CommonMark 和常用 GFM 能力为基础，包含表格、任务列表、删除线与自动链接；具体行为按实际兼容测试确认，不能把 parser 的单个 `ENABLE_GFM` 开关当作完整 GFM 实现。具体扩展经应用注册接入，已有能力与本轮新增要求按 §1.1 区分。

### 3.1 核心编辑能力

| 能力 | 编辑行为 | 写回规则 |
| --- | --- | --- |
| 段落、H1–H6、引用、分隔线 | 直接输入；块类型切换；软／硬换行 | 局部源码事务，保留其余空白和标记 |
| 粗体、斜体、删除线、行内代码 | 快捷键、工具栏、选区格式化、继续当前样式输入 | 处理嵌套、边界与转义，不重新序列化全文 |
| 有序／无序／任务列表 | Enter 续项、空项退出、Tab／Shift-Tab 缩进、任务勾选 | 使用列表容器规则；重编号是明确操作 |
| 代码块 | 语言选择、源码编辑、语法高亮、复制 | 正文原样保存，围栏长度避免与内容冲突 |
| 表格 | 单元格导航与编辑、增删行列、列对齐、粘贴 TSV | 保留未编辑单元格；显式格式化才对齐源码空白 |
| 链接、图片与内部锚点 | 编辑目标／标题、插入、预览、定位 | 支持行内与引用式链接；图片位置由宿主 resolver 解释 |
| 文档大纲与定位 | 根据标题导航、折叠与跳转 | 大纲从文档派生，不插入目录指令或改写正文 |

普通编辑还包括跨块选择、全选、复制／剪切／粘贴、撤销／重做、拖选自动滚动、全文查找替换、跳转行、缩放和深浅主题。应用可选择展示哪些工具栏和面板。

复制区分“复制所见文字”和“复制 Markdown”；后者导出可独立解析的所选 Markdown 片段。生成内容复制所见文字时使用其展开内容，复制 Markdown 时保留对应指令。源码模式粘贴原始文本；富文本模式优先采用可识别的 Markdown／富文本剪贴板数据，再回退普通文字，整次粘贴只有一个历史项。已完成的 HTML 导入维持现有转换范围，不执行其中脚本，不新增转换能力。

表格对 TSV 的粘贴、链接自动识别、粘贴为纯文本与自动格式动作需要独立命令，不能靠内容猜测破坏用户明确的源码输入。插入或粘贴图片由宿主选择保存／上传位置，成功取得 URI 后再提交 Markdown 修改。

### 3.2 扩展方向与已有辅助能力

以下说明扩展框架需要承载的内容与写回规则。已有实现按当前范围保留，尚未实现的具体能力留待后续，不作为本轮逐项交付要求。

| 能力 | 接入与编辑方式 | 写回规则 |
| --- | --- | --- |
| 脚注与目录指令 | 复用已有引用、定义与 TOC 派生展示；后续语法按需增加 | 定义保留在源码中；目录内容不自动替换指令 |
| YAML front matter | 独立源码区编辑，可折叠 | 保留内容和定界符，不因预览改写配置 |
| 数学公式 | 行内／块级源码编辑，公式结果展示 | 保留 TeX 与定界符，显示结果不参与写回 |
| Mermaid | 围栏源码编辑，图像块展示 | 保存原始 Mermaid fence，不替换成生成图片链接 |
| 自定义模板／指令 | 源码编辑，处理后片段或图片展示 | 原指令保留；生成内容只读并映射回来源 |
| HTML／额外 Typora 语法 | 通过行内或块展示接口接入；扩展内容使用局部源码编辑，库不逐个提供内置实现 | 保留原始标签、参数和指令；缺少适配时仍可源码编辑与保存 |

## 4. 与现有 UI 的衔接

### 4.1 可以直接复用的能力

- [`scoop.graphics.text`](../../specs/SCOOP-GRAPHICS-TEXT-SPEC.md) 的 StyledText、Paragraph／TextLayout、Unicode 导航、bidi、命中、选区矩形与行内对象。
- [`scoop.ui`](../../specs/SCOOP-UI-SPEC.md) 的 Element／LazyElement、ScrollState、焦点、快捷键、帧提交、任务归属与资源生命周期。
- `scoop.ui.component` 的滚动、可调分栏、按钮、菜单、弹层、工具提示和表单控件；字体与颜色消费现有主题体系。
- [`scoop.window`](../../specs/SCOOP-WINDOW-SPEC.md) 的 TextInputBatch、平台编辑命令、剪贴板、输入连接和候选窗合同。

### 4.2 不能直接当作整篇编辑器的现有实现

当前 `TextEditorState` 保存 `TextInputState.surroundingText: String`；`TextEditHost` 把完整投影结果交给一个 Paragraph。现有 `TextProjection` 主要表达纯文本区间替换，并不提供 Markdown 块树、嵌套表格／列表和跨块编辑。

因此不把 MarkdownEditor 实现为一个巨大的 Textarea，也不为每个段落建立独立文档和撤销栈。新增的 `MarkdownEditHost` 管理文档级输入、可见块和源码映射，复用底层公开的文本／输入能力。确有两个消费者共用的导航或输入代码再提取，不为此重写整个 UI 框架。

控件与 document 之间以差量通知衔接：`onChanged(change)` 提供 revision 与变化范围，不在每次输入时发送完整 Markdown String。文档的异步解析完成只更新派生状态，不再发一次正文修改通知。

## 5. 编辑、投影与原生输入

### 5.1 编辑状态与统一事务

`MarkdownEditorState` 持有 document、当前逻辑选区、一个撤销／重做栈和 composition；视图状态持有模式、滚动、折叠和布局。普通输入、格式命令、表格操作、任务勾选、批量替换和扩展源码编辑最终调用相同的 document 事务。

历史保存文本差量和前后选区，不按键存全文。连续相邻键入／删除按编辑类型合并；粘贴、格式命令、模式／焦点切换及跨块操作结束合并。一段 IME 组合最终形成一次历史操作，临时 preedit 不逐次入栈。

组合期间保持正在编辑区域的源码和显示映射稳定，延后会改变该区域结构的自动转换。取消恢复组合前基线；显式模式切换先按现有编辑状态合同接受当前组合文本一次，再转换视图。原生失焦／取消继续沿 window 的既有规则，不能重复插入已提交内容。

保存请求同样先结束活动组合并固定一个源 snapshot，由宿主写出；写入成功只标记该 revision 已保存，期间的新输入仍保持未保存状态。外部程序化修改经过 document 的内容通知更新当前视图和位置；整体重新载入明确重置历史，不伪装成一次普通键入。

### 5.2 SourceMap 是必要模型

每个已布局块保存源文本与显示文本之间的映射，覆盖普通文字、隐藏标记、实体／转义、代码规范化、行内对象和生成内容。示例：

```text
源码：  **A &amp; B**
显示：  A & B
```

这里不能用“减去四个星号”换算所有光标位置。`&amp;` 与 `&` 的长度不同，隐藏标记两侧也有不同的插入意图。

映射区分普通一对一文字、折叠／替换片段和带来源的生成片段。隐藏定界符处保留向内／向外的端点偏向；点击强调内容末尾默认继续当前样式，显式越过格式边界或切换样式后才在外部输入。把编辑焦点交给富文本且定位到不可见标记时，在原位置显露相应片段。双栏中只有左侧源码在编辑时，右侧继续展示结果，不因镜像选区自动展开源码。

渲染中的公式和图片是原子对象，native caret 只有对象前后的位置。宿主将键盘向对象内部移动、点击放置光标等进入意图映射到扩展源码，再按 §8.2 原位展开；不能仅等待不存在的“图像内部 native 字符位置”。对象在 TextLayout 的规范化文本中使用真实 U+FFFC 单元，遵守 UTF-8 三字节及 InlineKey 合同，不按“一字节图片”计数。

### 5.3 结构化编辑的具体语义

- 在 `**word**` 中编辑文字只替换正文；对范围切换粗体才改变相应分隔符。
- 在任务列表中按 Enter 创建下一项；空项 Enter 退出当前层级。勾选只修改对应任务标记。
- 在列表开头 Backspace 先按容器规则退出／合并，不能吞掉前一块的代码围栏或引用定义。
- 普通段落 Enter 分段，Shift-Enter 插入当前 profile 的硬换行；代码块 Enter 保留代码语义。
- 表格 Tab／Shift-Tab 移动单元格，末格 Tab 可新增行；输入需要的转义由结构操作负责。跨单元格和跨块删除作为一个事务处理。
- 自动输入转换可立即撤销；反斜杠转义和明确的源码编辑不触发富文本快捷转换。

格式化、跨块删除和粘贴产生的源码差量由文档层实现并测试。UI 只负责把用户意图与当前 selection 转成这些操作。

粗体、斜体与删除线通过 `MarkdownRichInput.setStyle` 作用于非空跨块选区；折叠光标只保存后续键入的显式样式，实际输入时与文字合为同一事务。设置样式先接受组合，移动选区或外部修改后清除覆盖；组合取消保留待输入样式。`MarkdownRichHost` 与 `MarkdownEditorViewState` 提供 setStyle／toggleStyle 和可追踪的 styleState；可选 `markdownFormattingToolbar` 使用同一命令并返回富文本焦点。Primary-B／I／Shift-X 分别对应这三种样式，Mixed 切为全部启用；源码模式、只读和未挂载时禁用。行内代码使用独立的 setCode／toggleCode／codeState 与 Primary-E，避免把代码规范化混入普通格式标记；后续输入显式进入或退出代码模式，保留相应的换行与组合选区语义。

普通复制／剪切同时提供所见 text/plain 与语义 text/markdown，原指令的生成显示不会取代被复制的源码。富文本粘贴依次选择 Markdown、HTML 与纯文本；HTML 在独立文档 Cone 中按明确范围转换，纯文本保持字面含义。源码面默认直接插入 Markdown／普通文本。MarkdownClipboardCommand 的显式纯文本、Markdown、HTML 和 TSV 命令供 Host／ViewState 的菜单入口使用；PasteHtml 在源码面也可显式插入转换结果。一次粘贴复用 MarkdownFragmentEdit.after 并进入单一历史项，详见编辑器规范及[文档规范 §7.1](../../specs/SCOOP-MARKDOWN-SPEC.md#71-html-导入)。

块操作通过 `MarkdownBlockCommand`、RichHost／viewState 的 `blockState`／`executeBlock` 及可选 `markdownBlockToolbar` 接入。Block、List、Table 菜单覆盖段落／H1–H6、引用层级、列表类型与条目层级、代码块、分隔线、表格插入和行列／对齐；Primary-0／1…6 切换段落／标题。状态只读取已有结构，执行才解析必要的当前区域。连续同级块包装复用文档 Cone 的前缀事务，标题转换保留相邻块；空表格单元格使用真实源边界定位，删除后选择相邻有效单元格，禁止删除表头或最后一列。菜单关闭后恢复输入，代码转换直接打开局部源码面；所有操作共用当前选区、组合和撤销。

### 5.4 输入片段与全文文档分开

现有 window 发布入口会复制完整 `surroundingText`。Markdown 宿主向原生连接提供当前输入片段的快照与映射，覆盖活动选区、marked range 和必要上下文；全局导航、跨块选区和历史仍由文档级宿主处理。

源码视图的片段是对应源码；富文本视图的片段是当前可编辑投影，native 操作先在该临时快照上按顺序解释，再映射为源码事务。这份快照不是另一个可保存的正文，也没有独立历史。

工具栏的链接／图片面板由 beginTarget 取得当前快照与选区对应的 MarkdownTargetDraft，公开字段可供应用自建面板使用。applyTarget／removeTarget 验证草稿仍对应当前文档和选择，作为一次普通源事务发布。未修改的链接文字保留样式，折叠光标编辑已有目标；图片 URI 由宿主提供，引用形式修改仅作用于当前使用点。面板取得原生输入焦点，关闭后恢复富文本，跨块选择不生成跨结构链接。

富文本原生输入统一消费文档 Cone 的 MarkdownTextContent；单段借用 MarkdownInlineContent，多块选择使用 MarkdownRegion 的源码顺序映射。格式、图片和扩展保留各自源范围，块分隔不按固定偏移估算。准备结果的 insertedRange 用于组合文字和相对选区；取消恢复完整源码上下文，发布直接使用同一准备快照。结构变化以局部行集合立即显示，即使此时没有单段覆盖层也保留块投影。

片段坐标与源坐标明确区分。输入连接的 baseRevision／origin、UTF-16 转换、确认顺序与过期批次拒绝沿现有 window 合同。需要移动片段边界时在组合之外重建连接并更新映射，不能每次按键重开 IME，也不能把超出已知片段的 native 范围静默截断。选区很大时允许快照覆盖必要范围，不以任意片段尺寸限制文档编辑能力。

document 的内容 revision 与 native 输入快照的 revision 分开：选择或 marked 状态变化可以更新输入快照，但不因此重新解析未变化的源文本。两者的对应关系随当前输入片段保存。

活动编辑区域在虚拟化过程中保持必要的布局和输入归属；滚动不能卸载尚在组合的区域。候选窗和 hit test 使用匹配当前文档／投影的已提交几何，不能把旧布局坐标套到新字节位置。

## 6. 双栏同步与文档导航

三模式组合入口为 `markdownEditor(viewState, controller, ...)`。`MarkdownEditorViewState` 借用 `MarkdownEditorState`，持有 `Source`／`Wysiwyg`／`SideBySide` 模式、活动栏、左右各自稳定的 `ScrollState`／`FocusHandle`、分栏比例、同步开关及 `rightReadOnly`。组合控件使用现有 `resizable` 和稳定栏 key；保留栏复用挂载，移除栏释放自己的原生资源，文档、解析器和宿主字体仍由调用方管理。同一个视图状态同时只能绑定一个组合控件，不同视图状态可以借用同一个编辑状态。

`rightReadOnly` 只作用于双栏右侧；整体只读配置作用于所有模式。模式未变化的设置不结束输入合并；实际模式切换接受当前 composition 一次并结束合并，不生成新的正文事务。显式 `requestFocus` 可以先于目标栏挂载，挂载后兑现；默认不会抢走应用焦点。显式 `showSource(range)` 仍可将共享选区定位到源码栏，在所见即所得模式下转为双栏并聚焦源码；这是完整源码栏的导航入口。

富文本内部的扩展默认按 §8.2 原位编辑，无须切换模式。当前实现已有点击打开 `MarkdownSourceRegion` 限定源码面的能力，复用源码宿主、行虚拟化和共享历史；新的设计在此基础上增加光标自动进入／离开和 Inline 原位投影。围栏、定界符与指令保留完整，尚未闭合的语法不关闭活动源码面。显式编辑命令与可选的 Done／Escape 沿同一状态转换，宿主仍可通过 onSource 提供其他源码展示入口。

组合控件只注册一次正文变化回调。滚动同步等待发起栏的匹配请求帧被接受，再记录顶部命中的源码锚点及行内高度比例，向另一栏发起一次布局定位；自身镜像请求与布局高度修正不反向驱动同步。未完成解析的目标栏保留映射后的源码锚点，等待当前 revision 的布局；丢弃帧不能完成同步或覆盖已接受的几何。进入双栏或重新打开同步时，以活动栏为起点对齐一次。

滚动同步使用源码锚点：记录顶部可见块内的源位置及其相对视口位置，再在另一栏求对应位置。长代码块映射到行，普通段落映射到其排版行，图片／公式映射到整个源块与块内比例。

不采用两个滚动条的百分比联动。图片高度、段落折行和表格尺寸不同，百分比不能表示同一个阅读位置。同步以当前主动滚动栏为驱动，镜像调整不反向触发；支持关闭同步。

外部图片完成、字体改变或窗口宽度变化时，使用滚动锚点修正高度，保持当前阅读段落的位置。没有对应细粒度映射的生成内容定位到所属指令，并明确显示其来源；不伪造精确行号。

大纲与折叠以同一文档索引工作。跳转到折叠或未挂载位置时先展开／实现所需范围，再进行布局和定位。

`MarkdownParsedDocument` 在工作线程建立 sourceNavigation／previewNavigation。`MarkdownNavigationController(viewState, parser)` 提供标题、内部锚点、行列跳转和最多 128 个位置的后退／前进；普通编辑映射已有历史，Reset 清空。选区方向和正文撤销保持独立，不为导航切换模式。`markdownOutline` 使用 VirtualList 显示原文标题，`markdownNavigationBar` 使用原生 line:column 字段及 Primary-L／Enter／Escape，调用方将同一 controller 传给 markdownEditor 的 navigation 参数。

[TOC] 按最终预览语法中的标题派生为只读目录行，包括扩展生成的标题；内部链接与脚注跳转沿同一来源映射返回原文。目录点击记录导航历史，源码入口保留原指令；后台解析待完成时不使用旧标题范围跳转。索引的 section 范围也供后续折叠实现使用。

全文查找由独立文档 Cone 的 `snapshot.search(query)` 执行，结果保存实际 snapshot 身份与源码 UTF-8 范围。UI 的 `MarkdownSearchController(viewState, executor, proxy)` 合并后台请求，仅发布仍匹配查询与文档的结果；选择、颜色与保存状态不重新扫描全文，隐藏后正文键入只废弃结果。`markdownSearchBar` 复用普通原生 Input，`markdownEditor(..., search)` 绑定 Primary-F／Alt-F／G 和可见范围高亮。查询、替换字段保持独立输入历史，结果定位保持字段焦点，经源码锚点滚动到目标，不隐式切换编辑模式。

搜索原始源码，包括标记、链接目标、代码及扩展指令；include 派生内容不进入原文搜索结果。大小写、整词和正则规则由文档 Cone 统一提供，正则替换支持捕获模板。可见行／单元格对匹配集合做二分查询，显示映射负责隐藏标记和原子内容的位置，零宽匹配画细线。替换先准备当前有效范围，再通过 editor 发布一次事务；全部替换只有一个撤销项，旧搜索范围不应用到变化后的正文。整体只读、活动栏只读或禁用时禁止替换，资源由实际宿主管理。

### 7.1 真实样本

| --- | ---: | ---: | ---: | ---: |
| `docs/specs/SCOOP-IMPL-SPEC.md` | 641,186 | 626.2 KiB | 2,342 | 2,711 |
| `docs/specs/SCOOP-SPEC.md` | 546,601 | 533.8 KiB | 3,960 | 1,564 |
| `docs/program-performance/GC-EVOLUTION.md` | 364,392 | 355.9 KiB | 2,144 | 1,028 |
| `docs/specs/SCOOP-RUNTIME-SPEC.md` | 252,347 | 246.4 KiB | 1,078 | 4,026 |

因此首期必须流畅处理 1 MiB 级混合文档，扩展验收到 5 MiB；另外用 20 MiB 文档观察增长趋势。语料包括中文长段落、宽表格、嵌套列表、代码块、公式和图像，不能仅用几万行短英文代替。

### 7.2 布局虚拟化

源 buffer 与行索引由 `scoop.markdown` 管理。渲染层维护块树及可见范围索引，只为视口、少量前后区域和必须保留的活动编辑区域建立布局与挂载。

- 源码视图按物理行／行组取片段，保留全局字节位置；高亮覆盖可见范围。
- 富文本视图按段落、标题、列表项、代码行组、表格行等单位布局，保留真实的引用／列表容器结构。
- 代码块可以按行虚拟化；表格按行虚拟化，但列宽是整个表格的布局输入，不能只看当前可见行后让列宽随滚动跳变。采用明确的列宽分配规则，用户可调整，超宽内容横向滚动。
- 用包含累计高度的平衡索引完成偏移到块的查找和局部高度更新；不在每次滚动时从第一个节点累加高度。
- 离屏内容先使用已知／估算高度，实际测量后通过同一滚动锚点修正。选择和复制使用 document 范围，不需要挂载被选中的全部块。
- 一处普通编辑只使相应块及确有依赖的容器失效。caret 闪烁、选区变化、颜色变化不重新解析 Markdown；不影响尺寸的颜色更新也不重排。

`LazyElement` 的稳定 key、pinned item 和已接受帧合同继续适用。文档级焦点不等于为每行创建一个输入框；布局结果独立持有本次排版，输入不读取另一次试测留下的最近布局。

### 7.3 解析调度与一致性

文本差量先发布，源码输入不等待整篇 Markdown 解析。后台消费不可变 snapshot，初版允许合并多次输入后全文解析；同时只保留正在运行的解析与最新待处理快照，不为每次按键排队一份完整任务。

普通文字编辑可在已有映射的活动内容内立即显示。可能改变结构的编辑使受影响范围进入局部源码显示，直到当前解析完成；其他确定未变的块继续复用。已激活的扩展源码区域还受 §8.2 的编辑状态约束，解析完成不能在光标仍在其中时强制恢复渲染。未闭合围栏、HTML、列表容器及定义变化允许影响文档尾部，不能假设所有修改只影响一行。

解析结果带源 revision。过期结果不覆盖当前结构，也不用于执行当前富文本命令；完成后继续处理最新快照。连续输入期间不反复启动后立即取消所有任务：当前任务可完成，最新任务合并等待，当前编辑区域有即时源码反馈，停止输入后在验收时限内收敛到最新解析。

需要当前语法结构的命令在取得匹配结果后执行；等待时保留用户意图和源锚点并给出必要反馈。若其目标已被随后编辑删除，明确取消该动作，不能静默使用旧 range。普通源码输入、选择和保存不等待 Markdown 语义树。

复用未变节点的布局时核对其实际内容、样式、宽度和资源版本，不因文档其他位置增加几个字节重建全部段落。全局引用、脚注编号、标题锚点、TOC 和扩展资源通过各自真实依赖失效。源片段 flatten、定义处理、代码高亮与外部工具都不在 render／measure／scene 中运行。

代码块的初版高亮采用 Prism 规则的平坦 PCRE2 词法实现，通过 `MarkdownCodeHighlighter` 接口替换；不引入外部语言服务或脚本引擎。后台以提供器身份、语言名和正文复用相邻快照的未变化代码块，原始与展开文档分别映射。源码物理行和预览代码行共享颜色范围，未知语言或提供器失败时完整显示原文。局部代码面用原生文本字段编辑完整 Language / info，通过文档 Cone 的 `setCodeInfo` 提交；Copy code 只复制正文，所有修改与撤销共用文档历史。

### 7.4 大块不能被块级虚拟化掩盖

压力项必须单独包含：十万行代码、数千行表格、超长无换行文本、一个很长的中英混合段落，以及大尺寸的扩展图像块。图像块可复用已有数据，验证布局与资源生命周期，不要求新增某种图表 renderer。

代码与表格可以按真实行拆分，普通段落则不能任意每几千字节切开后独立 shaping；那会改变 bidi、连字和断行结果。现有 SkParagraph 的完整逻辑段落成本仍与段长有关，视口虚拟化没有消除这个问题。

首期的 1／5 MiB 交互目标针对真实文档及相似块分布的放大语料；单个超长段落另外报告输入、换宽和排版延迟。A 批先测定现有排版的实际边界。如果长段排版超过交互目标，需要在 graphics.text 增补完整段落后台排版及已完成结果的明确所有权转移，并先更新对应规范；不能把当前要求 owner 线程的 Paragraph／TextLayout 直接传给任意工作线程。不能通过错误切段、截掉正文或悄悄关闭富文本来记为通过。

这项结果必须写进验收范围。设计不承诺所有尺寸和所有单段结构都具有恒定输入成本，也不以文档大小作为是否合法的门槛。

### 7.5 初始性能验收目标

以下为 release 构建、固定并记录设备／字体／视口条件下的待验证目标，不是现有测量结论。本轮按用户要求只验证本机 macOS aarch64；其他平台另行安排。

| 指标 | 1 MiB 混合文档 | 5 MiB 混合文档 |
| --- | --- | --- |
| 首个可编辑视口 | ≤ 500 ms | ≤ 1 s |
| 普通输入到对应正文／caret 可见的 P95 | ≤ 16 ms | ≤ 32 ms |
| 停止输入到当前结构预览收敛 | ≤ 200 ms | ≤ 500 ms |
| 稳态滚动 | 60 Hz 目标；报告帧时间分位数和掉帧 | 同左，工作量随可见块增长 |
| 局部编辑 | 无全文 String／历史复制，不重排全部块 | 同左 |

冷启动解析、首次打开文件与启用的扩展渲染分别计时。若本次验证调用外部图像工具，其冷启动和复杂图渲染单独报告，不计入文本键入时延；等待期间正文可编辑、可保存。核心验收不以逐个运行所有具体 renderer 为前提。

内存报告文档增量占用、撤销／快照保留、两栏布局、图像和外部工具占用，避免把 renderer 进程移出统计后声称内存很小。历史释放、快照退休和离屏图像淘汰都需要真实验证。这些是性能指标与普通缓存管理，不是文档合法性或跨阶段配额规则。

## 8. 行内与块扩展展示

### 8.1 两种展示合同

扩展展示分为 Inline 与 Block。该划分描述内容参与布局的方式；公式、代码、Mermaid、图片与自定义指令各自保留内容类型，同一种内容可以支持两种展示形态。

| 展示形态 | 布局合同 | 典型内容 |
| --- | --- | --- |
| Inline | 参加当前段落的断行与 bidi 排版；返回宽度、上升／下降高度或等价的尺寸与基线；遵守当前字号、颜色和 scale | 行内公式、行内图片、自定义嵌入元素 |
| Block | 独立参与文档布局；接收可用宽度和可见范围，报告高度及需要的水平滚动范围；支持离屏释放和高度变化后的锚点修正 | Mermaid、公式块、代码块、独占一块的图片 |

一个扩展包可以同时提供两种展示入口并共享解析与资源。行内公式与块公式使用同一份 TeX 数据和渲染适配，传入的布局模式不同；图片的形态由文档 profile 的上下文规则确定。独占段落的图片采用块布局时，源码仍是原有图片语法。

两种入口均消费文档层的 `MarkdownExtensionSpan`，按扩展名称与形态选择展示适配；共用原始源码范围、语义数据与参数、替代文字、加载／错误状态及生命周期合同。编辑器据片段索引判断进入和离开，适配不各自实现选区、caret、IME 或撤销。结果可按内容与实际配置共享，每次出现仍有独立的源码位置和编辑状态。

图像是两种展示形态都可采用的一种结果。Mermaid 与公式可由外部工具生成图片；普通图片可直接解码。代码块使用原生文本展示，保留语言、语法高亮、文本选择／复制、局部源码编辑及按行虚拟化，不要求转换成一张图片。块展示接口须保留现有文本布局的可见范围能力，不能把大型代码块当作必须一次完整布局的不可分割对象。

解析和内容处理仍属于独立 `scoop.markdown` Cone。标准节点匹配和新增语法识别统一输出片段，详见[文档设计 §6.1](../../markdown/DESIGN.md#61-按具体语法接入)；标准 `CodeBlock`／`Image` 保留原节点，UI 不再自行按语言或正则扫描源码以决定扩展边界。`MarkdownProcessor` 可返回带来源映射的派生 Markdown；`MarkdownExtensionLocation.Code` 只表示允许在代码正文识别指令的语法上下文。无 UI 程序不依赖展示适配。

`MarkdownParsedDocument.sourceExtensions`／`previewExtensions` 已分别提供原始与派生语法的索引，图片、代码与既有扩展投影消费识别结果。`MarkdownParseOptions.imageExtensions` 只选择已识别的扩展名称采用图像展示，Mermaid 的语言匹配由文档 profile 负责；`MarkdownImageKind.Extension(name)` 统一图像适配的名称。`MarkdownImageRenderer`／`MarkdownImageRequest.inlineContent`、行内对象与原生代码视图仍是两种展示合同的实现基础，统一公共展示入口和光标自动源码编辑继续实施，不另建通用组件或脚本插件框架。

后台工作只处理普通数据，不访问 View、Canvas、TextLayout 或 UI State。图像路径返回编码字节、逻辑尺寸、基线和替代文字，owner 线程按 graphics 合同创建与释放资源。原生文本路径沿既有 Paragraph／TextLayout 所有权合同。异步结果仅在实际内容、配置和资源依赖仍适用时发布；卸载后不更新已关闭组件。

### 8.2 源码与显示的交互

编辑器统一管理 `Rendered` 与 `SourceEditing` 两种交互状态。加载中、成功、失败或等待最新结果是另一维度：正在编辑源码时可以更新渲染缓存，但结果到达不能收起源码或打断输入。

| 事件 | 行为 |
| --- | --- |
| 活动、可编辑的富文本光标进入扩展源码范围，或执行显式编辑命令 | 进入 SourceEditing，按源位置展开完整语法；普通程序化定位与键盘／鼠标沿同一规则 |
| 光标离开活动源码区域，且没有未结束的输入法组合 | 回到 Rendered，以最新文档内容请求展示 |
| 显式完成／Escape，或输入焦点转交其他正文编辑面 | 按组合规则结束当前编辑，保留正确的源码位置，再恢复展示 |
| 只读视图、另一栏的镜像选区、跨多个片段的非空选择 | 保持展示；不因相交范围而批量展开源码 |

Inline 在当前段落中用可编辑源码替换该对象，前后文字继续参加同一段落的断行与排版，不弹出整段或整篇源码框。Block 在原块位置显示完整源码，保留容器上下文、行高亮和按行虚拟化。两者都通过已有输入宿主与源映射修改同一个 document，所有修改进入共享历史；展开／收起本身不改正文、不生成撤销项。原生代码展示仍可选择和复制，开始输入时按同一规则进入代码源码。

范围边界结合移动方向及向内／向外偏向判断。对图像等原子对象，键盘从一侧向内部移动或点击请求放置光标时，先把进入意图映射到源码；有精确源位置时保留它，否则按进入方向落到正文相应端点。拖选或选中整个对象不等于进入源码编辑。图像像素没有到 TeX 字符或 Mermaid 图元的精确反向映射，不能伪造该位置。状态转换基于输入意图和源码锚点，不根据展开后的新布局反复切换。

活动区域的两端使用随 `MarkdownChange` 推进的锚点。用户删除闭合符号、改掉语言名或暂时使图片语法失效时，仍保留当前源码区域和输入；不能只用旧节点 ID 或最新 parser 是否还能匹配决定其生存期。退出后按最新语法显示：仍是扩展则渲染，已变成普通 Markdown 则走普通投影。解析尚未完成时保留可定位的源码反馈，完整重载或外部整体删除沿现有输入取消规则释放失效区域。

组合输入期间不因光标／范围变化、重新解析或渲染完成退出源码编辑；组合提交或取消后再判断离开。Escape 在组合中先取消组合；无组合时可完成扩展编辑。显式完成而光标仍在范围内时，将它放到相应外侧边界并记录外向偏向，避免下一次位置检查立即重新进入。局部输入面、工具栏或输入法候选窗间的临时焦点转移不等于离开该逻辑编辑区域；实际模式切换仍沿 §5.1 接受组合一次的规则。

双栏左侧编辑源码时，右侧继续渲染扩展；只有焦点转交可编辑的右侧，才根据当前源码位置进入局部编辑。只读预览提供选择、复制和应用动作，不自动进入 SourceEditing。嵌套扩展以当前可见的最内层片段为编辑入口；外层已展开源码时，内部继续作为源码，不递归创建子编辑器。

源码修改立即发布 document 与历史，合并连续渲染请求。退出时若结果尚未就绪，可以保留上次成功结果并标明待更新／失败；没有可用结果时显示替代文字、源码回退与诊断。渲染失败不撤销输入，也不阻断其余文档。

结果仅在对应出现仍存在，且语义内容、renderer 配置、主题、宽度／scale 和实际资源依赖仍匹配时接收，包括引用式图片使用的目标定义。其他段落修改不使所有扩展失效。迟到结果不能覆盖新结果或编辑状态；展开、收起与图片真实高度到达都通过滚动锚点修正保持阅读位置。

源码、图片展示和导出分别处理：保存 `.md` 原样保留扩展源码；“导出图像”才输出图片；显式“替换为图片链接”才会改写文档。宿主可以持久化普通渲染缓存，但它不成为 Markdown 文件的新必需伴随格式。

### 8.3 Mermaid 图像适配参考

本节保留已有 Mermaid 图像适配作为 Block 接口的参考，不增加本轮的图种、语法兼容或 SVG 渲染要求。文档 profile 将标准 fenced CodeBlock 中语言为 `mermaid` 的节点匹配为 Block 扩展，完整围栏范围用于源码编辑，renderer 只消费 fence body 及实际配置。参考适配调用已配置的 `mermaid-cli`，把一个图的定义转换为 PNG，再返回上述结果：

```text
mmdc -i diagram.mmd -o diagram.png -b transparent
```

使用实际 argv／stdin 或临时输入文件传递源码，不把图内容拼入 shell 命令。应用选择工具路径、主题和配置，适配负责本次任务的临时文件与进程收尾。缺少工具或生成失败时展示明确诊断，源码仍能正常编辑和保存。

不调用 `mmdc -i whole-document.md -o rewritten-document.md` 作为显示实现：该路径会把原文 Mermaid 替换成图片引用，违反源文档合同。已有图像适配可用于框架的代表性验证，其他工具以后实现同一接口即可接入；测试普通编辑功能不逐项启动浏览器或重新生成所有图。

当前 [Skia SVG 规范](../../specs/SCOOP-GRAPHICS-SVG-SPEC.md)没有完整 CSS、marker、foreignObject 和 SVG 字体接入，解析成功也不等于完整呈现。因此不声称 Mermaid SVG 可直接正确显示。以后验证具体 SVG 输出范围后，可用原生 renderer 替换图像生成适配，文档、编辑命令和块交互保持同一合同。

Mermaid 图像中的文字与连线按一个原子图像处理，不提供逐图元选择和修改。扩展可以另提供打开链接／来源等明确动作，原图内容不会自动变成 UI 脚本。

### 8.4 公式

块公式复用图像块；行内公式复用其异步渲染与错误处理，但结果还必须返回真实 baseline／advance，作为 `graphics.text` 行内对象参加同一段落排版，不能用图片高度的一半估算文字基线。

公式用于验证 Inline 基线、Block 布局与可替换的异步 renderer。已有参考路径采用 MathJax：TeX 生成 SVG 后，经 resvg 等离屏 SVG 光栅器转换为 PNG，并带回排版度量；工具版本、font cache 和字体属于适配配置。本轮保留现有能力，不追加 TeX 语法、宏库或工具兼容。将来验证输出可正确通过 Skia SVG 后再选择省去转换；公式源码的保存始终不依赖 renderer。

公式的字号、颜色、display／inline 模式、宏定义和字体都是输入；宏或主题变化使真正依赖它们的公式失效。渲染失败保留 TeX，并能定位原公式。用户可以替换为其他公式工具，无须让文档层理解 PNG 或 GPU 资源。

## 9. 自定义指令与展示

语法／展开接口在 `scoop.markdown`，展示接口在 `scoop.ui.markdown`。用户可以只实现一个新指令的处理器，返回带源映射的 Markdown／代码文本片段，直接复用原生预览；需要生成图的扩展实现图像块 renderer。本轮完成这些通用接口并复用已有指令验证来源映射，新的模板命令或 mdBook 兼容能力以后独立加入。

例如 `{{#include example.rs:sample}}`：

1. 原文档保存指令和范围，用户可以在三种模式的源码编辑面修改它。
2. 无 UI processor 经宿主 resolver 读取文件并选取 anchor 内容。
3. 正文中的展开按真实 Markdown 上下文显示，代码块中的展开作为代码文本显示。
4. 展开内容默认只读；在可编辑富文本中把光标移入所属指令范围或显式“编辑指令”时，原位展开原指令源码；“打开来源”交给宿主打开实际文件。
5. 被包含文件改变时只使其消费者失效；删除／缺失／循环包含显示指令级诊断。

同一个结果可以多次出现，每次出现有独立的文档位置和选中状态，共享合适的只读资源。生成内容没有可靠细粒度来源映射时，定位和同步滚动只保证到所属指令，不承诺双向编辑展开内容。

自定义展示使用 §8 的 Inline／Block 两种合同；内容展开继续使用文档 Cone 的处理器。现有公式、Mermaid、图片、代码和 mdBook 提供实际消费者，其他 Typora 扩展按需由应用注册，不把内置每一种扩展作为编辑器交付条件。

## 10. 拟议使用方式

注册分为文档识别与 UI 展示两部分。以下仅表示依赖和匹配关系，不是已经提供的 DSL；其中 math、Mermaid 与 directive 是可选适配示例，不是本轮新增清单：

```text
MarkdownProfile
  Image node                         -> image   (Inline / standalone Block)
  Fenced CodeBlock, language=mermaid -> mermaid (Block)
  CodeBlock fallback                -> code    (Block)
  Inline math rule / block math rule -> math    (Inline / Block)
  Registered directive rules        -> named extension spans

scoop.markdown
  parse(snapshot, profile) -> syntax + extension index
  optional processor      -> derived content + source mappings

scoop.ui.markdown
  image   -> Inline / Block image presentation
  mermaid -> Block image presentation
  code    -> Block native text presentation
  math    -> Inline / Block formula presentation
  editor  -> caret activation + source editing + shared history
```

正式 API 随实现写入规范。应用可以只配置文档识别并在 headless 程序中使用，也可以为同一扩展名称增加或替换展示适配。没有 Mermaid renderer 时仍可解析、保留与编辑围栏，UI 提供代码源码回退及缺少 renderer 的状态；配置 renderer 后使用同一扩展片段更新展示，不要求重新选择一种文档格式。

`MarkdownEditor` 是独立复杂控件，由 `scoop.ui.markdown` 提供；普通 Input／Textarea 和基础 component Cone 不因此依赖 Markdown parser 或外部渲染工具。

只读阅读场景可复用 `MarkdownView`，消费相同 document／parsed snapshot、布局与扩展 renderer；它没有编辑历史或第二套 Markdown 解析实现。工具栏、大纲和源码预览面板是可组合部件，状态仍归同一个 editor。

## 11. 实施顺序与验收

### 11.1 分批交付

| 批次 | 交付 | 完成条件 |
| --- | --- | --- |
| A：文档与测量基础 | 独立 Cone、源码 buffer、解析、查询、差量、builder／输出、位置映射；真实语料和长段落测量 | headless 程序完成解析→修改→生成；无修改字节往返；明确现有排版的长段边界 |
| B：源码与双栏闭环 | 虚拟源码编辑、原生 Markdown 预览、共同历史、同步定位、图片与扩展图像块 | 仓库两份最大 spec 可编辑／保存；双栏切换无损；图片及图像结果沿统一接口展示 |
| C：普通 Markdown 富编辑 | 语义输入、标记、列表／引用、任务项、链接、代码、表格与跨块操作 | 右栏可编辑，三种模式交叉撤销；真实中文 IME、复制粘贴和格式命令通过 |
| D：扩展框架 | 标准节点与新增语法接入、统一片段索引、Inline／Block 展示、自动源码编辑、来源映射与异步资源合同 | 复用图片／代码、已有行内语法与自定义指令，验证两种入口、两种形态和编辑闭环；具体扩展数量不作为完成条件 |
| E：核心与框架的组合交付 | 大文档、异步资源、字体／主题、生命周期、本机验证和文档示例 | 核心能力与扩展框架达到声明的性能目标，公开限制有实测依据，规范／API／示例同步 |

大文档测量从 A 开始，B 起每批保留相关回归；不把全文 String 和单 Paragraph 实现一直留到最后再优化。A 中发现必须修改 graphics.text 的实际问题，先更新该规范与当前批次，再依赖新增能力。

实现已恢复，按完整大项验证后提交、推送并合并远端 main。标准节点路由、统一片段索引及既有投影接入完成后，继续补齐块解析接入点、统一展示合同、光标激活状态与 Inline 原位源码投影，再完成核心编辑剩余问题、必要组合与本机大文档验收。已有点击打开局部源码面和图像适配可复用，但不能据此将自动进入／离开或统一接口记为已完成。新的具体扩展在这一范围交付后独立安排。

### 11.2 必要测试

普通模型、命令和扩展行为放所属 Cone 测试；真实 window／IME、渲染和外部进程行为使用已有 native／进程验收方式。只有编译、ABI、链接和必须由外部进程控制的合同使用 fixture，不为每个语法重复全量编译缓存检查。本轮验证扩展的通用合同，复用少量已有适配；具体扩展的兼容测试随其后续交付增加，已有外部工具只在相应适配受到修改影响时做必要回归。

- 三模式不编辑往返逐字节一致；任一模式修改后另一模式立即反映同一内容，撤销／重做跨模式连续。
- 源码到显示映射覆盖中文、emoji ZWJ、组合字符、RTL、实体、转义、行内对象、折行及隐藏定界符两侧。
- IME 测试覆盖中文长句、预编辑更新、取消、模式／焦点切换、跨块选择替换、滚动出视口及过期 native 批次。
- 普通语法既测独立命令，也测嵌套列表中的代码／表格、引用式链接、任务项和跨块粘贴等必要组合。
- 扩展识别覆盖普通／引用式图片、多种合法围栏、转义和代码上下文、列表／引用中的扩展、多行块、未闭合输入及具体规则优先于回退；UI 与 headless 使用同一结果。
- Inline／Block 都覆盖键盘、点击和程序化光标进入／离开、向内／向外边界、完成后不立即重入；跨片段选择、只读、双栏镜像和嵌套不产生额外编辑面。
- 活动源码覆盖删除闭合符号、改写成普通 Markdown、组合更新／取消、撤销、外部删除和 Reset；迟到解析／渲染不得收起编辑区域或移动 caret。
- 图像／异步展示合同覆盖成功、失败、缺少适配或资源、迟到结果、删除与撤销、配置／scale 变化和卸载，可复用已有图像或 Mermaid 适配。
- Inline／Block 度量覆盖真实行内基线、字号与颜色、可用宽度、可见范围和高度变化后的锚点修正，可复用已有公式适配。
- 内容处理覆盖代码／Markdown 上下文、相对 URI、资源依赖与错误、生成内容只读和粗粒度来源映射，复用已有指令；不扩充 mdBook 命令与语法覆盖面。
- 性能同时测冷打开、连续键入、IME、选择／全选、查找替换、滚动、调整栏宽、主题切换与撤销；记录 parser、布局、图像和进程时间，不能只测 `apply()` 的耗时。
- 大文档中的扩展位置查询与激活不扫描或复制全文；大型代码源码仍按行虚拟化，Inline 展开保持段落正确排版，收起与异步高度修正保持滚动锚点。
- headless 示例和 UI 示例消费同一份文档库；不在 UI 中私藏另一套解析／输出语义。

无障碍接入沿 UI 的公共文本与虚拟化合同：文档范围不依赖已挂载块，图片／公式有替代文字，编辑动作进入同一事务。现有无障碍工作仍处设计阶段，平台 provider 的交付状态单独记录，不能把拟议接口当作已实现功能。

### 11.3 规范与材料

按实施批次更新 `SCOOP-MARKDOWN-SPEC.md` 和 `SCOOP-UI-MARKDOWN-SPEC.md`，分别规定 headless 与交互合同；只有真实需要增强 window／graphics.text 时才修改对应规范。普通 `TextEditorState` 的行为不因设计文档被隐式改变。

按[编程材料工作流](../../scoop-programming/UPDATE-WORKFLOW.md)交付 headless 处理示例、三模式编辑示例及扩展注册说明；复用已有代表性适配演示新增扩展如何接入，不要求另做一套扩展集。涉及外部工具的已有示例保留实际安装／配置说明；使用编辑器不自动下载工具，不把可选扩展写成所有环境默认可用。

已有纯 Scoop 实现的状态以实施记录为准；恢复后的新增工作受 §1.1 范围约束。原始实验日志放仓库外，验收文档只记录范围、结果与实际限制。
