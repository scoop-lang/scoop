# 原生 DataGrid 设计

设计日期：2026-11-20。状态：实施中；各批次实际进度见独立仓库的进度记录。功能参考 AG Grid 36.3.0；采用 Scoop 现有的声明式 UI、类型化数据、原生输入与无障碍接口，不承诺 AG Grid 的 JavaScript API 或配置兼容。

本文定义本阶段的范围、模型、交互、实施顺序与验收要求。文中的新类型、方法和目录均为拟议设计，不能作为当前已发布 API 使用。现有行为仍以 [UI 规范](../../specs/SCOOP-UI-SPEC.md)、[组件规范](../../specs/SCOOP-UI-COMPONENT-SPEC.md)、[UI 无障碍规范](../../specs/SCOOP-UI-ACCESSIBILITY-SPEC.md)为准；实施各批次时先把对应合同纳入所属 spec，再修改实现和调用方。

## 1. 目标与范围

### 1.1 本阶段交付

在独立仓库 `scoop-grid` 的 `scoop.grid` 库中增加 `DataGrid<Row>` 与 `dataGrid(state) { ... }`，用于宽表格、数据管理和分组分析。外观沿用现有主题，并提供表头、单元格、选择、冻结区与编辑状态的可配置样式。

| 功能族 | 本阶段范围 |
| --- | --- |
| 数据与列 | 稳定行列身份、类型化取值／格式化、普通与自定义单元格、显式列定义更新 |
| 查询 | 稳定多列排序、文本／数值／日期／布尔／集合筛选、组合条件、快速筛选、查找定位、分页 |
| 列与表头 | 调宽、显隐、重排、冻结、多级列分组、适应视口／内容的显式自动调宽、有限跨列显示 |
| 行与布局 | 行列双向虚拟化、固定／显式可变／指定列决定的自动行高、固定表头、顶部／底部固定行 |
| 导航与选择 | 二维键盘导航、单选／多选业务行、一个连续矩形单元格选区、按 key 定位与焦点显露 |
| 编辑与剪贴板 | 单元格编辑、解析／校验／业务提交、单格粘贴、矩形区域复制、编辑器内部正常文本操作 |
| 层级与分析 | 行分组、树数据、聚合、小计／总计、透视、主从详情 |
| 外部数据 | 应用提供的分页结果和按区间加载结果；平面与层级结果使用同一外部结果合同 |
| 配套操作 | 列／筛选工具面板、菜单、状态栏、加载／错误／空状态、CSV 导出、视图状态保存与恢复 |
| 平台与组合 | 现有主题、明暗、密度、RTL、中文 IME、原生无障碍和既有输入设备接入 |

分组、树数据、聚合、透视和主从详情均属于本阶段，按第 16 节的批次实施。批次顺序不是把这些功能再次排到本阶段之外。

### 1.2 明确排除

按本次需求排除以下六组功能：

1. 高频增量更新。
2. 多区域选择、填充柄、整行／批量编辑、跨单元格撤销。
3. 行拖动、跨行合并。
4. Sparkline、选区生成图表。
5. Excel／PDF 导出、打印。
6. 公式、用户自定义计算列。

上述排除项不建立公开空接口、预留插件或验收门槛。具体边界如下：

- 普通数据快照替换、分页返回和一次单元格提交仍然支持；不增加流式更新事务队列、固定周期合并或专门的高频增量索引。
- 本设计把一次粘贴改写多个单元格视为批量编辑，因此排除矩形粘贴、选区批量清空和向下填充。保留一个矩形的选择与复制，以及只修改当前单元格的粘贴。
- 编辑器内部的文本撤销／重做复用 `TextEditorState`。提交并关闭编辑会话后，不创建跨单元格历史，也不把一次表格编辑包装成应用级撤销框架。
- 列拖动保留，行拖动排除。表头分组和有限跨列显示保留，任何跨行显示合并均排除。
- 自定义单元格仍可组合普通 View；DataGrid 不新增图表专用列、迷你图协议或选区联动图表。
- 开发者的普通取值／格式化回调可以返回业务派生值；不提供终端用户创建计算列、输入表达式或维护公式依赖的能力。透视结果列与聚合列属于本阶段明确定义的数据分析结果。

### 1.3 适配原则

借鉴 AG Grid 的功能行为和组合经验；使用现有 `View`、`State`、`Binding`、`Element`、`LazyElement`、主题及 native accessibility。DOM、CSS selector、React／Angular／Vue 包装、JavaScript 字段反射、表达式求值、AG Studio 和 AI 配套生态不进入设计。

业务 IO、服务端查询执行、权限、持久化位置和网络任务由应用负责。DataGrid 提供具体查询描述、结果接入和操作回调，不增加 HTTP 客户端封装、数据库查询引擎、通用插件容器或编译器／runtime 专用能力。

AG Grid Community 源码为 MIT，Enterprise 为商业许可。参考公开文档设计功能；确需复用第三方实现时按具体包许可证处理，不复制 Enterprise 实现。普通库依赖按仓库规范确认维护状态，不为本设计预先增加依赖。

## 2. 当前基础与真实缺口

## 3. 分层与实现位置

| 层 | 职责 |
| --- | --- |
| 应用 | 不可变业务数据、类型化列配置、单格提交、异步请求、结果投递、状态持久化 |
| `scoop.grid` | DataGrid 模型、查询／结果、分组／树／聚合／透视、二维布局、选择与编辑协调、CSV 数据导出 |
| `scoop.ui` | 原挂载树、焦点请求、文本宿主、Portal、滚动与语义接入；仅按实际 DataGrid 消费者补必要公开接口 |
| `scoop.ui.style` 与主题 | 现有 token、状态、绘制；必要的新公共视觉参数随主题一起补齐 |
| `scoop.surface` / `scoop.window` | 原输入归属、Accepted 几何、IME、剪贴板与平台无障碍协议 |

新增实现放在相邻独立仓库 `../scoop-grid/src/`，公开包为 `scoop.grid`，作为普通 Cone 消费现有 UI 库的公开接口。底层公共接口的实际缺口在 Scoop 仓库独立分支修复、验证、提交、推送、开 PR 并合并；随后更新本地 main、合并回工作分支并更新工具链，再继续 Grid。按实际实现拆为列、模型／查询、层级／聚合、布局、导航、编辑、剪贴板／导出、语义等模块，不为每个功能增加 Cone 或运行期注册模块。

DataGrid 有自己的呈现与交互入口，不把现有 DataTable 当成一个不可见的内层网格再覆盖另一套单元格。列宽分配、稳定排序、滚动范围、extent 与文本编辑等已有算法优先复用公开接口；必要的共同能力在 Scoop 中提取为明确的公共接口，不复制私有实现，也不提前抽象只有一个消费者的框架。

`Table` 的有限呈现与 `DataTable` 的轻量查询用途继续成立；DataGrid 新模型不要求它们承担树、透视和单元格编辑协议。项目未发布，不增加旧版 AG Grid 或旧 Scoop API 的兼容层。

## 4. 数据、身份与状态

### 4.1 主要对象

以下是职责名称，具体公共签名随对应批次纳入 spec；各对象只有表中列出的实际用途。

| 拟议对象 | 职责与所有者 |
| --- | --- |
| `DataGridState<Row>` | 应用持有；数据／列快照、查询、列呈现状态、业务行选择、展开、固定行与单矩形选区 |
| `GridColumn<Row>` | 不同值类型列的共同操作接口；保存稳定身份与实际支持的列操作 |
| `GridQuery` | 排序、类型化筛选树、快速筛选、分组／透视配置、分页；不保存 View、闭包或网络对象 |
| `GridResult<Row>` | 已计算或外部提供的逻辑结果；按索引／key 访问行、列与必要聚合结果 |
| `DataGridHandle` | 绑定一个挂载；按地址显露／聚焦、开始／提交／取消当前单格编辑 |
| Grid 挂载内会话 | 当前编辑器、一次性定位请求、拖列／调宽／拖选过程；实际焦点仍来自 Surface |
| 应用 Job | 加载和远程保存的生命周期；完成后投递到 UI owner，才调用模型动作 |

模型只通过明确动作更新，例如 `replaceData`、`replaceColumns`、`setQuery`、`setColumnState`、`setSelected`、`setExpanded`、`restoreViewState`。构造和更新入口检查当前输入的类型／引用关系；render、measure、scene、draw 只读快照。未变数据复用查询和几何结果，不重复完整扫描验证。

列配置与用户状态分开：更新列时，相同列身份且操作含义保持的配置保留宽度／显隐等状态；删除列会清理其查询、选区与在途编辑引用。列值类型或编辑契约变化结束该列的旧编辑会话。应用更换数据集时显式重置视图，不能用相同显示标签推断身份延续。

### 4.2 稳定身份

- 业务行继续使用来源提供的显式 `ViewKey`；禁止 `Position`、重复 key 和当前页位置冒充记录身份。
- 用户列使用显式稳定 id。标签、格式化值、宽度和当前位置都不是列身份。
- 分组路径由有序的“分组列 id＋组值 key”构成；组值 key 是明确的普通数据键，与组标签分开。
- 透视结果列身份由透视维度及其值 key、度量列 id 和聚合操作构成，不把显示标题拼成列 id。
- 逻辑行键区分数据行、分组、汇总、详情及加载位置；逻辑列键区分用户列与透视结果列。使用具体 enum／struct，避免把两类身份混用。
- 到 `ViewKey` 的映射采用无歧义的内部编码；不使用可能碰撞的分隔符拼接、显示文字或按本次遍历分配的临时序号。

`CellAddress` 由逻辑行键和逻辑列键组成。排序、列拖动和冻结改变位置，保持存活单元格身份。异步加载占位位置没有业务 key；加载后替换为真实记录，不继承占位项的选择或编辑状态。

### 4.3 类型化列与异构值

列构造入口在编译期绑定 `Row` 与值类型 `T`，例如由 `gridColumn<Row, T>` 创建内部 `TypedGridColumn<Row, T>` 并实现共同的 `GridColumn<Row>` 操作接口。不同类型的列可存入同一列数组；取值、比较、解析、编辑和格式化仍在各自带 `T` 的实现中完成。

必要操作包括：

- 从 Row 取得值，并分别生成显示内容、复制／导出文字和无障碍描述。
- 比较两行的该列值，或把对应筛选条件编译为类型化行谓词。
- 提供可选的组值 key／标签、聚合定义和编辑器构造。
- 解析一个编辑输入、校验候选值，并向应用提交一次有类型的新值。

不把每个单元格装进 `Any`，不把所有原始值转换成字符串后排序，也不引入星投影／关联类型等 Scoop 不具备的语言机制。`Option<T>` 缺值、空字符串和解析失败分别表达；列明确缺值排序及筛选规则。

纯操作列可只提供 View，没有数据值，因此不会自动成为可筛选、聚合或导出的列。界面按列实际能力提供入口，不展示无效操作。自定义内容的内联按钮、菜单和编辑器使用真实控件，不为显示而另外建一套命中或输入模型。

### 4.4 查询与结果

`GridQuery` 保存普通数据：有序排序项、带列身份的筛选条件、AND／OR 条件树、快速筛选文字、分组／透视定义及分页。条件文字不作为 Scoop、JavaScript 或 SQL 执行。

查询字面量按文本、布尔、数值和日期等种类表达，接入时由所属列解析／检查一次并产生类型化执行操作。它只用于查询、保存和外部数据交付，不成为所有单元格的动态值容器。未知列、操作与列类型不匹配、重复排序维度及非法页大小在查询动作入口报告。

结果行采用不同的完整变体：Data 携带 Row 和业务 key，Group 携带路径／展开／数量，Total 携带聚合定位，Detail 携带父记录与内容入口，Loading／Failed 携带实际区间请求信息。不能用一组无关的可选字段加下游 unwrap 来猜测行种类。无数据的行不伪造 Row。

选择、调宽、显隐与普通焦点变化不重跑本地过滤／排序／聚合。数据或参与查询的列定义变化才重新计算受影响结果；本阶段允许普通快照重新计算，不承诺高频增量维护。

## 5. 列、冻结区与行高

### 5.1 列几何

沿用 Fixed／Auto／Fraction、最小／最大宽度与共享列宽结果。逻辑 Start／End 冻结随 RTL 解析；对外使用逻辑方向，物理坐标只在布局阶段计算。

Auto 的日常测量只使用表头和显式样本；“适应可见内容”是用户触发的独立操作，只测当前已呈现行和明确样本，并在操作结束后保存列宽。不会为了自动调宽挂载或读取整份外部数据。“适应视口”复用比例分配，遵守列宽限制；不在每次滚动时重新调宽。

列拖动改变呈现顺序，不改变列定义或排序优先级。分组表头保持逻辑树：组内叶列在该组内重排，整个组作为一个单位在同级重排；跨组成员变更由显式列定义更新完成。冻结可使一个表头组分成多个视觉片段，片段仍指向一个逻辑组，不能复制组的业务状态。

冻结 Start／End 区与中心区共享列宽。中心区的最小可用宽度是明确布局参数；新增冻结或扩大冻结列会挤掉中心区时，用户动作被夹取或拒绝并提供反馈，不暗中解冻其他列。窗口已经窄于可容纳宽度时，按 Start、End 的确定顺序裁剪冻结区域，中心可退化为零宽；列工具面板仍可解除冻结。零宽区域不发布可交互几何。

### 5.2 跨列显示与固定行

跨列只改变一个行内连续列区间的呈现。跨度必须位于同一冻结区域，不跨越隐藏列或非法边界；列状态变化后重算。跨列锚点即使在视口之外，所占区域进入视口时也必须参与挂载。键盘定位跳到锚点，语义发布真实 columnSpan。

被覆盖列的底层值仍按各列定义存在；复制与 CSV 按逻辑列逐格取值，不重复锚点的显示内容。自定义跨列显示在本阶段只读，单格编辑仅用于跨度为一的单元格。跨行合并不支持。

业务行固定按稳定 key 表达，沿 Top／Body／Bottom 的垂直顺序呈现为顶部、正文和底部区域。同一记录只挂载一次：固定行从正文呈现序列移出，分组／筛选／聚合仍基于同一记录，固定不改变其原始组关系或重复计入聚合。

固定业务行来自当前查询结果，可独立于当前分页显示；筛选不再匹配时暂不显示，删除时清理固定 key。固定顺序由固定状态指定，正文排序不改变它。全表或分组汇总使用专门的 Total 行，不能伪装成可编辑业务记录。

外部固定行必须由应用提供当前查询对应的记录；新查询尚未取得它们时保留固定配置，不显示旧查询记录。固定区域超过可用高度时按 Top、Bottom 的确定顺序裁剪，正文可退化为零高；解除固定与退出焦点的入口仍须可用。

### 5.3 行高

支持固定高度、应用提供的显式行高和由指定列决定的自动行高。默认沿现有表格尺寸采用固定行高 48、基础表头高 40 个逻辑单位；通过 Grid 样式和密度配置紧凑呈现，不把物理像素写死到布局算法。

自动行高列在可见行内始终参与测量，即使横向离屏。其余列继续虚拟化；不得声称“任意列决定高度”同时仍只测横向可见列。宽表格可选择固定／显式高度；详情行使用普通内容测量和现有可变 extent。

行高变化保持最近 Accepted 的阅读锚点与项内偏移，沿原 ScrollAdjustment 发布修正。调整列宽、字体、密度和展开详情都走同一条路径；被丢弃的测量结果不修改滚动状态。

## 6. 查询、层级与分析结果

### 6.1 平面数据与筛选

本地平面来源复用 `TableSource<Row>`，执行“筛选→稳定多列排序→分页→呈现”。分页可明确关闭；关闭后呈现完整查询结果的虚拟窗口，不能只隐藏翻页按钮而继续截取十条数据。

排序缺省按未排序、升序、降序循环；Shift 点击追加排序列，平台 Primary 修饰键可显式配置。改变已有排序方向保留优先级。相同比较结果保持来源顺序；缺值位置由列规定，不随格式化文字改变。

筛选提供以下有限、可序列化的操作：

- 文本：包含、等于、前缀／后缀、为空／非空；大小写和 locale 由列的文本策略规定。
- 数值／日期：等于、比较、闭区间、缺值；使用列绑定的类型解析和比较，不按显示字符串比较。
- 布尔：真、假、缺值；集合筛选按明确值 key 选择，重复标签不合并不同值。
- 同列条件与跨列 AND／OR 通过可视化 builder 组合，不支持自由文本表达式。
- 快速筛选只读取列明确提供的搜索文字。查找用于定位匹配项，不改变查询结果；二者不共用含糊的状态。

集合候选可由完整本地来源在该操作需要时派生，并按数据／相关查询变化复用；大候选使用已有虚拟列表。外部模式的候选由应用提供，不能用当前页的不同值假冒全体候选。打开菜单、读取无障碍名称和绘制行都不扫描全表。

改变筛选、分组、透视或排序回到第一页；页大小改变同样回到第一页。数据减少时一次收敛失效页。隐藏一列不隐式删除该列筛选／排序；工具面板显示仍在生效的条件。

### 6.2 分组与聚合

本地分组先筛选原始记录，再按声明维度构造层级，聚合筛选后记录，分别排序同级组和叶记录，最后分页、展开为呈现行。展开状态按组路径保存，列宽／选择变化不重新构造组。

组值 key 与标签由类型化列提供，显示相同不代表同组。空组值有独立身份。组排序使用对应列的类型比较；按聚合值排序调用该度量的比较操作，不拿标题或格式化金额排序。

聚合至少提供 count、sum、min、max、average。count 统计非缺值，组记录数独立提供；全缺值的 sum／min／max／average 返回缺值，count 返回零。整数 sum 检查真实溢出；浮点无效结果和溢出显示明确聚合错误，不截断成有效数值。average 的输出类型由聚合构造入口明确，例如整数平均输出 Double，十进制平均使用显式舍入配置。

不同度量的累加器与结果保存在各自泛型实现中，通过组 key 和度量 id 读取。自定义聚合也使用类型化的累加／完成操作；不把累计值装进 Any 或另建通用表达式引擎。普通数据单元格与聚合单元格使用各自明确的格式化入口，因为 count／average 等结果类型可能不同。

小计／总计从同一聚合结果产生。默认基于整个筛选结果，分页只影响呈现，不把当前页局部总和标成全量总计。组行和聚合结果只读；编辑叶记录后重新应用查询，允许该记录离开原组或当前页。

### 6.3 树数据

树来源使用稳定业务 key 和显式父 key，或应用已经整理好的同等父子访问接口。完整本地来源在接入时检查重复 key、缺失父引用和实际环路；该检查只依赖当前输入，不扩展为跨库验证框架。

同级节点使用稳定排序，展开状态按业务 key 保存。筛选保留匹配节点及其必要祖先，祖先标明仅作为路径上下文；上下文记录默认不参与本次筛选集的选择统计和聚合。非叶节点默认显示自己的业务值，子项统计通过明确的聚合／汇总入口显示，不自动覆盖原字段。

分组模式由平面记录生成组，树模式消费已有父子关系；两种拓扑在一个模型中互斥。树数据支持自身的排序、筛选、展开、单格编辑和主从详情。透视采用第 6.4 节的分组结果，不在本阶段定义对树路径的透视语义。

### 6.4 透视

透视需要至少一个度量聚合，可以没有行分组维度，此时输出单个总计组。筛选在原记录上执行；按行维度和透视维度组合聚合，产生结果列树和行组结果。

结果列由实际出现的维度值组合生成，不构造所有维度的笛卡尔积。每个组合下生成各度量列；没有记录的交叉点使用缺值。维度排序采用类型化比较，结果列的标题与身份分开。维度或度量变化后，同身份结果列保留显隐／宽度／冻结状态，失效的状态项被移除。

透视结果、总计和聚合单元格只读；本阶段不做修改聚合值后向原记录分摊。用户通过列面板选择允许分组、透视和聚合的列，调整顺序和总计显示。结果列过多时使用列虚拟化，不用任意列数配额判定数据是否合法。

### 6.5 分页、固定与详情的组合

分组／树模式按根级结果分页，展开的后代与其根留在同一页。pageSize 表示根项数，界面明确标注；平面模式仍表示业务行数。小计、详情、加载行不占 pageSize。固定业务行从分页后的正文移出显示，聚合成员及根项计数保持原查询定义。

主从详情只附着具有真实业务 Row 的行，由 `(Row) -> View` 提供内容；父记录 key 决定展开身份。详情可包含普通布局或应用明确创建的另一个 DataGrid，内部网格拥有自己的模型、焦点域和滚动，不自动递归创建详情网格。

展开／收起通过按钮、键盘和语义动作进入同一模型操作。收起或删除有活动编辑／弹层的详情时，按正常卸载顺序清理并恢复到有效父行。父行固定时，详情跟随其呈现区域；整个区域继续使用相同的可变行高与裁剪规则。

## 7. 外部分页与区间加载

### 7.1 一个结果接入合同

外部数据使用应用提供的结果，控件不二次执行全量排序、筛选、分组、透视或聚合。普通分页和按区间加载共享查询、列描述和结果接入；不照搬四套 Row Model 的继承体系。

请求信息包括当前查询、根／分组路径／树父节点、offset 和 count。分页据页号请求；区间加载据可见范围及 overscan 请求缺失数据；层级展开请求该分支的子项。网络实现和 JSON／数据库结构由应用处理。

结果包含实际行、该分支已知总数或未知总数、是否到达末端，以及必要的组／聚合元数据。外部透视还提供这份查询对应的完整结果列描述。聚合值通过绑定到具体列类型的供应器交付，不能用普通 Row 的空字段伪造汇总。

应用声明允许用户使用的查询列与操作，控件只提供这些入口。某服务端没有某操作时，应用不声明该操作；不能先在 UI 中承诺，再只对已加载的一页偷偷执行。

### 7.2 请求、替换与失败

- 初始挂载／查询动作在正常 owner 更新中通知应用。滚动需要的新区间在接受布局结果后通知，measure／scene／draw 不调用 IO。
- 相同查询与区间已有数据或正在请求时复用；失败区间显示错误与显式重试，不维持自动轮询。
- 每次查询和请求有普通的生命周期身份。应用完成时交回原请求；查询已替换、分支已关闭或挂载已结束的 UI 结果不再安装。
- 新查询的结果与列结构一起替换，不把新表头、旧行序和旧聚合拼成一个可交互视图。等待期间显示与本次请求对应的加载状态。
- 取消由应用 Job 实施。取消或关闭控件不等于已发生的服务端操作被回滚，实际业务结果仍由应用处理。
- 未加载行没有可选择／编辑的记录身份。向未知位置导航时保存当前查询中的目标位置，加载后再解析真实 key；查询变化即取消，位置不能冒充业务 key。

未知总数时，范围由已知前缀和实际加载尾部构成，不伪造巨大 count。到达尾部请求下一段，末端确认后收敛。已知总数时可按位置请求远处区间。树的“兄弟数量”与所有后代总数分开，不把一个分支 count 当成整个展开树的行数。

### 7.3 能力边界

外部分页／区间加载均支持列操作、显示、单格编辑、行选择、矩形复制、状态保存和原生语义；加载内容不能因列虚拟化被重复请求。

查找、集合候选、跨区间复制和 CSV 必须明确数据范围。客户端查找仅查当前可用结果；全服务端查找由应用提供显式动作。复制或导出目标含缺口时返回具体的不可用范围，不跳过缺口生成看似完整的数据。

组全选只在所需业务行身份完整可得时启用；否则提供选择已加载行的明确入口。没有“所有远端匹配记录减例外”的抽象选择协议，也不为了勾选或读屏器取名自动加载全部数据。

## 8. 二维虚拟化与焦点接入

### 8.1 一份数据结果与挂载树

采用按行的 LazyElement，行内再按列按需挂载。列索引、宽度前缀和冻结区几何由网格共享，行内不各建一个横向 ScrollArea。正文 ScrollViewport 由网格布局控制器持有；表头、固定行和固定列消费同一份滚动结果。

正文与固定行共用稳定行身份域，同一行的所有列也共用该行的列身份域；固定区域仅改变放置和裁剪，避免因分区建立不同父级而丢失同 key 内容的身份。表头有独立挂载，但引用相同列定义和几何。

一次布局选择：

1. 用已有 extent／锚点逻辑确定正文行窗口。
2. 用共享列宽前缀定位中心区列窗口，加上冻结列和有限 overscan。
3. 加入自动行高所需列、跨列锚点，以及已有焦点、编辑、弹层、指针序列或在途定位要求保留的行列。
4. 经原 LazyElement 准备／测量／放置；每个数据单元格只有一个挂载实例。
5. 对 Start、中心、End 及上下固定区施加各自裁剪和位移，Accepted 后统一发布几何。

不预创建行数乘列数的 View、FocusHandle 或语义节点数组。列元数据可随列数线性保存，行顺序索引随实际本地查询保存；不存在所有单元格的二维对象矩阵。离屏语义值读取直接访问同一数据结果。

冻结区不是三套 DataGrid。跨区域移动列时，稳定列身份保持；正在编辑或持有输入序列的列操作先按第 10 节结束／拒绝当前动作，再改变所属区域。不会同时保留一个可操作副本和一个可操作原件。

### 8.2 可变布局与停帧

共享列几何只由列结构／状态、字体、密度和可用宽度决定。行高只依赖当前行及高度贡献列的有效输入。普通悬停、焦点、选区覆盖层变化不重跑全量查询；未变化的列宽和测量结果直接复用。

数据替换删除真实 key 时，即使窗口隐藏也结束对应挂载、输入和请求。Accepted／Discarded、祖先裁剪、零尺寸与缓存复用遵守 UI 原合同。选区、拖列指示和编辑框都使用实际 Accepted 几何，不能使用试测矩形接受操作。

仅实际拖动中的边缘自动滚动、正在播放的可见动画和真实更新请求帧；结束后恢复停帧。使用现有 Surface 时钟与滚动动画，不为 DataGrid 新建定时绘制循环。

### 8.3 需要验证的公共接口

现有 `LazyFocus` 只能选择线性条目的 First／Last 目标，有限 `KeyNavigation.Grid` 也只认识已注册成员。不能直接宣称它们已经提供二维离屏定位。

设计采用“网格解析行列地址，UI 完成一次真实焦点请求”的分工：网格把目标行、目标列纳入本轮 lazy 布局；挂载完成后取得该单元格的真实 FocusHandle，再由根的唯一 pending request 显露并聚焦。取消、新输入、删除、禁用、模态边界和关闭继续由同一请求路径处理。

D0 原型必须验证以下能力，并只对确实缺失的部分扩展 UI spec：

| 能力 | 拟议最小扩展边界 |
| --- | --- |
| 行挂载后选择指定列目标 | LazyFocus 支持只读的条目内明确目标选择；返回真实 FocusHandle，并检查它属于所请求条目。DataGrid 保存的定位意图让目标列参与挂载 |
| 自定义单元格内部 Tab 与离开单元格 | 沿现有 FocusScope 遍历；若当前公开接口不能报告域内遍历结束，补该结果，不创建另一份全局 Tab 顺序 |
| 原生访问离屏列 | 扩展现有 Grid 单元格 Realize／Reveal／Focus 路径，按行列 key 准备真实目标，与键盘请求共享取消和几何发布 |

以上是需要实现验证的设计目标，不是已存在的方法签名。不得通过全部单元格常驻、先聚焦错误列再跳转、隐藏文本框或第二套焦点树绕过。原型完成后在对应 spec 确定唯一公共合同；不把试验实现留成两条生产路线。

## 9. 导航、行选择与单矩形选区

### 9.1 浏览与内部交互

网格正文作为一个 Tab 入口，恢复最近有效的单元格；表头、工具栏和外部控件保留正常 Tab 顺序。实际焦点仍由 Surface 决定，模型只记录最近成功的地址与必要定位意图。

| 输入 | 正文浏览行为 |
| --- | --- |
| 方向键 | 按当前行列顺序移动；左右随 RTL 映射，跨冻结区保持连续 |
| Home／End | 当前行的首／末可导航列 |
| Primary＋Home／End | 当前结果的首／末可导航行；未知远端末尾只定位已知末端，不自动穷举加载 |
| PageUp／PageDown | 按正文视口高度移动，再解析同列的可导航行 |
| Tab／Shift＋Tab | 下一／上一单元格；到网格边界后进入外部正常 Tab 序列 |
| Enter／F2 | 可编辑格进入编辑；自定义交互格进入其真实控件，分组展开按钮执行自身操作 |
| Escape | 编辑／弹层优先处理；浏览状态清除当前矩形选区 |
| Shift＋方向键／Shift＋点击 | 从锚点扩展一个矩形 |

自定义单元格内部的按钮、链接、输入和菜单保留自身键盘操作。进入其交互后，Tab 先经过该格的实际目标，离开边界才回到网格遍历。原生 IME 和文本编辑先于网格快捷键，不能抢走组合输入的方向键、Enter 或 Escape。

普通单元格点击聚焦，点击实际子控件直接进入其操作；子控件成功认领的点击／拖动不再生成网格拖选。离屏定位按 key 等待实际布局，旧请求不会在新滚动或新焦点之后迟到兑现。

### 9.2 业务行选择

支持单选和多选，选择保存业务 key，与当前单元格和矩形选区分开。Checkbox、行选择动作和原生选择操作调用同一入口。范围选择按当前结果顺序处理，跳过不可选记录。

分页表头全选只作用于当前页；区间模式提供名称明确的“选择已加载行”。组选择对当前查询中该组的合格业务记录计算三态，折叠不改变已知成员；外部身份不完整时按第 7.3 节处理。

本地来源确实删除记录时清理选择；过滤隐藏或外部本页缺少记录不代表删除。组、汇总、详情、加载和失败行不作为独立业务选择对象。固定业务行与其原记录共用同一选择事实。

### 9.3 矩形范围

只保存一个锚点和一个端点，范围由当前可见列顺序及可成格的结果行顺序解释。冻结区域连续，详情、加载和错误行不生成可编辑格；分组／汇总的已知展示值可以参与复制。

Ctrl／Command 拖动不会添加第二个范围，也不对原范围挖洞。排序、筛选、分页、展开结构或列顺序／显隐变化会清除原矩形，避免把同一对位置解释成另一批记录；仅调宽和布局缩放保留范围。原始值更新但结构未变时保留范围，复制读取动作开始时的同一结果快照。

拖选使用现有 Drag 与输入归属，触点取消、第二触点、失焦、禁用、关闭和几何失效均结束本次手势。边缘滚动只在活动拖选期间推进；已选但未编辑的离屏单元格不因为选区而常驻。

## 10. 单元格编辑

### 10.1 编辑操作

列明确是否可编辑，并提供编辑器、解析、校验和提交。Text、数值、布尔、日期、枚举分别复用 Input／Textarea、Checkbox、DatePicker、Select／Combobox；自定义编辑器沿同一单格合同接入。

同一挂载最多一个编辑会话。草稿保留在该会话的类型化实现及真实 TextEditorState 中，不修改原始 Row。进入编辑记录行列 key 和原值，提交时重新确认记录仍存在、该列仍可编辑及原字段未被外部替换。

| 事件 | 行为 |
| --- | --- |
| 双击、Enter／F2、显式 handle 请求 | 为当前可编辑格创建会话，聚焦真实编辑器 |
| 文本输入意图 | 进入编辑后交给 Window／TextEditHost 的 Unicode 输入路径；不枚举 ASCII 按键伪造文字 |
| Enter／Tab／点击其他单元格 | 先完成合法单格提交，成功后结束或移动；校验拒绝则保留编辑并显露错误 |
| Escape | 按 IME、编辑器弹层、编辑会话的顺序处理；最终取消草稿，不写数据 |
| 外部删除记录、列消失、禁用或卸载 | 取消当前会话和 UI 等待，释放真实输入归属 |
| 外部替换同一字段 | 原值确实变化时结束旧草稿并通知；不以旧候选覆盖新值 |

组合输入没有完成时不把 preedit 当成候选值提交。系统输入法所需的开始输入、候选选择和失焦处理必须在 D0／D3 用真实中文 IME 验证；不得以拉丁字母输入测试代替。

### 10.2 校验与应用提交

解析和同步校验只处理一个候选，失败保留草稿与可读错误。应用接受值时，在一次 owner 动作中更新数据快照并完成会话；新值相等时不制造数据变化通知。组／透视结果、跨列显示和纯操作格没有伪造的 setter。

远程保存由应用自己的 Job 执行。当前格可进入提交中状态，阻止重复提交和新编辑；成功后安装实际结果，失败后回到该格显示错误。完成回调只属于原编辑会话，关闭／取消后不重新挂载编辑器。已发生的服务端写入由应用按业务结果同步，不因 UI 回调失效而假定回滚。

会让编辑目标不可见的网格用户操作先尝试提交；校验未通过或仍在 composition／提交中时拒绝该次操作并保留目标。外部强制数据替换及挂载销毁沿取消规则处理。正常滚动可保留离屏编辑项，沿原活动项 retention 和 clip，不把编辑器复制到另一个格。

一次提交之后重新应用当前查询，因此记录可能换组、移位或消失。目标仍存在时按稳定 key 维持位置；消失时选择同列最近有效行，没有候选则回到网格入口，不继续编辑同一旧索引的新记录。

## 11. 剪贴板与 CSV

### 11.1 矩形复制与单格粘贴

浏览状态的复制优先使用当前矩形，否则使用活动单元格。按当前逻辑行列顺序，从同一结果快照读取列的复制文字；不调用 View 工厂，不要求离屏单元格挂载。是否包含表头是明确选项。

矩形文本使用制表符分列、换行分行；含分隔符、换行或双引号的字段使用双引号包裹，内部双引号加倍。Unicode 原样保留。未提供复制表示的操作列输出空字段，保持矩形位置；已声明的缺值使用列的明确缺值表示。

网格浏览状态下粘贴先解析剪贴板矩形：只有一个字段时才进入当前格的解析／校验／提交。多个字段或多行结构返回“一次只能粘贴到一个单元格”的用户操作结果，不截取首格，不循环提交。末尾普通记录终止符不额外生成一行。

真实文本编辑器取得焦点时，剪贴板直接由其编辑 policy 处理。Textarea 粘贴多行文字仍是编辑一个值，不被当成矩形批量编辑。剪切和文本撤销在编辑器内保持原行为；网格层不提供选区剪切或批量 Delete。

### 11.2 CSV 数据导出

导出生成数据流或文字，由应用选择文件位置并执行写入。实现复用现有字符／IO 能力；不能把整个可视网格截图或建立离屏 View 树来导出。

导出选项明确：列顺序与是否包含隐藏列、是否含表头、行范围、是否含分组／汇总／固定行。缺省导出当前显示列，排除纯操作列与详情内容；固定业务行按身份只出现一次。

| 数据模式 | 可选择的范围 |
| --- | --- |
| 完整本地结果 | 当前页、已选择记录、全部筛选结果；分组／透视可明确导出展示结果或原始业务行 |
| 外部结果 | 当前完整页或明确的已加载范围；包含缺口的请求返回不可用范围 |
| 需要全远端结果 | 应用另行取得完整来源后调用同一导出操作，或执行自己的服务端导出；DataGrid 不隐式加载全部区间 |

CSV 使用 UTF-8、逗号分隔、CRLF 记录边界；含逗号、换行或双引号的值按双引号包裹和加倍规则输出。导出文字由列显式 formatter 决定，日期、数值与缺值不依赖任意 View 的显示内容。计算错误使用明确的错误文本／应用提供的导出处理，不能变成正常的零值。

本阶段不增加 XLSX、PDF、打印布局或 Excel 导入引擎。应用可以用独立文件解析库生成普通来源，导入格式不进入网格的数据契约。

## 12. 工具面板、状态与外观

### 12.1 组合控件

列面板提供显隐、顺序、冻结、列组及允许的分组／聚合／透视设置；筛选面板显示类型化条件，支持添加、修改与清除。列头菜单与面板调用同一模型动作，取消调宽／拖列恢复本次操作开始值；期间有应用新状态时以应用结果为准。

上下文菜单只提供当前目标可执行的操作。状态栏可显示结果数、已选行数、加载状态及单个矩形中数值的 count／sum／min／max／average；范围统计读取数据，缺口明确显示不可用，不触发隐式取全量。它是只读派生信息，不是批量编辑或公式。

工具栏、底栏、空状态、加载、错误和详情接受现有 View 插槽。展示文案通过显式本地化配置提供；不把英文按钮字符串固化到查询和身份中。图标复用现有图标能力。

### 12.2 保存与恢复

视图快照包含列顺序／显隐／宽度／冻结、查询、业务行选择、层级展开、固定行、有效矩形，以及可选的阅读锚点和最近单元格地址。它只含普通数据，不保存 Row 对象、View、回调、FocusHandle、native 句柄、在途请求或编辑草稿。

应用负责持久化。恢复时按当前列和来源检查：已经删除的列／记录引用不恢复，外部尚未加载的业务选择可保留，但不能据此宣称目标已存在。返回未采用的具体状态项，方便应用反馈；没有历史版本兼容迁移器或 AG Grid 状态导入层。

恢复在一次模型动作中应用有效状态并计算相应结果，不先展示默认未筛选数据再逐字段回写。列结构不匹配的矩形不恢复；有效行列地址经普通按 key 显露处理，失败就结束。恢复不发送多次中间查询，来源异步返回仍走第 7 节。

### 12.3 主题与输入偏好

Grid 样式包括表头／组头、正文／交替行、边线、hover、行选择、活动单元格、矩形选区、冻结分界、编辑／错误／提交中，以及调宽／拖列指示。默认从现有 token 组合，不按主题名称分支；确需公共参数时同步四套主题。

字体、密度、对比度、减少动画和 focus-visible 沿根偏好继承。方向通过逻辑 Start／End 解析，数值／日期等文字不因 RTL 镜像。焦点环与编辑错误需要实际布局留白，不能仅在绘制中放大到已裁剪区域之外。

鼠标、触控板、Touch／Pen 使用已有 Press／Drag／滚动路径。普通触摸拖动优先滚动；单矩形选择可通过明确的选择模式进入，避免和滚动抢同一触点。长按打开当前单元格的既有上下文菜单；不引入选区填充柄。键盘及语义动作始终提供等价操作。

## 13. 原生无障碍

整个网格发布一个逻辑 Table／Grid，表头组、列头、行及单元格使用真实关系。冻结只是几何分区，不产生多张被读屏器重复朗读的表。范围中的实际行列位置随查询与列顺序更新。

元数据来自 `GridResult<Row>` 和列声明：名称、值、排序方向、选择、只读／可编辑、错误／busy、层级深度与展开状态。不为取名创建 View；自定义 View 没有明确数据描述时保留未知，并使用其实际挂载语义。

行虚拟化与列虚拟化均保留数据级可查询位置。读取单元格值不滚动、不加载网络、不抢焦点；显式 Realize／Reveal／Focus 才沿原路径准备目标。外部未知总数不假报为全量零行，公布实际可描述集合及明确的已加载／总数未知状态。

编辑时由真实 TextEditHost 发布文字、选择与 composition，表格外层只表达该格编辑状态。分组和树的展开、行选择、冻结／调宽菜单操作复用同一业务入口；无效或已删除目标返回正确的不可用结果。

macOS AX、Windows UIA、Linux AT-SPI 的进程内方法、外部客户端和 VoiceOver／Narrator／Orca 分别验收。现有基础 provider 通过不能自动证明新网格的虚拟列、固定区或层级组合通过；实际支持范围按测试结果记录。

## 14. 关键组合合同

| 组合 | 确定行为 |
| --- | --- |
| 列虚拟化＋自动行高 | 指定高度贡献列始终测量，其余列仍虚拟化；不承诺未知离屏内容决定精确高度 |
| 冻结＋RTL＋矩形选择 | 使用统一逻辑行列顺序，几何分片；每格一个实例，范围跨区连续 |
| 分组／树＋分页 | 按根项分页，后代／小计／详情随根，不截断一个展开分支 |
| 筛选＋聚合＋分页 | 聚合基于整个筛选结果，页内数值不冒充全局数值 |
| 树＋透视 | 拓扑不组合；切换分析模式是显式模型动作，不猜测树路径的维度含义 |
| 单格编辑＋排序／分组 | 先完成或拒绝提交，再按真实新值计算；按 key 保持或选择合法后继 |
| 编辑＋虚拟回收 | 活动项保留并按 viewport 裁剪，结束后恢复回收；真实删除优先取消 |
| 跨列显示＋编辑／复制 | 合并呈现只读；复制／CSV 使用各逻辑列的实际值；无跨行合并 |
| 外部缺口＋选择／复制／导出 | 不伪造记录或默默跳过；明确已加载范围，缺口返回不可用结果 |
| 详情＋折叠／删除 | 真实子树正常卸载，编辑和弹层先收尾，焦点回有效父目标 |
| 保存恢复＋外部取数 | 一次应用视图状态，一次发起对应查询，旧请求不能覆盖新视图 |
| 多字段剪贴板＋单格编辑范围 | 浏览模式拒绝多格改写；文本编辑器内部仍可粘贴多行单值 |

组合限制应体现在公开配置与操作结果中，不能用底层空分支或笼统的“尚未支持”代替处理。

## 15. 性能与资源要求

呈现成本主要随可见行、可见列、冻结区、高度贡献列和真实活动项变化。正常横向滚动不重新执行全量排序／筛选，选择覆盖层变化不创建所有选中格，静止窗口不持续提交帧。

本地查询允许与实际数据量相关的遍历和排序，分组／透视索引也只表示实际数据。不能把“有百万行虚拟化测试”写成百万行排序、透视或宽表格帧率承诺。无需新增跨操作的 CPU／内存计费、任意最大行数或通用预算体系；实际索引、计数、跨度和坐标仍做必要的溢出／边界检查。

外部结果可按正常区间缓存复用。回收缓存区间不等于业务删除，不清除其稳定 key 选择；活动编辑、焦点和在途动作所需记录在实际会话期间保留。相同查询中未变化的已加载区间直接复用。

资源归属沿现有 scope：字体／布局／编辑器／Portal 随挂载清理，应用数据和借用状态不被控件关闭。错误沿现有组件根错误边界或明确的操作错误结果处理，不把任意异常吞成空行。

## 16. 本阶段实施顺序

每批先更新对应 spec，再实施公开入口、算法、实际消费者和必要测试。以下均属于本阶段；排除项没有预留批次。

| 批次 | 交付内容 | 完成条件 |
| --- | --- | --- |
| D0：公开合同与纵向原型 | 细化类型化列和结果、行列虚拟化、单格焦点／编辑、原生单元格定位；确定第 8.3 节实际需要的 UI 扩展 | 宽表格真实窗口可横纵滚动，离屏格能一次正确聚焦，冻结区无重复实例，中文 IME 能进入并取消编辑；确定唯一生产路径 |
| D1：本地模型与列 | 数据／列身份、类型化查询、稳定排序、基本／组合筛选、分页、列状态、普通数据替换 | 普通模型测试和实际管理表格闭环通过；分页关闭语义、重复标签、缺值及查询复用明确 |
| D2：完整布局 | 列重排／分组／冻结、固定行、行高、显式调宽、跨列显示与双向虚拟化 | 宽表格、RTL、缩放、变高、窄窗口和跨区操作通过；只创建实际需要的单元格 |
| D3：单格交互 | 二维导航、自定义控件内部交互、编辑／校验／应用提交、单格粘贴 | 输入法、失焦、取消、禁用、远程保存回调及滚动回收有完整出口；不出现多格改写 |
| D4：选择与配套操作 | 行选择、单矩形选择／复制、查找、菜单／面板／状态栏、CSV、保存恢复 | 离屏复制不构造 View；导出范围正确；恢复只产生最终查询；排除功能不可通过快捷键绕入 |
| D5：层级与聚合 | 分组、树、展开、聚合、小计／总计、根项分页与固定行组合 | 重复组标签、缺值、空结果、深层树、环／缺失父引用、筛选上下文和跨页统计正确 |
| D6：透视与详情 | 动态结果列、度量／维度配置、总计、只读结果、普通及嵌套详情 | 透视不构造笛卡尔积；列状态按身份保留；详情可变高度、编辑、折叠与焦点收尾通过 |
| D7：外部结果 | 分页／区间加载、未知总数、层级分支、外部透视、加载／失败／重试及取消 | 用真实应用数据源验证请求与结果配对；迟到结果、缺口和部分集合选择／复制／导出均按合同处理 |
| D8：完整组合验收 | 四套主题、本机原生语义与输入、规模测量与使用材料 | 本节和第 17 节范围在本机完成验证；真实读屏器和硬件测试据实记录，不安排跨平台验收 |

D0 的原型用于确定必要接口与实现路线；通过的生产实现归入同一组件路径，不长期维护一套演示网格和一套正式网格。D1～D7 持续维护同一组真实示例，D8 不靠另起一个功能较少的展示页验收。

## 17. 验收与编程材料

### 17.1 模型与算法

普通行为放在所属 Cone 的 `scoop.test` 中，至少覆盖：

- 行列／组／透视身份、重复显示文字、删除与重排、外部页缺失不等于删除。
- 类型化排序／筛选、缺值、数值边界、稳定次序、查询结果复用和一次恢复。
- 单格解析／校验／提交／取消、多字段粘贴拒绝、编辑器内部文本撤销。
- 单矩形在结构变化时清除、固定区顺序、CSV 引号／换行／Unicode、缺口不产生部分成功。
- 分组／树／聚合／透视、小计／总计、根项分页、实际环路、动态列和上下文祖先。
- 外部分页／区间／层级返回、未知总数收敛、失败重试、取消与迟到结果。

需要验证新的语言编译错误规则时才增加代表性 expected-error fixture；普通库 API 行为不复制成 consumer fixture。

### 17.2 真实窗口与必要组合

实窗 Cone 使用 release、真实已有工具与 sysroot；以公开 UI 接口观察挂载和实际操作。至少覆盖：

| 场景 | 验证重点 |
| --- | --- |
| 宽表格与冻结 | 横纵滚动、头部对齐、列拖动、窄宽退化、RTL、DPI、跨列锚点与单格唯一挂载 |
| 编辑与虚拟化 | 真实中文 IME、候选键、Tab／Enter／Escape、外部字段改变、排序换组、滚出视口、禁用与关根 |
| 选择与剪贴板 | 跨冻结区的一个矩形、拖选边缘滚动、子控件不被抢手势、真实系统复制／单格粘贴 |
| 层级与详情 | 展开分页、可变高度、固定父行、详情内输入／菜单／嵌套网格、收起时的焦点和资源 |
| 原生语义 | 冻结区不重复、离屏行列读取／显露／聚焦、列顺序和树深度、只读／错误／busy、目标删除 |
| 失败与生命周期 | Accepted／Discarded、零尺寸、模态阻挡、来源替换、缓存回收、隐藏窗口和静止停帧 |

按用户后续要求，本阶段只在本机 macOS aarch64 验证，不安排多平台验证。没有设备或外部客户端结果时不把受控事件注入记成真实硬件／读屏器通过。

### 17.3 性能测量

使用固定数据和同一构建、机器、窗口尺寸与字体配置，分别测量：

- 普通管理表格：一万行、二十列，包含文字、数值和少量真实控件。
- 宽表格：十万行、数百列，分别测固定行高、少量自动高度列、冻结区和横纵滚动。
- 大惰性来源：百万行，检查挂载／measure／View 工厂调用随视口变化，不把完整排序或全部 Row 预分配混为虚拟化成本。
- 分组／透视：真实基数分布与度量，测构造／切换查询耗时及结果列数；不使用人为笛卡尔积作为正常场景。
- 静止与关闭：无持续帧、无在途定位或编辑资源残留。

记录可见／保留单元格数、首次呈现、滚动帧耗时分布、查询耗时、内存与空闲提交；这些是具体场景测量，不成为库的运行期资源预算。原始日志、截图和逐次报告放仓库外，文档只保留范围、环境、概要与失败闭合。

1. 组件 spec 增加 DataGrid 的公开模型、操作和组合合同；UI／无障碍 spec 只更新实际新增的公共能力，涉及原生接口时同步 Window spec。
2. 公共声明、builder、必要示例与所属 Cone 测试一起实现；示例中的列类型、query 和生命周期必须能由当前工具查询和编译。
3. `scoop-grid` README、API 文档与示例；底层公共接口变更涉及的编程 skill 和工具在对应能力实际可用时更新；不能提前发布本设计中的拟议签名。
4. 文档纯文字阶段只做事实、链接和结构检查；代码实施阶段先执行对应格式化／lint，再做定向测试，最后完成本阶段矩阵。

当前设计不改变语言、runtime 或编译 pipeline 契约；其基础规则继续遵循 [语言规范](../../specs/SCOOP-SPEC.md)、[运行时规范](../../specs/SCOOP-RUNTIME-SPEC.md)、[编译器与产物规范](../../specs/SCOOP-IMPL-SPEC.md)及 [API 风格](../../specs/SCOOP-API-STYLE.md)。不增加来源审计、授权链、通用配额或重复语义验证。
