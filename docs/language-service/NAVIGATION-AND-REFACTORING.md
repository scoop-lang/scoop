## 首批实施

### 转到上级声明

在 `override` 方法或属性的声明名称上执行命令。沿各条实际重写关系返回最近的上级声明，包括抽象覆写和接口成员。构造参数声明的覆写属性按原 logical property 定位。单个目标直接打开，多个目标由编辑器列出所属类型并供用户选择。仅有元数据的上级用于连接已知继承关系，能打开的源码目标才返回位置。

前端已有成员实现索引，其中包含覆写来源、虚方法根以及接口分派选中的提供方。上行查询取**该声明自身的覆盖来源**。例如子类用继承来的 `Base.run` 满足自己的 `Runner.run` 时，这条分派关系属于子类，查询 `Base.run` 的上级需要读取 `Base.run` 的声明关系。若现有投影只保留虚方法根或合并后的实现边，在原覆盖计算处补充查询实际需要的直接声明来源。属性沿已有覆盖关系查询，方法沿实际 slot 和基类／接口关系查询。 [成员实现索引](../../compiler/hir/src/semantic_queries/editing/implementations.rs) · [源码成员关系](../../compiler/hir-lower/src/editing/implementations/members/source.rs) · [接口实现选择](../../compiler/hir-lower/src/editing/implementations/members/conformances.rs)

`scoop-analysis` 将源码位置绑定到成员并返回可定位的上级来源。`scoop-lsp` 通过一个专用位置请求转换为 `Location[]`，沿用现有项目选择、位置编码和取消机制。VS Code 扩展注册「转到上级声明」命令，使用该文档所属的语言客户端。查询所需事实来自声明分析，方法体有错误而声明关系已完成时仍可导航。 [声明与实现查询](DESIGN.md#53-源码到语义的关联) · [VS Code 扩展](../../tooling/vscode-scoop/README.md)

### 提取局部变量

在函数或其他已分析正文的块内选中一个完整表达式。「提取局部变量」在同一块插入 `val`，并把原选区替换成对它的读取。首版覆盖整个局部初始化式、整个 `return` 值和能在原语句前保持求值位置的实参。例如可从顶层函数调用 `publish(encode(input))` 提取 `encode(input)`。如果选区出现在 `ready && check()` 的右侧，原语句前的插入点会把条件求值改成每次求值，因而该位置没有可用动作。 [类型事实与短路](../specs/SCOOP-SPEC.md#23-语义调整) · [调用顺序](../specs/SCOOP-SPEC.md#853-求值顺序与调用处实例化)

1. 从当前 CST 定位完整语法节点和可插入的语句边界。前端提供该表达式的实际类型、绑定和使用处上下文。需要保留上下文定型时，给新 `val` 写出可在当前作用域解析的类型，例如原调用为 `[]` 提供了 `Array<T>` 期望类型。
2. 在原执行路径上选择插入点，保留 receiver、实参和运算数的求值顺序与次数，以及原位置已建立的 smart cast。保留选区中的注释和原文件换行，生成当前作用域可用的默认名称。用户可用现有重命名修改该名称。
3. 用 `SourceEdit` 生成同版替换。插入和替换共用一个起点时合成一个编辑。候选快照沿普通前端分析，核对新名称的绑定、受影响的既有引用和重载选择，以及替换处的类型。选区或插入点所需的事实不完整时，该选区没有可用动作。 [编辑快照](../../compiler/analysis/src/host/edits.rs) · [编辑与绑定检查](../specs/SCOOP-IMPL-SPEC.md#220-可恢复语法与语言服务公共基础)

通过 `textDocument/codeAction` 返回 `refactor.extract`。沿用 Code Action literal 和 `documentChanges` 的客户端能力协商。按实际支持在动作内提供编辑，或通过 `codeAction/resolve` 延迟取得。按 `context.only` 匹配请求类别，`quickfix` 请求只计算诊断修复。 [现有 Code Action 入口](../../compiler/lsp/src/queries/code_actions.rs) · [LSP 3.17](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/)

## 后续导航

### 类型层级

接入 `textDocument/prepareTypeHierarchy`、`typeHierarchy/supertypes` 和 `typeHierarchy/subtypes`。沿已有类型绑定选择名义声明，透明别名先解析实际目标，泛型应用归并到原声明。每次展开只列**直接关系**。父类型来自声明阶段得到的直接基类或父接口，子类型来自所选项目中相应的反向关系。子接口、抽象类、`object` 和实现接口的值类型按实际声明参与。现有实现查询使用的传递关系可用于查找后代，展开层级时读取直接声明边。 [类型关系和实现查询](DESIGN.md#53-源码到语义的关联)

### 调用层级

接入 `textDocument/prepareCallHierarchy`、`callHierarchy/incomingCalls` 和 `callHierarchy/outgoingCalls`。每条关系记录调用者、被调用声明和调用位置，同一对声明间的多处调用合并为一项。调用者查询使用项目中实际绑定的调用，向下展开读取当前声明拥有的源码正文。对虚调用展示静态选中的成员，可继续用「转到实现」查看具体提供者。 [现有源码绑定契约](../specs/SCOOP-IMPL-SPEC.md#220-可恢复语法与语言服务公共基础)

构造委托和初始化正文归到所属构造器，默认表达式归到定义处。getter 和 setter 归入逻辑属性，有实际访问器分派的读写记录原用法。运算符使用原 token。直接调用函数引用可以定位该声明，其他能确定源码位置的函数值调用可定位到值绑定。`::f` 的创建位置仍可通过查找引用定位。展开使用发起请求所属的项目与版本。 [一致视图与取消](DESIGN.md#73-一致视图与取消)

### 其他导航

需要逐层浏览方法重写时，使用成员的上级声明和下游实现关系提供方法层级。文件内用法高亮可按需求复用查找引用的绑定位置。相关测试跳转以可定位的真实关联为依据，Test 配置下的实际引用可先用于导航。控制流目标跳转沿普通前端确定的 `break`、`continue` 和 `return` 目标实现。跨平台定位使用现有目标配置，切换后跳到该目标实际解析的声明。 [引用与源码导航](DESIGN.md#72-从保守更新逐步细化) · [K2 控制流跳转](https://github.com/JetBrains/intellij-community/blob/idea/262.8665.258/plugins/kotlin/code-insight/kotlin.code-insight.k2/src/org/jetbrains/kotlin/idea/k2/codeinsight/navigation/GoToBreakContinueReturnHandler.kt)

## 后续重构

### 提取函数

通过 `refactor.extract` 在同一块内生成局部 `fun`，在选区处调用。完整表达式返回原值，连续语句须能独立执行并正常落到选区末尾。用已有绑定和控制流确定可传入的外部读取、输出类型和跳转目标。外部输入用显式形参表达时，读取仍须发生在和原执行路径等价的位置。局部函数可按原规则捕获外层不可重新绑定的值。需要写回外层局部、把局部声明带出选区，或改变 `return`、`break`、`continue`、挂起及清理边界时，首版不给出提取动作。能保留原上下文类型、调用效果和被移动名称的绑定后，才生成编辑。 [捕获与局部函数](../specs/SCOOP-SPEC.md#813-捕获与局部函数) · [块级导入](../specs/SCOOP-SPEC.md#1246-块级-import)

### 局部内联、类型别名和安全删除

| 动作 | 首版可用范围和检查 |
| --- | --- |
| 内联局部 `val` | 在能保持类型和求值的场合，以字面量或稳定的不可重新绑定值替换读取。删除原声明前检查全部相关用法，在候选快照核对替换点的期望类型、重载和绑定。以 `refactor.inline` 提供 |
| 引入透明 `typealias` | 对一个已完整解析的类型选区，在合法声明位置写出同一类型并替换该处。保留实际类型参数的身份、可见性及需要随类型保留的注解。以 `refactor.extract` 提供 |
| 安全删除 | 首版检查普通文件私有函数。用完整引用结果检查调用、函数引用和其他用法，并识别编译器与运行器使用的入口。有阻塞用法时给出可定位的结果，满足删除条件时返回删除声明的编辑 |

### 提取常量、计算属性和参数

`Extract Constant` 使用已有 `const val` 求值检查，生成文件私有常量。`Extract Property` 在类中生成私有计算属性，getter 保留表达式的求值位置，方法局部变量等不可访问的绑定会阻止编辑。`Extract Parameter` 针对普通文件私有函数的字面量或已有形参读取，生成带默认值的新形参，保留已有调用及其实参次序。 [常量与默认值规则](../specs/SCOOP-SPEC.md)

### 内联函数

在同文件中展开普通私有函数的一次直接调用，支持表达式体和仅末尾有值返回的块体。用独立的表达式分支在原调用位置执行，显式实参按源码顺序求值一次，随后按声明顺序求值默认表达式，再运行函数体。用绑定事实替换形参读取，保留原声明与其他调用。内联需要额外处理的返回、缺少绑定或依赖源码位置时，当前调用处没有可用动作。 [求值顺序与调用处实例化](../specs/SCOOP-SPEC.md#853-求值顺序与调用处实例化)

### 提取接口、父类和上下移成员

在同文件的非泛型内部类或文件私有类中，从类名称或选定的普通 final 方法进入。提取接口复制方法契约，并将原实现保留为 final override。提取父类将方法移动到新增的无状态父类，要求原类可以接入新的基类构造链。上移使用实际直接基类，下移使用唯一的直接子类。移动保留方法正文和注释，核对原用法与移动正文的绑定。依赖源位置、原类状态或会使父类用法失效的动作不返回编辑。 [继承和方法规则](../specs/SCOOP-SPEC.md)

### 移动声明与修改签名

- **移动顶层声明。** 从同一 Cone、同一 package、同一配置中已选中的两个文件之间移动普通顶层函数开始。复用文件头与块级导入规则，检查文件级 `private`、同名绑定和实际引用。跟随声明的文档和注释一同移动。若被移动表达式依赖定义位置或相对资源路径，须满足对应 intrinsic 的源码来源规则才能提供编辑。跨 package 及跨 Cone 移动另按实际导入、依赖和重导出关系设计。 [可见性和源码输入规则](../specs/SCOOP-SPEC.md)
- **修改签名。** 在普通文件私有函数上调整形参顺序、新增带默认值的形参、删除未使用形参及设置或清除默认值。换序按已绑定的形参映射补写命名实参，核对显式和省略实参的求值顺序。方法沿同文件内部或私有类型的实际重写链换序。普通文件私有函数的引用被直接调用时，可改写为等价的命名调用。删形参时只移除无副作用的对应值，保留其余实参与绑定。 [实参映射和求值顺序](../specs/SCOOP-SPEC.md#853-求值顺序与调用处实例化)

移动和修改签名由编辑器收集目标文件或参数顺序，服务端返回完整的版本化编辑供预览和应用。整理导入使用独立的 `source.organizeImports` 动作。用绑定事实识别未使用的精确导入及星号导入，涵盖文件头和块级作用域，并保留公开重导出。 [导入与引用关系](DESIGN.md#72-从保守更新逐步细化)

## 查询与编辑的职责

- CST 提供选区、原文和插入边界。`scoop-hir-lower` 复用普通前端已检查的类型、作用域、控制流和分派结果，补齐当前动作实际需要的查询事实。`scoop-analysis` 管理项目、文本版本、查询和候选快照。`scoop-lsp` 处理协议与坐标，编辑器显示结果并应用编辑。 [公共模块与数据流](DESIGN.md#2-模块与数据流)
- 导航以 typed 声明身份定位源码。局部动作只要求所选范围及它依赖的分析事实可用。跨文件动作要求所需的声明与用法覆盖完整。一次请求读取同一项目配置和快照，已完成的事实沿现有失效边界复用。 [共享语义与引用索引](DESIGN.md#5-共享语义查询)
- 重构候选使用私有编辑快照重分析受影响的源码。按原声明来源及编辑的位置映射核对实际绑定，并按动作检查求值、控制流或调用顺序。编辑结果按打开文档的实际版本转换为 `documentChanges`，关闭文件使用协议允许的空版本。延迟动作依赖的文本或项目上下文过期时返回 `ContentModified`，取消的请求沿现有 LSP 机制完成。 [源码编辑契约](../specs/SCOOP-IMPL-SPEC.md#220-可恢复语法与语言服务公共基础)

进入各批实现前，先把该批对外协议和语义边界补进实现规范 2.20。交付后同步服务器说明、VS Code 操作入口和实施记录，涉及用户实际用法的变更按编程材料更新工作流同步。 [实现规范](../specs/SCOOP-IMPL-SPEC.md#220-可恢复语法与语言服务公共基础) · [编程材料更新工作流](../scoop-programming/UPDATE-WORKFLOW.md)

## 验收

| 功能 | 检查的可观察结果 |
| --- | --- |
| 上级声明 | 多个实际父接口、抽象中间覆写、继承来的接口提供方、属性 accessor、跨 Cone 和缺源码依赖得到正确位置。声明事实可用时，损坏正文旁仍能跳转 |
| 提取局部 `val` | 能在表达式位置、带预期类型的实参和已有 smart cast 的正文应用编辑。语义验收覆盖显式实参前后顺序、短路、重载与同名遮蔽。缺少适当插入点时返回空动作 |
| 类型层级 | 沿直接边逐层展开。接口菱形、透明别名、泛型声明归并及配置更新后的结果正确 |
| 提取函数 | 完整表达式传入输入并返回原值，连续语句保持执行次序。跨选区跳转、外层 `var` 写回和缺失绑定等不可提取情况返回空动作 |
| 调用层级 | 双向结果对应同一批调用位置。覆盖重载、递归、同一 caller 的多个调用点，以及只有函数引用的用法。编辑后旧调用位置消失 |
| 其他重构 | 内联保持类型及求值，引入别名保持类型应用，删除能报告已知用法及入口，移动保留可见性与来源，签名换序保留实参求值次序 |
