# EventLoop 后端实施记录

状态：平台后端迁移已完成；2026-11-11 起继续按 HTTP 实测热点改进共享层。设计与合同见 [DESIGN.md](DESIGN.md) 和 [asyncio 规范](../specs/SCOOP-ASYNCIO-SPEC.md)；三目标迁移实测与回退见[性能记录](PERFORMANCE.md)。

## 进度

- 2026-10-27：开始实施，保留现有公共行为，以共享 owner、Darwin、宿主接入、Linux、消费者迁移的顺序提交。
- 共享层已完成：资源、操作和连接竞速只依赖 `LoopOwner`；一次非阻塞处理消费有限快照并阻止递归进入，同步运行复用该流程。native 公共头不再暴露 uv 类型，过渡适配的布局集中在私有头。
- Darwin 原生后端已完成：通知 pipe、串行 I/O queue、source 与后台 work 覆盖全部现有操作，错误保留 POSIX 来源。source 取消处理器与 worker 退出均计入关闭条件。
- `PlatformEventLoop`、`EventLoopSession` 和宿主协议已交付；Darwin 的 `MainDispatchHost` 使用真实主 dispatch queue。应用投递经根 continuation 恢复 attach Context，监听注销完成后才销毁后端和通知关闭。
- Linux 原生后端已完成：固定 liburing 2.15、eventfd、真实 ring 数据操作、独立取消 CQE、有限 native worker 与完整退休条件。消费者和发行资源已迁移，旧 adapter、libuv vendor 与失去消费者的 UV 错误转换已移除。

## 2026-11-11：owner 命令发布与状态读取

首次 HTTP 调查发现多 worker 在共享 `IoLock` 上忙等。启动配置改为一次发布后读取，操作编号独立原子分配；命令发布、通知有效期及停止接纳集中到使用平台 Mutex 的 inbox，空转非空时合并通知。owner 退出本轮时仍补查工作，关闭前原子停止接纳；不改变 I/O 借用、取消退休及 executor 排空合同。

Linux GNU／io_uring 使用已安装工具链及独立 Cone 输出验证：asyncio 167、tls.asyncio 23、http.asyncio 146、http.server 151、http.client 254 项 release 测试全部通过。新增多生产者顺序／完整性及四 worker TCP＋timer 覆盖；格式、静态检查通过。两种 worker 配置另逐条校验共 4,096 个混合 HTTP 响应，全部正确。

## 2026-11-11：HTTP 定时通知与接入调度

`EventLoop.schedule` 复用现有操作表、native timer 和退休协议，提供可撤销的一次 owner 通知；通知不捕获调用方 Context，不建立辅助协程。H1 I/O idle、server 请求头及请求总期限迁移到该机制，正常完成不再通过取消计时协程触发异常展开。动态期限以通知身份排除旧回调，整个请求子树结束后才撤销期限。

仅移除计时协程时，单 worker 首请求出现明显排队长尾。最终 H1 在可复用请求边界让出；TCP 接受循环与连接所有权安装使用 owner executor，协议、业务和正常清理继续使用原 executor。初始化用一次完成通知交接；worker 排队期间取消由 owner 关闭连接。单次逐请求诊断中，64 连接的大响应首请求最大延迟从初始候选的 1,074 降到 151 ms，动态响应从 1,061 降到 56 ms；该诊断与下表的重复统计分开保留。

最终 server 155 项 release 测试通过，包括真实 worker 占用时接受连接、排队取消关闭 transport，以及并发初始化后的业务 executor 归属。asyncio 172、TLS 23、HTTP asyncio 146、client 254 项本轮测试全部通过，最后仅 server 有变更，因此复用其他库结果；合计 750 项。额外 4,096 个混合响应逐条校验正确，42 个性能样本无错误。格式、静态检查及差异空白检查通过。

## 第二十三轮：具体操作保存完成结果

B22 将操作建立定位为单连接分配中的最大单项。本轮移除公共 `LoopOperation` 内的完整 `NativeEvent` 存储，只保留仲裁、订阅和提交／交付阶段。字节传输保存实际传输量与待交付异常，`CallbackOperation` 自行保存完整结果。错误转换失败也进入原有清理／恢复路径；保存结果不调用用户回调，真正退休、ready 分轮、提交进度、解除借用与方向占用、恢复 continuation 的次序保持。按 spec 先行修改 asyncio 规范，公开 API、worker 队列、work stealing、native 后端、编译器及 GC 策略未变。
