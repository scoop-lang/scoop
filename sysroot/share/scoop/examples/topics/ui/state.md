## 运行

保存完整项目，在配备图形会话和 Scoop UI 系统库的 macOS、Linux GNU 或 Windows 主机执行：

```sh
scoop test --release .
scoop run --release .
```

测试包含一个短暂的隐藏原生窗口；无图形会话的主机不能据纯模型测试声称窗口行为已验证。

## 预期结果

窗口包含两个独立计数器。连续点击某个计数器会持续加一；Reverse 改变排列但保留对应计数；Remove 删除该行；Add 或平台主快捷键加 I 新增计数为 0 的行。关闭窗口后应用退出。

## 关键说明

根 frame 采用主题的 Plain 表面，给背景和文字提供一致的颜色；布局从起始位置排列。

`CounterModel` 拥有状态和稳定业务 ID，`CounterPanel` 描述布局，`CounterRow` 处理一行的交互。新增、删除、重排使用新数组通知状态系统，并保留未删除计数器的对象；不能用列表下标替代 `ViewKey.Number(entry.id)`。

事件回调读取 `props.value` 和当前 State，不捕获首次 render 时的计数快照。快捷键注册由组件 `scope.resource` 持有，组件卸载时释放；不为示例新增平行的资源管理器。

模型测试覆盖重复事件、重排与删除后再新增；原生宿主测试执行挂载、状态更新和关闭。可见窗口的上述点击步骤用于核对渲染、布局及真实输入。

这三类验证承担不同职责：模型测试不证明真实输入，隐藏窗口测试不证明按钮可操作。可以用可用的 GUI 自动化工具完成点击和快捷键步骤，并观察相应行与计数；使用公开宿主 API 验证生命周期即可。库内部的 test-native Cone 不是本例依赖，不需要为这类应用将开发 sysroot 的测试路径写入 manifest。

## 常见误用

不要每次 render 创建新的 model 或重置状态，也不要让共享的临时对象承载所有行的计数。UI 线程上的长任务应使用所属异步能力处理；本例只有同步、短小的状态更新。
