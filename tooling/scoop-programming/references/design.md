# 设计 Scoop 程序与复审修改

需要设计数据、状态、模块或公共 API 时阅读。小脚本可以直接用函数和值；下面的边界应有实际用途，不要求固定层数、文件数或一套通用框架。语言写法见 [language.md](language.md)，库声明入口见 [libraries.md](libraries.md)。

## 数据、状态与模块

- 需要继续计算、排序、判断或转换格式的数据，保留数值、单位和状态；在展示边界再格式化。只用于展示的 DTO 可以保存文本。字节、时长和比例不能只靠字符串中的后缀区分，也不必为每个字符串建立包装类型。
- struct/enum/tuple 表达值；class 表达真正共享的状态、身份或资源。复制包含引用的值不会复制引用指向的对象。`val` 限制重新绑定，不禁止修改对象；用由 val 引用的对象承载闭包所需共享状态，跨线程仍须同步。
- enum 适合表达有不同载荷的状态；Option 表达缺失，Result 表达需要保留的成功/失败载荷。不要把零、空文本、空集合、未配置、解析失败和系统错误全部转换为 None。
- 解析/业务计算适合接收明确的值并返回结果；文件、网络或进程适配负责获取输入和资源。渲染接收所需的数据和显示配置，不暗中查询系统或固定一个平台。业务确实很小时，这些职责可以保持在同一文件的几个函数中。
- 接口用于已有多个实现、真实平台差异或需要替换的 I/O；简单数据参数与纯函数足够时不增加接口。测试替身也遵守真实 API 的空值、失败和生命周期合同，不能默认让所有未匹配操作返回 None。
- 跨 Cone API 显式公开必要类型、构造器、成员及 companion，说明单位、失败和所有权；保留其余 internal/private 实现。先用 `language/visibility` 核对真实消费者需要的公开边界，不为测试方便公开全部内部函数。

## 组合 Option/Result，保留失败信息

Option 的组合扩展由 `scoop.std` 提供，package 为 `scoop`；源码在 `<SYSROOT>/src/scoop.std/src/results/option.scoop`。manifest 必须声明实际直接使用的 std 依赖。

| 操作需求 | 查询现有 API | 需要核对的区别 |
| --- | --- | --- |
| 存在时转换为普通值 | `map` | 回调返回可选值会产生嵌套 Option |
| 存在时运行返回 Option 的操作 | `flatMap` | 展平一层，不把所有内层 None 变成相同业务状态 |
| 缺失时生成普通默认值 | `getOrElse` | 回调仅在 None 时求值 |
| 缺失时尝试另一个可选结果 | `orElse` | fallback 返回 Option，回调仅在 None 时运行 |
| 两种分支返回同一种结果 | `fold` | 明确两边的业务行为 |
| 将缺失转换为有载荷的失败 | `toResult` | 失败值按需生成；Result 的转换继续查询 results 目录 |

`?:` 的默认分支与 `orElse` 的可选替代不是同一个返回形状。`?.` 遇到原本可选的结果不会自动展平。先检查接收者、回调结果和完整返回类型，再选择操作。

传给函数的普通实参会先求值；把外部查询写成 fallback 实参，不能保证主要结果存在时不执行。需要惰性替代时用实际的回调 API，并用调用计数检查副作用是否发生。不要为了简写把进程启动或网络请求放进急切求值的默认参数。

只捕获当前层能够解释和处理的失败；如需降级，保留诊断或明确的业务状态。通用 I/O 封装应保留原始错误、进程退出/信号状态及标准流，再由应用决定哪些可忽略。资源仍按既有 `use`、`useAsync` 或作用域合同收尾。

## 按领域选择边界

| 任务 | 实现前需要明确的内容 | 材料入口 |
| --- | --- | --- |
| 库、集合与数据处理 | 值/引用与快照、泛型约束、可见性、无效输入、数值范围；预留真实的格式转换边界 | `language/visibility`、`language/generics`、`collections/*`、`json/typed` |
| 文件、命令行与进程 | 空与缺失、argv、退出状态、标准流、资源所有者；有机器可读输出时使用实际可用的格式 | `io/files`、`io/resources`、`cli/options`，scoop.platform 的 process/environment API |
| 异步与网络 | 调用是否挂起、任务归属、取消与等待、响应消费及关闭；重试须符合操作自身语义 | `async/tasks`、`http/get` 及相关库 README |
| 终端与交互 | TTY/重定向、颜色、控制字符、字素簇和列宽、窄屏行为 | scoop.terminal、scoop.charset、scoop.readline 示例 |
| UI | 状态所有权、事件执行时的当前值、稳定 key、挂载/卸载及异步收尾 | scoop.ui 与实际使用的组件/桌面库 README 和 examples |

`suspend` 不等于并行线程；`cancel` 不等于清理结束。按 API 等待 join/await，业务上的“已经启动”条件使用实际同步协议。睡眠时长不能充当通用同步条件。

终端列宽不等于 byteLength 或 charLength。字符集库已有字素簇分割和标量宽度接口；组合字符、emoji 和控制字符需要明确显示策略，单纯相加标量宽度并不完整。按当前产品需要处理重定向与窄屏，不为简单输出引入完整布局框架。

UI render 可以按真实区域提取普通 View 函数。显示快照用于当次显示，事件根据执行时的模型/Props 更新状态；不要捕获旧显示值计算下一状态。使用当前 receiver 的 builder、显式 key 和公开 Binding/模型，按生命周期关闭资源；只给确需独立生命周期的部分建立组件。

## 完成一批修改后复审

检查本次改动实际涉及的项目即可：

1. 编译修复是否改变了业务含义：新增 None/空串、过早格式化、吞掉错误或丢失状态？
2. 是否复制了库已有的组合操作，或为了规避一次候选错误增加包装类、重复分支、可变状态？
3. 是否重复读取、扫描或调用外部程序，fallback 是否真的按需执行？
4. 错误和取消路径能否完成收尾，借用与拥有的资源是否分清？
5. 期望来自需求还是当前实现？精确断言是否保留了 actual/expected；必要的真实集成、流/退出码与副作用是否验证？

修改后的抽象应能解释当前代码和测试。未涉及的领域无需逐项检查，也不把整张清单转成额外的运行时或编译器检查。
